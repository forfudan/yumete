# yumete 使用手冊

**yumete**（宇夢終端編輯器）是一個寫中文散文用的終端編輯器，內置宇夢輸入法。
名字就是這麼拼的：`yumete` ＝ `Yume` ＋ `TE`（Text Editor／Terminal Editor）。
裝好之後兩個名字都能用——`yumete` 是全名，`ye` 是實際會打的那個。
本手冊記錄目前能用的功能，隨開發持續更新。想知道某個設計為什麼這麼做，見
[development.md](development.md)。

---

## 一、設計哲學

**yumete 採用 Helix 的哲學：先選擇，後動作。**

Vim 一脈的編輯器是「動詞 + 賓語」——`dw` 是「刪一個詞」，兩個鍵都敲完之前什麼都不
會發生。Helix 和 yumete 反過來：**一個移動就是一次選擇**。按 `w` 光標往前走，同時
把走過的那一段選中，所以你**先看見**將要操作的範圍，再決定動不動它。`d` 刪的就是這
段選區。

由此有兩件事第一天就該知道：

- **每個移動都會留下選區。** `w`、`f`、`x` 都會標出一段範圍，`d`、`c`、`y`、`R`、
  `>`、`` ` `` 作用在這段範圍上。
- **光標所在的那個字，本身就在選區裡。** 沒有「零寬選區」這回事：方塊光標蓋住的字
  就是 `d` 會刪掉的字。所以 `f。d` 連句號一起刪，`e` 選得到整個詞，`v` 之後按一次
  `l` 選中的是兩個字。這一條照 Helix。
- **`;` 把選區收成一個光標**，`v` 切換「延伸模式」——延伸模式下移動是把選區撐大，
  而不是換一段。`Esc` 退出延伸模式。

**凡是與 Helix 不同的地方，都是為了漢字文化圈。** Helix 是給「詞之間有空格、行從左
往右」的語言寫的代碼編輯器，中文散文兩樣都不是。所以：

- **詞由詞典決定，不由空格決定。** `w`／`b`／`e` 按真正的中文詞走，用的是宇夢自己
  的語言模型（見第六節）。
- **`gJ` 併行不一定補空格。** 兩個全角字之間合併時直接接上——中文換行本來就不帶空格，硬 插一個等於替你寫了你沒寫的字。拉丁詞之間照補。
- **match mode 認得中文括號。** `mi「`、`ms《`、`md` 這些對
  「」『』（）《》【】〔〕 和 ASCII 括號一樣有效——小說的結構本來就是括號。
- **版面可以竪排**（第五節），像小說排版那樣，標點會轉向，可以注音，光標也跟著轉。
- **輸入法是編輯器的一部分**，不是擋在前面的東西——搜索行裡也能打中文，因為在中文
  文檔裡搜中文不是什麼特殊情況。

## 二、上手

```sh
scripts/build.sh             # 編譯出 ./yumete，安裝輸入法數據，並接上全局的 yumete 與 ye
scripts/build.sh --no-data   # 只編譯二進制
scripts/build.sh --no-link   # 不動全局那一條命令
```

最後一步是把 `~/.local/bin/yumete` **和 `~/.local/bin/ye`** 都指到剛編出來的那個
二進制上，所以在任何目錄裏打 `yumete` 或 `ye` 用的都是這一次的編譯。
**`ye` 是同一個程序的短名字**，不是另一個程序——就像 helix 裝出來叫 `hx`。
（`ye` ＝ **y**ume **e**ditor，和 `yumete` ＝ `Yume` ＋ `TE` 是同一條線。）
想放到別處：`YUMETE_BIN_DIR=/usr/local/bin`。
那兩個位置上如果已經有一個**真的檔案**（不是我們建的連結），它不動——別人裝的東西
不該被一個編譯腳本悄悄換掉。`ye` 短，所以這一條對它比對 `yumete` 更要緊。

**第一次用**：進去之後打 `:tutor` ——它會把一課抄成**你自己的一個檔案**，
邊改邊學，裏面每一個會破壞東西的鍵都可以放心按（`u` 是第一課）。
記不起某個鍵：`:help`，四節，可以像讀稿子一樣讀、一樣搜。

```
yumete <檔案>...       打開一個或多個檔案
yumete                 接着上次——上次開着的那些檔案，各自停在離開時的那一行

  -v, --vertical       這次以竪排（縱書）開啟
  -H, --horizontal     強制橫排
  -t, --table          當表格讀（CSV 沒有 schema 也行，用首行當表頭）
  -R, --readonly       鎖住這一次開的每一份，不許改
  -n, --new            這次不接上次，開一個空白的
  -p, --preview        只打印內容，不進編輯器
      --shot[=寬x高]   把一幀畫成文字印出來就退出（預設 100x30）
  -h, --help           按鍵與命令一覽
  -V, --version        版本，帶構建時間與提交號
```

**版本號說得出「我跑的是哪一份」。** `0.1.0` 一個號碼答不了這個問題，而開發期間一天十
幾個提交，這正是所有故障報告的第一個問題：

```
$ yumete --version
yumete 0.1.0-dev.20260905110744+bbc1485.dirty
       │     │   │              │       └ 編的時候工作區有沒提交的改動
       │     │   │              └ 從哪個提交編出來的
       │     │   └ 什麼時候編的（本地時間）
       │     └ 不是發布版
       └ Cargo.toml 裏那個號
```

`.dirty` 比看上去要緊：沒有它的話，只要樹上有沒提交的改動，那個提交號就是**假的**；有
它，那個號誠實地只是一個「起點」。發布版（`YUMETE_RELEASE=1` 編的）就是乾淨的 `0.1.0`，
後面什麼都不帶。

同一行也印在每一張**畫出來**的圖最下面（`--shot`、`--html`、編輯器裏的 `:shot html`／`txt`
都是），畫在頁面
**外面**，所以貼過來的圖自己說得出它是哪一版畫的：

```
-- yumete 0.1.0-dev.20260905110744+bbc1485.dirty
```

`--preview` 不進編輯器，直接把內容打印出來，也認 `--vertical`——不離開命令行就能看
排版效果。

`--shot` 更進一步：它把**整整一幀**——行號、狀態列、面板、竪排的縱，全部——按編輯器
真正會畫的樣子印成文字。所以一張「當時長這樣」可以貼進 issue，也可以讓沒開這個編輯器
的人看見版面到底是什麼樣子。`yumete --shot=64x16 -v 第一章.txt` 就是一頁竪排。

編輯器裏面的 `:shot` 有四種，第一個字說的是**拍什麼、留下什麼**：

| | |
| --- | --- |
| `:shot`（＝`:shot screen`） | 拍視窗，圖進**剪貼簿**，直接貼進聊天窗或 issue |
| `:shot png` | 同一張，存成 PNG 檔 |
| `:shot html` | **不截螢幕，自己把這一頁畫出來**，帶顏色，自帶樣式的 HTML |
| `:shot txt` | 同上，不帶顏色的純文字那一版 |

拍視窗那兩種交給系統的截圖程序，命令寫在配置的 `[editor] screenshot` 裏；`png` 那一種
把去處放在 `$YUMETE_SHOT` 裏交給它（出廠那條命令收得到，自己寫過那一行的話照着補一句
`"${YUMETE_SHOT:--c}"`，沒補的話 `:shot png` 會告訴你圖還是進了剪貼簿）。

畫出來的那兩種不經過螢幕。截螢幕要知道終端機視窗在螢幕上的位置與顯示器的縮放倍率，編輯
器兩個都拿不可靠，於是圖裏總會多出標題列、標籤頁、終端機自己的留白——**畫出來的那一張從
一開始就只有頁面**，而且遠程連上去的機器上一樣畫得出來。

存成檔案的那三種，檔名默認是**稿子的名字加上當時的時分秒**：`第一章.md` 存成
`第一章_20260906143012.png`，**放進下載資料夾**，不落在稿子旁邊。兩件事都是為了同一個
道理——圖是拍完就發出去、發完就忘的東西，沒有理由在稿子的資料夾裏積灰，也沒有理由跟上
一張同名。自己寫檔名（`:shot html 給編輯.html`）就照你寫的來，那時候撞了名字會停下來告
訴你，`:shot! html 給編輯.html` 才蓋。

`ambiguous_width = "auto"` 在截圖裏落到**窄**——`auto` 是問終端的，一張圖沒有終端可以
問。這也是對的：圖是從畫布上一格一格讀出來的，而那塊畫布本身就是按窄算的。設定寫死
`wide` 的稿子，圖裏 `——` `……` `“ ”` 會和實際的終端一樣偏一格，這正是那個設定要處理的
問題本身。

## 三、模式

| 模式 | 怎麼進 | 做什麼 |
| --- | --- | --- |
| **Normal** | `Esc` | 移動、選擇、發命令 |
| **Insert** | `i` `a` `I` `A` `o` `O` `c` | 打字；輸入法在這裡工作 |
| **Command** | `:` | 發命令。命令名是 ASCII，**參數走輸入法**（`:e 第三章.md`） |
| **找命令** | 空行上再按 `:` | 說它是做什麼的，找出叫什麼；輸入法在這裡工作 |
| **Search** | `/` `?` | 打搜索詞；輸入法在這裡工作 |
| **Ruby** | `空格 r`（或 `:ruby`） | 改注音；輸入法在這裡工作（見 5.5） |

光標形狀告訴你在哪個模式：Normal 是**方塊**，Insert 是**竪線**。竪排時那根線跟著文
字轉了九十度，變成一條橫線。

**`Esc` 太遠的話，把 Caps Lock 換成它。** 一天要按幾百次的鍵，值得放在左手小指底下。
這件事 yumete 做不了——終端機根本收不到 Caps Lock，那一鍵在到達任何程式之前就被系統
吃掉了——但系統做得了，一次設好，往後每個程式都算數：

> 系統設定 → 鍵盤 → 鍵盤快速鍵… → 變更鍵 → Caps Lock 鍵 → 選 `Escape`

大寫還要不要？要的話按住 Shift；真正需要鎖定大寫的中文寫作場合，一年也沒幾次。

## 四、按鍵（Normal 模式）

前面加**數字**表示重複：`3w`、`10j`、`5>`。單獨的 `0` 不算數字前綴，留給別的用途。

### 移動

| | |
| --- | --- |
| `h` `j` `k` `l` | 左／下／上／右，按字素和**屏幕上看見的那一行**走；`h` `l` 走得過行尾，接上一行／下一行 |
| `Esc` | 離開延伸模式，選區收回光標 |
| `w` `b` `e` | 下一詞首、上一詞首、詞尾 |
| `W` `B` `E` | 同上，但按空格分的「大詞」 |
| `f` `t` `F` `T` *c* | 找／找到字符 *c* 之前，向前或向後 |
| `A-.` | 重複上一次 `f`／`t` |
| `C-w` `C-u`（Insert） | 退掉前面一個詞／退到行首 |
| `g/` `g?` | **這個詞還在哪裏**——選中的那段（或光標下的詞）在整份稿子裏。`/` 在這邊找，`?` 在另一個工作區給你看，你不動 |
| `n` `N` | 下一處／上一處。`Esc` 關掉的是那個窗，不是這次搜索：關了以後 `n` 走到下一處，窗自己回來 |
| `gd` | **去**它指着的地方：腳注的那條註、拆分欄裏那個部件自己的行（`C-o` 回來） |
| `gD` | **看**同一個地方——在另一個工作區，你不動 |
| （兩個都一樣） | 腳注還沒寫就先寫一條，`gd` 落在它末尾，打字即可 |
| `空格 w` | 另一個工作區：沒開就開，開着就過去 |
| `空格 W` `空格 q` | 只留這一個／關掉這一個到另一個去 |
| `Delete`（Insert） | 刪光標**前面**那一個字（Backspace 的鏡像；行尾刪的是換行） |
| `Home` `End` `C-a` `C-e`（Insert） | 行首／行尾——和 `:` 那一行同一套 |
| `J` `K` | 前進／後退**半頁**——最常按的一對，不該是和弦 |
| `C-d` `C-u` `C-f` `C-b` | 同上，Helix 原本的和弦 |
| `PageUp` `PageDown` | 整頁——鍵盤上本來就有的那兩個，Insert 裏也一樣 |
| `gg` `ge` | 檔首／最後一行；`10gg` 到第 10 行 |
| `G` | 最後一行；`30G`（或 `g30g`）到第 30 行 |
| （打一半的命令） | 右下角和光標旁邊都會顯示（旁邊那個歸 `:view-hud` 管）；`g` `t` `m` `空格` 還會彈出一張表 |
| `gn` `gp` | 切到下一個／上一個打開的檔案 |
| `gf` | 打開本行寫的 `檔名:行號`（`:grep` 結果用這個跳） |
| `gx` | 跟着光標下的連結走（見「跟着連結走」）；Ctrl 點一下同樣 |
| `空格` | 打開選單（見下）|
| `gh` `gl` `gs` | 行首／行尾／第一個非空白字符 |
| `Home` `End` | 行首／行尾 |
| `{` `}` | 上一段／下一段——**一段就是一個邏輯行**，空行跳過 |
| `M` *字母* | 把這個地方記下來，叫這個名字 |
| `'` *字母* | 回到那個地方（跨檔案，檔案會自己打開） |
| `C-o` `C-i` | 跳轉表：回到剛才那個位置／再往前 |
| `H` `L` | 上一句／下一句——斷在 。！？ 和它後面的 」）之後 |

`{` `}` 為什麼需要：開了折行以後，`j` `k` 走的是**屏幕上的一行**，而一段話有二十行。
「下一段」這個動作於是沒有鍵了。一段就是一個邏輯行——這不是這裏發明的定義，是編輯器
其他地方本來就在用的那個（折行、分詞緩存都以它為單位），也正是中文稿子的寫法。

`H` `L` 斷句斷在「。」和跟在它後面的收尾符號**之後**：「不。」斷在 」 之後，不是之前。
半角句點只有後面跟着空白時才算句末，所以 `3.14` 不是一句話。這一段沒有下一句了就走到
下一段的第一句。

**按不到的鍵會告訴你這裏叫什麼。** `$`、`^`、`G`、`@` 這些在別的編輯器裏有意思、在這裏
沒綁的鍵，按下去不會沒反應——它會在提示行說「行尾是 `gl`」。它**不會替你做**那件事：
這不是兼容層，是一本用得上的詞典。

| | |
| --- | --- |
| `v` | 延伸模式——移動把選區撐大 |
| `;` | 把選區收成光標 |
| `x` | 選中當前行（再按繼續往下選） |
| `X` | 把選區撐到整行邊界 |
| `%` | 選中整個檔案 |
| `A-;` | 光標換到選區的另一頭 |

### 修改

| | |
| --- | --- |
| `d` `c` | 刪除／改寫選區 |
| `i` `a` | 在選區前／後插入 |
| `I` `A` | 在行首／行尾插入 |
| `o` `O` | 在下方／上方開新行 |
| `y` `p` `P` | 複製／向後粘貼／向前粘貼。整行複製的整行粘貼，不會插進別的行中間 |
| `R` | 用寄存器內容替換選區 |
| `r` *c* | 把選區每個字都寫成 *c*。**中文也打得**：按 `r` 就開候選面板，選中什麼就替換成什麼；上屏一個字是逐字填滿，上屏一個詞是整段換掉 |
| `"` *a* | 下一次複製／刪除／粘貼使用寄存器 *a* |
| `Q` `q` | 錄製宏／回放上一個宏——和 Helix 同一個方向 |
| `gJ` | 與下一行合併（兩個全角字之間不補空格） |
| `` ` `` | 字形組：`` `l `` 轉小寫、`` `u `` 轉大寫、`` `` `` 大小寫互換。Helix 花三個一級鍵做這件事，而它在漢字上什麼都不做，所以收成一組（`~` 與 ``A-` `` 在這裏沒有綁定） |
| `>` `<` | 選中的行增加／減少縮進 |
| `C-a` `C-x` | 光標處的數字加一／減一 |
| `u` `U` | 撤銷／重做 |
| `.` | **再做一次剛才那個改動**——`r`、`d`、`c…Esc`、`ms(`、貼上，都算 |

### 搜索

| | |
| --- | --- |
| `/` `?` | 向前／向後搜索——**這裡能打中文** |
| `n` `N` | 下一個／上一個匹配 |
| `g/` `g?` | 找選中的那段：這邊跳過去／那邊看 |

**`/` 一按，上次找的那個就以灰字寫在提示行上。** 直接 `Enter` 就是再找一次它，
`Tab` 把它變成真的打上去的字，而直接打字就是找新的——打到第一個和上次對不上的字，
那行灰字自己退場；退格刪回去，它又回來。`?` 反着找，記的是同一個。

搜到的**那一段就是選區**——所以 `/她說` 之後直接 `c` 就是改掉「她說」。每個移動都留下
選區，搜索也不例外，否則它就成了唯一一個「按 `d` 刪掉的不是屏幕上指着的那一段」的
移動。

**搜索和取代用的是正則表達式**，和 vi、Helix 一樣。校稿的一半工作是模式而不是字串：

| | |
| --- | --- |
| `/第.+章` | 找章節標題 |
| `:%s/[他她]說/X/g` | 兩種寫法一起換 |
| `:%s/。/。\n/g` | 每個句號後面斷行，把一牆字拆成段 |
| `:%s/(.+)說道/$1說/g` | `$1` 是第一個捕獲組 |
| `:%s/！{2,}/！/g` | 連續的驚嘆號收成一個 |

**沒有大寫字母的模式不分大小寫**，有一個大寫就分——和 Helix 的 smart case 一樣。
稿子是漢字，漢字沒有大小寫，所以絕大多數搜索白拿這一條；稿子裏的西文多半是專名和
縮寫（`TODO`、`ISBN`、人名），而打出那個大寫就是「這個要照字面找」的意思。
一次性反過來寫 `(?-i)`（`/(?-i)todo` 只找小寫的），一直反過來寫
`[editor] smart_case = false`。

代價是 `.` `*` `(` `[` 有了含義——要找句點本身得寫 `\.`。替換串裏 `\n` `\t` 是換行
和製表符，`$$` 是一個真的錢號。`g/`（找選中的那段）走的是**原文**不是模式，所以選中
「（甲）」按 `g/` 找的就是「（甲）」。模式寫壞了會說是哪裏壞，而不是靜靜地換零處。

**分隔符是 `s` 後面的那一個字符**，和 vi、sed 一樣。模式裏本來就有 `/` 的時候——日期、
路徑、網址——換一個就好：

```
:s#2024/01#2025/02#          # 井號當分隔符
:s,docs/a.md,docs/b.md,      # 逗號也行
:s/2024\/01/2025\/02/        # 或者照 vi 那樣轉義
```

**改哪些行**寫在 `s` 前面：

| | |
| --- | --- |
| `:s/…` | 選區蓋到的那些行（沒選就是光標這一行） |
| `:%s/…` | 整個檔案 |
| `:1,40s/…` | 第 1 到第 40 行 |
| `:.,$s/…` | 從這一行到檔尾（`.` 是這一行，`$` 是最後一行） |
| `:40s/…` | 就第 40 行 |

**旗標**寫在最後：`g` 一行裏每一處都換（不寫就只換第一處），`i` 不分大小寫，**`n` 只
數，不改**——`:%s/裏/裡/n` 先告訴你有幾處。不認識的旗標會被說出來，不會被默默吞掉
（`c` 逐個確認還沒做，它會直說）。

搜到的**那一段就是選區**——所以 `/她說` 之後直接 `c` 就是改掉「她說」。每個移動都留下
選區，搜索也不例外，否則它就成了唯一一個「按 `d` 刪掉的不是屏幕上指着的那一段」的
移動。

### 所見即所得

`:render full` 之後，`**` `` ` `` `[]()` `[[]]` `%%` 這些標記從畫面上消失，只留它們框住
的字；`:render basic` 回到著色的源碼（默認就是源碼——**檔案裏是什麼，畫面上就是什麼**）。

**選區碰到的每一個結構都是展開的**（不只是光標那一個——錨點也是文本裏的一個位置，
高亮如果比 `d` 實際刪的少，就是畫面在謊報一次編輯會做什麼）。 這一條是整件事的地基，不是修飾：因為它成立，所
以「光標絕不會在看不見的文字裏」，於是 `d`、`x`、`w` 動的仍然是源碼字符，而你眼前看
見的就是源碼。靠近一個結構它自己打開，離開它自己收起——站在它的邊界上仍然算在裏面，
不然光標一離開行就抖一下。

**標題的 `#` 不藏。** 終端沒法把標題放大，井號是唯一說明「這是章還是節」的東西，而層 級是你的結構。列表符號、`:::` 那幾行同理——**行內的噪音藏起來，區塊的結構留着**。

所見即所得也會**排出注音**（注音是標記的一種）。不過只在竪排看得見效果：橫排沒有地方
放讀音那一欄，所以那裏仍然顯示原始標記。

一點還沒做完的：橫排的折行寬度目前按**源碼**算，所以標記多的行會比右邊界早一點折。竪
排沒有這個問題（隱藏的標記本來就不佔格）。

### Markdown 還是 Typst

`.md` 就是 Markdown，`.typ` 就是 Typst——問題只在**什麼都沒說**的檔案，實際上就是
`.txt`。用 Typst 寫小說卻存成 `.txt` 是很平常的事，而當成 Markdown 讀，`#import` 會
變成標題、`*粗*` 什麼都不是。

所以這類檔案**開檔時猜一次**（不是每幀）。兩種語法的信號是**互斥**的，不是「不同」：
`#let` `#import` `#show` `#set` 只可能是 Typst；`**粗**` 只可能是 Markdown（Typst 用單
個 `*`）；行首 `= ` 是 Typst 標題，行首 `# ` 是 Markdown 標題——Typst 的 `#` 後面必須跟
標識符，`# 第一章` 根本不合法。打分投票，**平手算 Markdown**：猜錯比不猜更糟，因為在所
見即所得下這個猜測決定了什麼會從畫面上消失。

但**最靠譜的是寫進配置**，因為讀檔案不一定判斷得出來：一章如果通篇只有散文，裏面根本
沒有 Typst 可找。項目目錄的 `.yumete/config.toml` 裏：

```toml
[syntax]
txt = "typst"                # 這個項目裏的 .txt 都是 Typst
"筆記.txt" = "markdown"       # ……除了這一個
```

確切檔名優先於擴展名，所以「我的 .txt 都是 Typst，除了那一個」說得出來。另外，從一個
Typst 檔案按 `gf` 跳進 `#include` 的章節，那個章節**繼承** Typst——被引進一本 Typst 書
裏的章節就是 Typst，不管它叫什麼、裏面有什麼。

`:syntax typst` 可以臨時推翻，`:syntax` 不帶參數就說現在是哪個；命令行上
`yumete --syntax typst 稿子.txt` 是同一句話，它比擴展名和配置都大——你已經知道裏面是
什麼了，就沒有什麼可猜的。

**`:syntax text` 是「沒有標記」**：檔案裏的每個字符都只是它自己。有人拿 `*` 當分場、拿
`#` 寫給自己看的批註，那不是 Markdown，按 Markdown 上色只會讓自己的標點在頁面上一閃
一閃。這種稿子寫 `text`（配置裏也可以：`"日記.txt" = "text"`）。

Typst 那邊認得 `= 標題`、`*粗*`、`_斜_`、`` `碼` ``、`$數學$`、`//` 註釋，以及
`#import` `#let` `#show` `#set` 和 `#chapter[…]` 這類調用。

**Typst 的代碼永遠不會被隱藏**，即使在所見即所得下——`**` 是圍着文字的裝飾，可以拿走；
`#chapter[初雪]` 是**產生**那一章的指令，藏掉它畫面就在說謊。它只是調暗。

`#import "ch01.typ"` 和 `#include` 那幾行，`gf` 可以**直接跳過去**（相對於引用它的那個
檔案解析，和 Typst 自己一樣）。大綱側欄還會把 `#include` 的那些檔案**讀開**，列出裏面
的章名而不是檔名——一個把章節引進來的主檔案，本身就是目錄（見 5.4）。

### Markdown 著色

`**年**` 裏的「年」會**加粗**，而 `**` **仍然留在畫面上**——這是稿子，不是預覽；你要
看得見檔案裏到底有什麼。標記本身調暗，讀起來是腳手架；它框住的字往前站。標題、
`` `碼` ``、`~~刪~~`、`*斜*`、`[文字](目標)` 同理。`:render off` 關掉著色。

**橫排竪排一樣。** 竪排以前只做隱藏、不上色，等於 所見即所得 只做了一半；現在
三層（塊底色、行內著色、選區）在兩個方向上是同一套。

認得的語法：

| | |
| --- | --- |
| `# 標題` | 六級 |
| `**粗**` `*斜*` `~~刪~~` `==高亮==` | 高亮是底色，像螢光筆留下的 |
| `` `碼` `` | 裏面的標記一律不算標記 |
| `[文字](目標)` `[[第三章]]` `[[第三章｜那一夜]]` | 外鏈與內部引用 |
| `[^1]` 與 `[^1]: …` | 腳註號與它的正文 |
| `%%給自己的話%%` `<!-- -->` | 批注：**不是書的一部分**，設得很靠後，但從不隱藏 |
| `> 引文` | 整塊有底色 |
| `- 項` `1. 項` `- [ ]` `- [x]` | 列表與任務 |
| `---` `***` | 分隔線（場景轉換） |
| ` ``` ` | 代碼塊，裏面一律不當標記 |
| 檔首 `---` … `---` | 頁首元資料 |
| `::: tip/info/warning/danger` … `:::` | 整塊有自己的底色 |
| `\| 甲 \| 乙 \|` | 表格行 |

**區塊和行內是兩層，會合成。** 區塊染整行的底（`::: warning` 的底色橫貫整行，不只在
字底下），行內出墨色和字重——所以 `::: warning` 裏的粗體字**兩樣都有**，不是二選一。

區塊那一層不能逐行判斷：三段之前開的一個 ``` 圍欄決定了這一行是不是代碼。所以它是從
文件**頂端順序掃**的——但只讀每行開頭的 64 個字符，而且**每次編輯算一遍**（不是每幀），
六十萬字的稿子一次 1.5 毫秒、一幀 0.6 微秒。逐字符的行內解析仍然是逐段緩存的。

圍欄和 `:::` 都**認得自己是誰開的**：`~~~` 不會關掉 ``` 開的塊，`::: tip` 不會關掉它
所在的 `::: warning`。代碼塊和頁首元資料裏**一切都不是標記**——那裏寫的就是那裏的字，
給 `**` 上色（更別說把它藏起來）等於謊報檔案的內容。

這裏沒有用 `pulldown-cmark` 之類的庫，是有原因的：一是它們**整篇**解析，而這裏每次按
鍵都要重畫（這個編輯器已經為 O(全文) 栽過三次）；這裏是**逐段**解析並按段落文本哈希
緩存，和分詞、折行共用同一套。二是 CommonMark 的強調規則建立在西文的空格分詞上，
`中**文**中` 這類在各家實現裏長期出問題——這裏不受那套規則約束。三是渲染器的設計目標
是把標記**吃掉**，而我們要的正好相反。

#### 跟着連結走

`gx` 打開光標下面那個連結——vim 和 Helix 把「打開光標下這個東西」放在同一個鍵上。
**Ctrl 點一下**是同一件事，用鼠標說。光標在連結的哪一段都算數：文字、方括號、
所見即所得 藏起來的那個目標，都是這個連結。

三種去處，各走各的路：

| 寫的是 | 去哪裏 |
| --- | --- |
| `[宇浩](https://yuhao.forfudan.com)` | 交給系統的瀏覽器 |
| `[下一章](02.md)`、`[[第三章]]` | **在這個窗口裏打開**，成為一個緩衝區 |
| `[雪](#雪)`、`[[第三章#雪]]` | 跳到那個標題（先開那一篇，再跳） |

`[[第三章]]` 是**篇名**，不是檔名：後綴是這本書的事，不用你再打一遍——它先找
`第三章` 加上當前檔案的後綴，再找 `第三章.md`。`[[第三章｜那一夜]]` 竪杠後面是
「這裏怎麼稱呼它」，去的仍然是 `第三章`。相對路徑是**照連結所在的那個目錄**算的：
一章的鄰居是它在磁盤上的鄰居。

**只有 `http` 和 `https` 交給系統。** `mailto:`、`obsidian:`、以及任何別的協議，
一律**說出來、不執行**。理由很直接：稿子是會從郵件裏來的檔案，而 `open` 會啓動任何
一個聲稱認得某個協議的程序。絕對路徑（`/etc/…`）同樣不跟——那不是這本書裏的一篇。
另外，交給系統的那一步從頭到尾**不經過 shell**：網址是作爲一個參數遞給
`open`／`xdg-open` 的，沒有任何地方拼過命令行。

### 想寫多長

`[editor] ruler = 80` 之後，**超過第 80 欄的部分底色不同**。這在開着折行時照樣有用：
它說的不是「這裏斷行」，而是「這一行已經超過你想要的長度了」——有些人開着折行，但仍然
想手工把長句斷開，這個視覺就是給那件事的。

**關掉折行時**（`:view-wrap off`，比如手工折行寫 Markdown）除了變色還多一條豎線，因為那時
行長真的是你決定的。開着折行不畫線——變色的邊界本身就是那條線，再畫一條是把同一件事
說兩遍。

竪排沒有這個：縱是往下跑的，限制它的是 `zong_length`，而每一縱都在那裏結束——那條「線」
已經是文字塊的下邊緣了。竪排對應的是**稿紙刻度**（見 5.2）。

**`:view-wrap 50` 更進一步：它不只是畫條線，是真的把稿子寫窄。** 行在第 50 欄折，第 50 欄
右邊那一整塊——不管那一行有沒有寫到那裏——是另一種底色。這就是「紙」和「紙以外」：

```
那年冬天，山下起了大雪。          ▓▓▓▓▓▓▓▓▓▓▓
雪一直下到開春。                  ▓▓▓▓▓▓▓▓▓▓▓
```

在很寬的顯示器上，這是把一欄寫作區放在窗口左邊，而不是讓一句話橫跨 200 欄——眼睛從行
尾回到下一行行首要走的那段距離，超過一定寬度就開始丟行。

`:view-wrap 0` 把窗口還回來。單獨的 `:view-wrap` 還是老意思——開折行——不動尺度。窗口比尺度窄
的時候窗口說了算：折不下的行讀不了。

**竪排也認這條命令**：`:view-wrap 40` 就是**一縱四十字**。橫排的尺度是行寬，竪排的尺度是
縱長，是同一件事的兩個方向。

想每次都這樣，寫進 `config.toml`：`[editor] measure = 50`。`ruler` 只畫，`measure`
真的折。

### 首行縮進

中文的段落是**縮進兩格**開頭的，不是空一行——空行是 Markdown 說「這裏換段」的辦法，
在屏幕上它還白白佔掉一整行（竪排是一整縱）。

```
:indent full         每段開頭縮兩格，段間那個空行從頁面上撤掉
:indent basic        縮進照畫，空行留着
:indent off          不縮
:indent 2            縮幾格是另一個問題：改寬度，不動撤不撤空行
:indent-hint none    那兩格上什麼都不畫（默認）
:indent-hint color   那兩格帶一條淡底
:indent-hint symbol  第一格畫一個記號
[editor] indent = 2
[editor] indent_hint = "symbol"
[editor] indent_symbol = "↵"
```

**這是「看」，不是「改」。** 檔案裏那個空行一個字都沒動——它得留着，否則導出來就變成
一段了。縮進是排版層畫出來的：竪排用的是**空格子**（和一條長注音為自己讓出來的那種格子
是同一個東西），所以光標永遠不會停在縮進裏，鼠標點不到那裏，也不會有一個「檔案裏沒有
的字」出現在你可以編輯的地方。

**`:indent full` 之下，段落之間那個空行會從頁面上撤掉**——條件是這一段已經被**別的方式**
標出來了：橫排是縮進，**竪排永遠是**，因為換段本來就是換一縱，空行是把同一件事說第二遍，
而在竪排說第二遍要花掉整整一縱的閱讀面積。一段話用縮進標，
還是用空行標，排版上只能選一樣——兩樣都上是沒有人做的事。檔案照舊留着空行，行號也照舊
是檔案自己的號，所以頁面上會看見 1、3、5：**跳號本身就是那個空行還在的憑據**。

**光標所在的那一段，按檔案本來的樣子畫**：不縮進，而且它上面那個空行畫回來。這樣「這裏
到底有沒有空行」永遠不必猜——你站在哪一段，哪一段就是原文。代價很小：**同時只有一個空行
是展開的**，所以從一段走到下一段是關掉一個、打開一個，下面的頁面不會跟着動。

另外兩種空行也不撤：**連着兩行以上的空行**（寫了第二行的人是有意的，那是分場），以及
**代碼圍欄和文件頭裏的空行**（那裏的空行是內容，不是段落之間的縫）。`j`／`k`、`h`／`l` 都會跨過撤掉的那一行——頁面上沒有的行，
光標不停在上面。

**那兩格默認是白的**，書上就是這麼印的；一個每段都出現的記號，讀三頁眼睛就不看它了。
真要在編輯的時候看見，`:indent-hint color`（淡底）或 `:indent-hint symbol`（第一格畫
一個 `↵`——它替掉的正是一個換行）。

以 `#` `=` `-` `*` `+` `>` `|` `` ` `` `~` 開頭的行**不縮進**——標題、列表、引文、
表格、代碼圍欄自己帶了開頭的結構，把它們往右推是在說一件不成立的事。`[^1]:`（腳註正文）
也不縮，但以 `[` 開頭的普通段落照縮——一段話當然可以從一個鏈接開始。本來就縮進了的行
也不再加。

`:view-dense` **不會**把它關掉。注音、旁置、刻度各佔一**欄**，那是密排要贏回來的東西；縮進
佔的是一段開頭的兩格，而且它正是密排的頁面上唯一還在說「這裏換段了」的東西——它替掉的
那個空行，本來要佔整整一縱。

### 段組：把頁面橫着分成兩條

一縱五十個字讀起來是累的——眼睛從一縱的底回到下一縱的頂，那一趟太長。日文竪排的傳統
答案不是把字調小，是**把頁面橫着切開**：上半頁從右讀到左，讀完再從下半頁的右邊接着讀。
報紙和文庫本都是這樣排的。

終端是個又寬又矮的形狀——那正好就是段組要對付的形狀。

```
:view-bands 2      分成上下兩條
:view-bands off    整頁一縱到底
[editor] bands = 2
```

**每一條就是一個獨立的短頁面**：自己的縱長、自己的段號行、自己從右往左填。條與條**一樣
高**，因為頁面是被分的，不是被裝滿的——下面那條永遠不會比上面那條矮一行。閱讀順序還是
那一串縱，段組只決定它們被放在哪裏，所以 `hjkl`、翻頁、鼠標點選全都照舊。

窗口矮到一條裝不下一個縱的時候，它自己退回一條。

**只對竪排有效。** 橫排的對應物是 Emacs 的 `follow-mode`（一段文字流過並排的幾欄），
那是另一件事，還沒做。

### 密排

**密排是預設的。** 想要注音欄、句讀旁置的邊欄和稿紙刻度回來，`:view-dense off`（或者
`[editor] dense = false`）。

`:view-dense` 把竪排的頁面壓到終端能給的最緊——**只管竪排**：橫排的注音是上面多一行，不佔
寬度，沒有什麼可以省的，所以密排開着也照排。

| 拿掉的 | 省下 |
|---|---|
| 縱與縱之間的間隔（`zong_gap`） | 每縱 1 欄 |
| 注音欄 | 有注音的縱各 1 欄 |
| 句讀旁置的邊欄 | 有句讀的縱各 1 欄 |
| 稿紙刻度 | 每縱 1 欄 |

之後**一縱就是兩格**——正好一個漢字，終端能畫的最窄。`:view-dense off` 還原**你原來的**
設定，不是預設值：本來就關着注音的人，關掉密排不會發現它自己開了。

**首行縮進不在拿掉之列。** 上面那四樣各佔一**欄**，那是密排要贏回來的東西；縮進佔的是
一段開頭的兩格，而且它正是密排的頁面上唯一還在說「這裏換段了」的東西。

**字本身沒法變窄。** 終端的格子是終端定的，yumete 只能決定用幾格。想要 90% 寬的
字身（更瘦長的縱），那是終端的設定，各家名字不同——Ghostty 是 `adjust-cell-width`，
kitty 是 `modify_font cell_width 90%`，WezTerm 是 `cell_width = 0.9`。改了之後整個
終端都會變瘦，橫排和狀態欄也一樣。

### 跑一條命令：`:sh` 和 `:!`

兩個動詞，因為有兩種情況，各有各的對的答案。

**`:sh wc -w ch01.md`** 想要的是一個**數字**，而且想要它**在文字所在的地方**——所以輸出
被收回來，開成一個緩衝區（和 `:grep` 的結果放在同一種地方）。可以搜、可以複製、可以
一邊寫一邊留着。`git log`、`typst compile`、`pandoc` 都是這一類。

**`:!make`** 想要的是**看着它跑**——帶顏色，帶進度條，可能還要問你一句話。捕獲的管道
做不到這三件事的任何一件。所以編輯器**讓開**：離開備用屏幕，把終端還給那條命令，跑完
之後印一行「按任意鍵回到 yumete」。

> 所以你問的「在哪裏看到它跑」——**就在你啟動 yumete 的那個終端裏**。`:!` 期間 yumete
> 整個從畫面上讓開，回來的時候再把畫面接管回去。這是 vi 從一開始就是這麼做的，也是唯一
> 誠實的答案。

命令走你的 `$SHELL -c`，所以管道和通配符都算數：`:sh wc -w *.md | sort -n` 是一條命令，
不是被拆開的幾個詞。

**第三種：`!`——把選中的字送出去，用送回來的換掉它。**

「pipe」就是 Unix 的管道：選中的那段文字**餵進**一條命令的輸入，那條命令**吐出來**的
東西，換掉原來那段。原文出去，結果回來，就地替換。

```
那年 冬 天        ← 選中這一行
!                 命令行變成 :pipe ▊
tr -d ' ' ⏎       tr -d ' ' 是「刪掉所有空格」
那年冬天          ← 換好了
u                 一次撤銷，字回來
```

`tr -d ' '` 不是 yumete 的東西，是你系統上本來就有的一條命令。`!` 的用處就是**把你系統
上所有的命令都變成 yumete 的編輯命令**：

| 打什麼 | 選中的那段會變成 |
|---|---|
| `tr -d ' '` | 刪掉所有空格 |
| `LC_ALL=C sort` | 按碼位排序（拆分表就是這樣排的） |
| `nl` | 每行前面加上行號 |
| `tail -r` | 行的順序倒過來 |
| `python3 -c '…'` | 你當場寫的任何處理 |

**排中文要小心 `sort`。** 它按你的 locale 排，不是按筆畫也不是按拼音；而且在
`en_US.UTF-8` 下 `sort -u` 會把「木」和「目」當成同一個而刪掉一個。要按碼位排就寫
`LC_ALL=C sort`。

`!` 只是把動詞先替你打好——它不是第二套機制，而且**按錯了看得見它要幹什麼**，Esc 就退。
換行結尾跟着原來那段走：原來沒有換行就不加，原來有就保留，不會把兩行黏成一行。

**命令失敗了不會動你的字。** 打錯一個 flag（`tr -D ' '` 而不是 `-d`）是常事，那條命令
吐出來的是一段錯誤信息——把段落換成錯誤信息，是一次沒人要求過的編輯，能不能撤銷是另一
回事。所以只有命令說自己成功了（退出碼 0）才替換，否則原文一個字不動，狀態欄告訴你它
抱怨了什麼：

```
沒有動你的字：tr: illegal option -- D
```

成功但有警告的，字照換，警告也照說。

順帶：`:sh` 相反——那裏 stderr 和 stdout 一起收進緩衝區，因為在那裏它們**合起來才是
「發生了什麼」**，而且它沒有在編輯你的文字。

### `:view-preview`：交給真正的排版器

`:render full` 是**這個畫面**顯示多少結果；`:view-preview` 是**真的那一份**——由做這本書的
工具做出來，在能顯示一本書的地方顯示。兩個不同的問題，兩個不同的詞。

| 檔案 | `:view-preview` 做什麼 |
|---|---|
| Typst | 起 `tinymist preview`，把它開出來的地址交給瀏覽器。你在 yumete 裏改，瀏覽器裏跟着變 |
| Markdown | 導出一份 HTML 到臨時檔案，交給瀏覽器 |

`:view-preview off` 停掉；退出 yumete 也會停掉——它是為這次會話起的，沒有理由在之後還佔着
一個端口。

**這不是一個終端面板。** 預覽服務器要說的話只有一行——地址——之後它就是個該被放着不管
的進程。給它一塊面板，等於在本來是稿子的地方看日誌滾動，還要為此在 yumete 裏裝一個
終端模擬器——而 yumete 本來就跑在一個終端裏面。所以它是一個**任務**：一個句柄、一個
地址、一個停止的方法。

### 輸入法要自己開

yume 的資料裏有兩樣東西，它們該有不同的待遇。

**語言模型**——詞頻表和詞彙表，兩張都**與方案無關**——是 `w` `b` `e` 走詞用的東西，也是
這個編輯器的詞跳轉比一個編輯器有理由做到的更準的原因。**27 毫秒，每個人都有。**

**碼表**是另外 109 毫秒，而且只對來打宇浩的人有用。給所有人載入，等於每次啟動都替一個
多數人沒要求過的輸入法買單。所以它**等你開口**：

```
:yume-scheme          用配置裏那個方案（默認靈明）
:yume-scheme riyue    指定一個
:yume-s l             一樣——不會有第二個詞的前綴就算數
```

前綴到哪一層都算：`s` 是 `:yume` 唯一以 s 開頭的詞，`l` 是唯一以 l 開頭的方案。有兩個
詞都能匹配的話它**兩個都不選**，而不是悄悄挑先寫的那個。

**什麼都沒裝也能打字。** 靈明的碼表在**編譯的時候**被寫進二進制——不是放在倉庫裏（那是
3.7 MB 的生成物，二進制檔案不做 delta，提交一次倉庫就從 1 MB 漲到 4 MB，每更新一次再漲
一次）。`scripts/build.sh` 先裝資料再編譯，所以它做出來的二進制帶着靈明；在一台沒有資料
的機器上 `cargo build`，就老實地不帶，也照樣能編譯過。

裝好的碼表**優先**——出廠這一份是後備。其餘四個方案不帶，沒裝就是老實地不可用，而不是
悄悄變成靈明。

**去哪裏找**：先是你自己指的（`[ime] data_dirs`、`$YUMETE_DATA_DIR`），然後是 yumete
自己的資料目錄，最後是 **yume 自己裝在哪裏**——每個平台按那個平台的規矩：

- **macOS**：`~/Library/Application Support/Yume/data/compiled/`（重編過的那一份在最前
  面）、`~/Library/Application Support/Yume/`，然後是輸入法自己那個 App：
  `~/Library/Input Methods/Yume.app/Contents/Resources`（只裝給自己的）和
  `/Library/Input Methods/Yume.app/Contents/Resources`（裝給全機器的）。
- **Windows**：`%APPDATA%\Yume\data\compiled\`、`%APPDATA%\Yume\`，以及 `.exe`
  旁邊的 `Resources\`。
- **Linux**：`$XDG_DATA_HOME/yume/data/compiled/`、`$XDG_DATA_HOME/yume/`，`$YUME_DATADIR`，
  以及 `$XDG_DATA_DIRS` 裏每一個的 `yume/`。

裝了 yume 的 macOS 上因此不用配置任何東西：`:yume-scheme` 直接就有那五個方案。（在
2026-09-07 之前它只認 Linux 那一套路徑，於是一台裝好裝滿的 Mac 一個方案都找不到。）

**自己造的方案也一樣掃得到。** 出廠那幾個方案是 `schemes/<名字>.toml` 一個檔一個；使用者
自己裝的則各佔一個**槽位**——`…/Yume/installed/<八位十六進制>/`，一格一個方案，裏面是
`custom.ytab`（碼表）、`custom.yzg`（字根）、`custom.ycdv`（這個方案自己的拆分）和
`custom.yscm`（這個方案自己的設置）。掃到一格就多一個方案，名字是方案作者寫在
`custom.yscm` 裏的那個：

```
:yume-scheme custom.6947b838      冰雪清韻
:yume-scheme custom.cc2d1290      天碼
```

碼長、選重鍵、頂不頂功**不猜**——照 `custom.yscm` 辦，跟輸入法裏是同一份。槽位另外兩個
位置也認（Windows 的 `data/custom/`、方案管理之前的裸 `custom/`），同一格只算一次。

**問一句現在用的是哪一個：**

```
:yume                 靈明 · 碼表 /Users/…/.local/share/yumete/schemes/ling.ytab · 拆分 關
:yume-builtin         改用出廠自帶那一份（裝的那份壞了、或者比它舊的時候）
```

出廠那一份會**說自己有多舊**——`出廠自帶 2026-08-28 13:08`，取自宇夢發佈包裏 `VERSION`
的構建時間；自己編譯的資料沒有那個檔案，就報碼表本身的日期。編進二進制的碼表是一張
**快照**，看到一個不認識的候選時，你該先知道這張快照有多舊，再去宇浩那邊找 bug。

（只報時間不報版本號：問題是「這有多舊」，而「3.12.0」要你先記得那是什麼時候。）

**裝了卻沒用上的檔，`:yume` 也會說。** 二進制格式跟着 yume-core 走，換過格式之後舊的
資料目錄看上去一切正常——檔案都在，只是核心一個都不收，於是拆分注解整批消失而哪裏都
不提。現在那句話會接在後面：

```
靈明 · 碼表 …/ling.ytab · 拆分 開 · 上屏 延遲（頂字）
  · data/chaifen.ydiv 核心不認：bad division magic（期望 YDV20260904，檔頭是 YDV20260828）
```

看見這個就重跑一次 `scripts/build.sh`。**沒裝的檔不算**——清單裏一半本來就是可選的，
真列出來反而把要緊的那一行埋了。

一直要打字的人寫進配置：

```toml
[ime]
scheme = "lingming"
start = true          # 啟動就載入碼表
```

啟動因此是**即時的**——`yumete --version` 和 `yumete -p 章節.md` 都是 0.00 秒。

### 命令：只記動詞，不記參數

打 `:` 列出全部命令，打幾個字母narrow下去——這是原來就有的。新的是：**打一個空格，它
就告訴你後面可以接什麼**。

```
:view-dense ▊          on 開   off 關
:syntax ▊         markdown 「#」標題、「**粗**」   typst 「=」標題、「#import」
:yume ▊           scheme 換方案（靈明、日月…）   chaifen 候選旁的拆分注解
:ruby-html ▊      on 開   off 關
```

`Tab` 在這些詞之間輪換，補的是**你正在打的那一個詞**，不是整行。

**括號裏是最短的寫法**，而且它是**算出來的**：

```
:yume (y)     :render (ren)     :table (ta)     scheme (s)     format (f)
```

**名字是代號的那幾行，後面跟着灰色的備注。** 方案是唯一這樣的一組——yume 裝進去的方案
按槽位取名，一列十六進制看不出誰是誰：

```
scheme custom.6947b838   冰雪清韻
scheme custom.cc2d1290   天碼
scheme lingming          靈明
```

打進去的仍然是**代號**（名字會變、會撞，槽位不會），備注只管讓你認出是哪一個——**而且
它搜得到**：`:yume-scheme ` 之後點一下 Shift 切中文，打「冰雪」就只剩那一條。其餘的行
沒有備注：`on` 旁邊再寫一次「on」是噪音，而高亮那一行的說明本來就在底下那條。

**`:` 和 `/` 這一行可以編輯。** `←` `→` 走，`Home` `End` 兩頭，`C-w` 退一個詞，
`C-u` 退整行，`Delete` 刪光標下那一個字，`↑` `↓` 翻你這一次會話裏打過的——`:` 和 `/` 各有各的一份。長長一條
`:%s` 打錯一個字，不用退回去重打。

規則一句話：**不重複的前綴就算數**，命令和參數都一樣。`:y` 就是 `:yume`——一族的頭不會
和自己底下的命令撞——`:yume-s l` 就是 `:yume-scheme lingming`。前綴撞了兩個詞就**兩個都不選**——`:re` 同時是 `recover`、
`redo`、`render` 的前綴，所以它報「不認識」，而不是悄悄挑一個。

已經宣告的短名**勝過**前綴規則，所以你熟的拼法不會變意思：`w` 是三個命令的前綴，但
`:w` 仍然是 `write`；`:e` 仍然是開檔案，不是 `export`。

括號裏那個是**算的不是寫死的**，所以以後加一個和它撞的命令，這個提示會在**同一次修改
裏**自己變長，不會留下一個教你打錯的短名。

**「父命令」不是另一套機制。** `:yume-scheme` 就是一個「取值恰好是動詞」的參數——所以
實現一次參數補全，命令歸類就白撿了：沒有第二條代碼路徑要維護，也沒有第二樣東西要你
學。想多深就多深（`:ruby-format html` 是三層），補全並不知道有什麼區別。

歸類只在**真的存在一組**的地方做，而且**舊名字直接刪掉**——留着兩套拼法，等於這條哲學
只是嘴上說說：

| 現在 | 沒有了 |
|---|---|
| `:yume-scheme 靈明` `:yume-chaifen` | `:scheme` `:chaifen` `:cf` |
| `:ruby full/off` `:ruby-html on` `:ruby-format typst` | `:ruby-on` `:ruby-off` `:render-ruby-html` … |
| `:layout vertical` | `:vertical` `:horizontal` |
| `:view-wrap off` | `:nowrap` |
| `:render off/basic/full` | `:markup` `:wysiwyg` `:source` |
| `:buffer` `:buffer-next/previous/close` | `:buffers` `:ls` `:bd` |
| `:clipboard-yank/paste` | `:cy` `:cp` |
| `:view-wrap/dense/bands/sentence/hanging/numbers/typewriter/focus/meter/punct/hud/preview` | `:wrap` `:dense` `:bands` `:sentence` `:hanging` `:numbers` `:typewriter` `:focus` `:meter` `:note` `:hud` `:preview` |
| `:count-progress` `:count-target 3000` | `:progress` `:prog` `:target` |
| `:write-all` `:write-as 新名.md` | `:wall` `:saveas` `:sav` |
| `:table-jump 木` `:table-find column 甲` | `:row` `:search` |
| `:check-merge` | `:conflicts` |
| `:buffer-close` | `:bclose` |
| `:theme system/dark/light` | `:appearance` |

判斷的標準是一句話：**這個名字是「一件事」，還是「某件事的一個取值」？** `vertical` 是
`layout` 的取值，`ruby-on` 是 `ruby` 的取值，`nowrap` 是 `wrap` 的取值——取值不配有自己
的命令名。而 `:w` `:q` `:e` `:s` `:toc` `:grep` 各自就是一件事，名字又短，硬歸類只會更糟。

**歸了類，名字要重新起。** 舊名字得自己扛全部意思，所以它們長：`conflicts` `search`
`row` `note`。歸到父親底下之後，那個名詞已經由父親說了，孩子只剩下**動詞**那一半：

| 現在 | 從前 | 父親已經說了 |
|---|---|---|
| `:check-merge` | `:conflicts` | check ＝ 查什麼有沒有問題 |
| `:table-find` | `:search` | table ＝ 在表格裏 |
| `:table-jump` | `:row` | table ＝ 表格的行 |
| `:view-punct` | `:note` | view ＝ 只是怎麼看，不動字 |

`:table search` 讀起來是「表格搜索」，`:table-find` 讀起來是「在表格裏找」——後者纔是
你要做的事。`:view note` 更糟：它像「看筆記」，而那條命令是把標點畫成淡的。

**打舊名字，它會告訴你新的在哪。** `:dense` 不再是命令，可是打下去不會只說「不認識」：

```
:dense
沒有「dense」這個命令；你要的是 `:view-dense`
```

這句話是**算出來的**——掃一遍命令樹，找名字對得上的孩子。所以以後再摺一次，指路的話
自己就對了，不用有人記得回來改。算不出來的只有「改了名」的那幾條——上表四條，
加上 `:bclose`→`:buffer-close`、`:wall`→`:write-all`、`:saveas`→`:write-as`、
`:appearance`→`:theme`——因為 `conflicts` 這個詞在樹裏已經不存在了，另記一張表。

### 短寫

完整命令是摺過的，說得出它做什麼；**短寫是它的首字母，別的都不是**——`:bc` 有，
`:bclose` 沒有，因為那既不是完整的名字也不是首字母，正是摺疊要去掉的那種拼法。

**空格與連字號分工**：空格是**樹**——`:buffer-close` 是 buffer 的一種、`:write-all` 是
寫的一種，選單一層層點得進去。連字號是**並列**——`:write-quit` 不是「一種寫法」，是
「寫，然後退」，兩個動詞。這不只是讀起來的事：`:write` 後面跟的是**路徑**，所以
寫成 `:write` 加一個 `quit`，就只能在「一個詞」和「一個叫 quit 的檔案」之間猜；
`:write-quit` 是一個詞，沒有可猜的。

| 短寫 | 就是 |
| --- | --- |
| `:bc` `:bn` `:bp` | `:buffer-close` `:buffer-next` `:buffer-previous` |
| `:qa` | `:quit-all` |
| `:wa` | `:write-all` |
| `:wq`（也認 vi 的 `:x`） | `:write-quit` |
| `:y` | `:yume` ＝ 開中文——一族的頭，兩個鍵 |

短寫只是**展開**：`:bc!` 就是 `:buffer-close!`，長命令以後長出什麼，短寫一樣拿得到。
補全也照這條走——打 `:wq` 提示的是 `write quit`，因為那纔是說得出意思的那個拼法。

**`:wysiwyg` 這個詞也沒了。** 它和 `:markup` 本來就是同一根軸上的三檔——代碼裏
`wysiwyg && show_markup` 早就承認了這一點：不著色的時候「把標記藏起來」沒有意義，那不是
把標記收起來，是把「這裏本來是粗體」這件事**扔掉**。所以合成一個：

| | |
|---|---|
| `:render off` | 原文，不著色 |
| `:render basic` | 著色，標記留在畫面上（默認） |
| `:render full` | 標記拿掉，只在光標那一處展開（所見即所得） |

三個值一根軸，第四種組合在類型上就不存在了。

上一次這麼做（方案、注音、橫竖、著色）命令從 42 個減到 26 個；2026-09-08 又摺了一次，
21 個名字進了 7 個父命令（`view` `check` `table` `count` `write` `buffer` `theme`），
**那一次**把頂層從 61 個減到 41 個。編輯器這期間長出來的功能比摺掉的名字還多——
**摺的是名字，不是功能**，而且摺完之後還會接着長：今天頂層是多少，按一下 `:` 看面板
右下角那個 `1/n` 就知道，這裏不寫死一個會過期的數。

### 整棵樹

上面說的是**怎麼記**，這一節是**查**：一級命令在外，二級命令縮進一格，再深一層的取值
跟在 `｜` 後面。同一份東西 `:help commands` 會開成一個可以搜的緩衝區，`::` 則按「做什麼」
找——這裏是給眼睛從頭掃一遍用的。

`（括號）` 裏是宣告的別名；最短的打法是**算出來的**，`:` 那一行自己會告訴你。

  - `chaifen` ｜ `on` `off` — 候選旁的拆分注解

### `::`：忘了名字就說它是做什麼的

前一節整節都建立在一件事上：**你記得那個動詞**。可是這些動詞是英文的，而你想的是
「竖排模式」。打不出來的命令等於沒有。

**再按一次 `:`**（空行上），那一行就從「命令叫什麼」變成「命令做什麼」：

```
::竖排           → :layout vertical    把整頁轉成竖排，一行一行從右往左
::排序           → :table-sort         照這幾欄排
::lyt            → :layout             橫排還是竖排
```

- **中文直接打。** 這一行開着輸入法（單按一下 Shift 切中文，跟 `/` 搜索一樣），
  因為它本來就是給中文問句用的。
- **三種語言一起找，只顯示你在用的那一種。** 說明本來就寫了繁、簡、英三份。你用繁體
  版打「竖排」（簡體）也找得到，你只記得英文名也找得到。
- **打不全也行。** `lyt` 找得到 `layout`，`tbsort` 找得到 `table sort`——字母是**順序**
  對上就算，不必連着。手滑打成 `laoyut` 也還在（只對**命令名**，只對三個字母以上的英文，容錯兩個字母）。
- **`↑` `↓` 挑，`⇥` 選中。**

**`⇥` 不執行任何東西**，它把整條命令**寫回 `:` 那一行**，光標放在後面，然後你自己按
Enter。所以 Enter 跑的永遠是你**看得見的那一行**，不是它猜的東西——`:q!` 是不能撤銷的。

`::` 和 `:` 是兩個模式，可以互相走：空行上第二個 `:` 進去，退格退空了就回 `:`，
`Esc` 一次回正文。

**說明之外還有一層看不見的詞。** 每條命令在 `messages.toml` 裏可以寫一行
`find = "直排 縱書 tategaki columns"`——搜得到，但不顯示。所以說明可以寫得短，而
「同一件事的另外四種說法」照樣找得着。加一個說法就是加一個詞，不用動代碼。

### 折行

橫排時一段太寬會**折到下一行**接着排。中文一個自然段常常就是一整行幾百字，不折就得
一路往右捲纔讀得完，所以默認是開的；`:view-wrap off` 關掉，`:view-wrap` 開回來。

關掉之後一段就是**一整行**，多長算多長，頁面跟着光標左右走——`gl` 走到行尾，窗口就跟
過去。行號欄不動，它是家具不是正文。**竪排沒有這一項**：一縱斷在窗口高度上，`:view-wrap
off` 在那邊會直接告訴你這條命令只管橫排（`:view-wrap 40` 兩邊都算數，見第五章）。

折行處遵兩條規矩：拉丁詞不從中間斷開（`Helix` 不會拆成 `Hel` 和 `ix`），行首不出現
。、」）這類收句的標點，行尾不出現「（這類開頭的括號——也就是**禁則處理**。

一段剛好排滿一行時，下面會多出一個空行：那是給光標站的。行尾之後的那一格在屏幕上不
存在，總得有地方放下一個字。

要緊的是 `j` `k` 走的是**屏幕上的那一行**，不是整個自然段。段落幾百字時，按邏輯行
移動的 `j` 一下就跳過整屏，那不是讀者眼睛所在的地方。行號只標在段落的**第一行**：
號碼是段落的號碼，逐行重複反而像是好幾段。

## 五、竪排（縱書）

`:layout vertical`，或 `yumete -v`，或配置裡 `layout = "vertical"`。

文字從上往下走，一條一條的**縱**從右往左排。「縱」就是竪排裡的「行」——之所以另起
一個名字，是因為在這裡「行」和「列」各有兩個意思。一個段落會軟折成若干縱，默認**窗口能給
多長就多長**——一縱多長是關於這本書的決定，編輯器沒資格替你做。`:view-wrap 32` 或
`[editor] zong_length = 32` 是你自己下的那個決定（32 字前後是散文舒服的上限）。

### 5.1 移動

`h j k l` 保持**屏幕方向**的意思。`j`、`k` 順著縱往下讀、往上讀，也就是文本的前進和
後退；`h`、`l` 換到左邊、右邊那一縱。長段落從一縱的底部自動接到下一縱的頂部，不用你
管。

**鼠標滾輪**翻頁：一格滾三縱。為此 yumete 接管了鼠標，所以終端自帶的拖選複製需要按
住修飾鍵（macOS 上是 Option）——Helix 也是這麼取捨的。

狀態欄寫的是 `橫 55, 縱 1, 字 20`：段落是橫著往左排的，所以段號是個**橫**向位置；
**縱**是這段的第幾縱；**字**是在這一縱裡往下第幾個。

### 5.2 版面自動做的事

`[editor] paper_ticks = 10` 會在邊欄上每十個字點一個淡刻度，像真的稿紙——傳統稿紙是
有格子的（20×20 = 400 字），寫作者靠它估篇幅，而竪排版面本來就是字格，這是它免費拿得
到、橫排編輯器沒有等價物的東西。刻度讓位給注音和旁置的標點（那兩樣有意義，刻度只是引
導視線）。開啓會給每一縱都留出邊欄，整頁因此往左退一格。

段落號那一條有自己的**底色**。別的編輯器靠**位置**把行號和正文分開——行號在一條專用
的欄裏，正文永遠進不去，所以再暗也不會被誤讀。竪排時號碼在縱的**正上方**、佔的是正
文同一列，位置分不開，只剩顏色可分；那條帶的底色是色階上的一格（見「主題」）。

狀態欄的座標是**兩個數**：「橫 56-2, 字 23」——第 56 段的第 2 縱，往下第 23 個字。
段落不夠長、只佔一縱時就只寫「橫 56」。

- **標點會轉向**：`。`→`︒`、`「」`→`﹁﹂`、`《》`→`︽︾`、`——`→`︱︱`。只在屏幕上
  轉，檔案裡還是原來的字符。
- **半角字符一行一個**，靠格子右邊，這樣拉丁字母和數字會沿著漢字右側排成一條線。想
  讓一對半角字擠進一格（**縦中横**），開 `[editor] tatechuyoko = true`。
- **字體很要緊。** 轉向後的標點是 U+FE10–FE48，思源／Noto CJK、更紗黑體、霞鶩文楷
  等寬都有，純拉丁的編程字體沒有。

### 5.3 標點旁置

`:view-hanging`（單寫是反過來，`:view-hanging on`／`:view-hanging off` 是說死），或配置裡
`hanging_punctuation = true`。

古籍的排法裡，。，、？！：；「」 不佔一格，而是掛在它所屬的字旁邊，正文一路連下去
不斷——這樣一頁對話才不會看起來有一半是空的。

```
   關閉       開啟
   子         子
   曰         曰:
   ︓         學｢
   ﹁         而
   學         時
   而         之,
```

掛出去的標點用的是**半角形**——`。`→`｡`、`、`→`､`、`「」`→`｢｣`，其餘借 ASCII 的
`,?!:;()`。這不是將就：邊欄只有一格寬，全角的 `︒` 塞進去會壓到右邊那一縱、把那個字
整個蓋掉；把邊欄加寬到兩格則是每一縱都多佔一格，正好抵消了旁置本來要省的東西。而且
從版式上說，句讀本來就是寫在字右邊的**小**符號。

`《》【】〔〕『』` 沒有半角形，所以**不掛**，照舊在正文佔一格——書名號比句號少得多，
而一頁之中邊欄寬度忽寬忽窄就不成其為邊欄了。破折號和省略號同樣佔格：「——」是一條貫
穿的全角橫線，塞進半角邊欄就斷了。

**開括號**掛在它引出的那個字旁邊，其餘的掛在它跟隨的那個字旁邊——即使那個字在一組注
音裡面（`「<ruby>漢…`）。

**連着兩個標點就不掛了，兩個擠進正文的一格**：`。」` 是 `｡｣`，一格兩欄，各佔一欄。這
是印刷的做法——JLREQ §3.1.4① 和 clreq §6.3.2.2 都說句點類後面接終止括號類要**去掉之
間的空**，而句讀和括號本來就是半角字身，兩個正好合成一格；clreq §6.1.3 從另一頭說了同
一件事：**連續標點不作懸掛**。中文對話稿的句尾差不多都是 `。」`，從前那裏第二個標點在
邊欄自成一行、正文那一格空着，讀起來就是一路上一個接一個的洞。

一個標點照舊掛——省下的地方本來就在那裏。`「冬」` 這種不算連續：`「` 是掛在它**引出**
的那個字前面的，把它拉出來就成了「冬「」」。

標點和注音搶同一個邊欄，**標點優先**——標點本來就該在它那個字的那一行——所以兩者同
時出現時，注音往上讓，佔據這個字上方的幾行。

### 5.4 注音（振假名／ruby）

注音以標記形式寫在檔案裡，由 yumete **排出來**：基字被撐開對著它的注音（所以相鄰兩
個注音不會撞在一起），注音走在該縱右側那個半角格子裡。

標記不是 yumete 自創的。兩種都認，可以同時開，默認按檔案後綴決定：

| 方言 | 寫法 |
| --- | --- |
| `html` | `<ruby>口<rt>kǒu</rt></ruby>` —— Markdown、HTML |
| `typst` | `#ruby("口", "kǒu")` —— Typst |

| | |
| --- | --- |
| `:ruby full` / `:ruby basic` / `:ruby off` | 排出注音／認得讀音但標記留在畫面上／源碼 |
| `:ruby-html` | 也讀 HTML 注音（`:ruby-html off` 停止） |
| `:ruby-typst` | 也讀 Typst 注音（`:ruby-typst off` 停止） |
| `:ruby-format html` | 把全篇注音改寫成 HTML |
| `:ruby-format typst` | 改寫成 Typst |
| `:ruby-auto` | 按詞把讀音注上去（見 5.6） |
| `:ruby-auto rare` | 只注生僻字 |

**橫排也排注音了**：放在那一行**上面**的一行裏，落在它所注的那個字的欄位上。只有**有
注音的那一行**才多佔一行——一段話裏注了一個字，不會把整本書變成雙倍行距。兩個注音如果
會撞在一起，後一個**不畫**（而不是擠着畫）：注錯了字的注音比沒有注音更糟。

竪排仍然是把注音放在該縱右側那個半角格子裏，基字撐開對着它——那是縱書本來的做法，也是
兩個注音永遠不會相撞的排法。

讀音可以是**全角**的——注音符號（ㄩㄥˇ）、日文假名——這時注音欄自動變成兩格寬，整頁
一致。以前寫死一格，每出現一個全角讀音，後面所有的縱就往左推一格，整頁階梯狀崩塌；
而這個功能本來就叫「振假名」。拼音是半角，仍然只佔一格（除非你把
`ambiguous_width` 設成 `wide` 而讀音裏有帶調母音，那也是兩格——因為終端就是那麼畫
的）。

### 5.5 Ruby 模式

注音排出來以後，`<rt>` 根本不在屏幕上，光標走不進去。**`空格 r`**（命令行寫法是
`:ruby`）在狀態欄開一行專門改它：

- **光標在已有注音上**——載入現有讀音，直接改。
- **有選區**——空著，你打什麼就給它注什麼。
- **提交空的讀音就是取消注音**，連標記一起去掉。所以在這個模式裡退格退到空**不會**
  離開（跟搜索行不同），空的狀態必須能到達；退出用 `Esc`。
- **輸入法在這裡能用**，因為讀音可能是假名或拼音。

**為什麼是二級鍵。** 一頁裏注不了幾個，而且不必按下去就發生——一級鍵留給非立刻不可
的事（`r` 就是：見 `docs/development.md` §5.1）。

讀音裡用 `|` 分成和基字數目相同的幾段，就是逐字注音：`hàn|zì` 給 漢字 注出兩組；
`hàn zì` 則是整個詞一個注音。

### 5.6 自動注音：`:ruby-auto`

一個字一個字注是注不完的。`:ruby-auto` 把選中的那一段——沒有選區就是整份稿子——按詞
走一遍，查得到讀音的就注上去，寫成這份檔案本來的那種方言（`.typ` 出 Typst，別的出
HTML）。注了幾個詞狀態欄會說；不要就 `u`，一步全退回去。

**按詞，不是按字。** 了 在 為了 裏是 `le`，在 了解 裏是 `liǎo`。一個字一個字查的工具
必然錯一半——Word 的「拼音指南」就是這麼錯的，所以沒人用第二次。yumete 問的是宇夢的
讀音表，**問的是整個詞**，多音字由它所在的詞定下來。查不到讀音的詞原樣留着，不猜。

**已經注過的不動。** 你手改過的那個讀音，不會被這條命令蓋掉。

**同一個拼法只差聲調的分不出來。** 為 在 認為 裏是 `wéi`、在 為了 裏是 `wèi`，可讀音表
本身不帶調（`ren wei`），所以這一類——為、難（`nán`／`nàn`）、好、教、中——一律取常用的
那一個，可能要你手改。差在拼法上的（了、行、和、長）沒有這個問題。

**你真正想要的多半是 `:ruby-auto rare`。** 每個字都有讀音的小說是課本，不是小說；只在
真正生僻的那幾個字上有讀音的小說纔讀得完。`rare` 只注**四套現行字集都沒收**的字——大陸
的通用規範、通規繁、臺灣、香港，四套裏任何一套有它就不注；只有古籍字表有的、四套都沒
有的纔注。就是讀者真會卡住的那些。

    :ruby-auto rare        整份稿子，只注生僻字
    :ruby-auto             選中的那一段，全注

讀音來自宇夢的**拆分表**（`:yume-scheme` 載進來的那一份）。沒載的時候這條命令什麼也不
做，只在狀態欄說一句。

### 5.7 着重號

漢字不會斜。西文強調靠字母往右倒，漢字沒有這回事——中文的強調是**在每個字旁邊點一個
點**，叫着重號，竪排時點在字的右邊。所以 yumete 竪排時就把 `*這樣*` 畫成着重號：

```
   一
   個·
   詞·
   而
   已
```

不需要新語法：`*字*` 本來就是 `<em>`，而 `<em>` 在中文裡的樣子**就是**着重號。`**粗**`
不點——那是另一種字重，兩樣都點的話半頁都是點。

點畫在邊欄裡，和注音、旁置的句讀、稿紙刻度同一欄，**排在最後**：有注音或者有掛出去的
標點，那一格歸它們。邊欄是**排版時買下來的**，和注音一樣：哪一段有強調，那一段的縱右邊
就留一格——所以密排（`:view-dense`、縱間距 0）也照樣點得出來，只是那一縱會往左讓一格。沒有強
調的段落一格都不多花。`:render off` 時不點，那時候 `*` 是字面上的星號。

### 5.8 一句一縱：`:view-sentence`

校對的時候句子要一句一句地看。老辦法是 `:%s/。/。\n/g` 把稿子劈開，看完再撤銷——**這
是拿改文件當看法用**，撤銷少按一次就寫進去了。

`:view-sentence` 是同一件事，但**一個字都不動**：打開它，竪排就在每個句號、問號、嘆號、
省略號之後起新的一縱。

```
:view-sentence        一句一縱
:view-sentence off    回去
```

一句太長就照常換行——一縱裝不下的句子仍然接着往下一縱走，只是**下一句一定另起**。
句末的引號跟着句號走：`「你回來了。」` 是一句，收尾那個 `」` 不會被甩到下一縱去。

斷句用的就是 `(` `)` 兩個動作跳的那條界——你看見的縱頭，正是按 `)` 會停的地方。

它只是竪排的一個看法，跟 `:view-dense`、`:view-bands` 一樣：文件沒有變，`:w` 存下去的還是原來
那一段。

### 5.9 平仄：`:view-meter`

寫舊體詩、填詞的時候，平仄是靠耳朵一個字一個字數的。`:view-meter` 把它畫出來——用的就是詞譜
自己那套記號，畫在注音和着重號共用的那一欄裡：

```
   春○
   眠○
   不●
   覺○
   曉▲
```

`○` 平，`●` 仄；句末那個字換成三角——`△` 平韻、`▲` 仄韻——因為韻腳落在那裡。橫排時
這一欄變成字上面那一行，位置對着每個字。

```
:view-meter        開
:view-meter off    關
```

**⚠️ 這是今音平仄，入聲是它會說謊的地方。** 調類是從現代漢語拼音讀出來的，因為數據裡
只有這個。中古音的入聲派進了現代的四個聲調（入派三聲），所以 `竹` zhú、`白` bái、
`石` shí 這些字**在規則裡是仄，在這一欄裡是平**。拆分表裡沒有中古音那一欄可查，從拼音
也推不回去——那個信息已經不在了。

按**中華新韻**寫，這一欄就是對的；按**平水韻**寫，它是頭一遍，把三聲四聲那一半的錯挑
出來，另一半它不出聲——知道它是這個形狀，就還是值得開着。

輕聲不畫。它既不平也不仄，舊體詩裡本來也沒有這件事。

平仄從**詞**查起而不是從字查起（`了` 在「為了」是 `le`，在「了解」是 `liǎo`），所以
它跟 `:ruby-auto` 讀的是同一份數據、走的是同一條路：**沒裝拆分表就查不到**，那時候
`:view-meter` 會直說，而不是畫一欄空的給你。

那一欄有注音或者有掛出去的標點時，讓給它們——注音是文件裡寫着的東西，平仄是編輯器在
一旁說話。着重號排在平仄後面。

### 5.10 標點寫錯了就在旁邊寫上：`:view-punct`

`:check-punct` 給的是一張清單，要跳過去看。`:view-punct` 換一個做法：**該寫的那個標點，就
寫在寫錯的那個旁邊**，當場看見，不用離開這一段。

```
他說,，好          橫排：逗號寫在半角逗號後面
```

```
:view-punct         開
:view-punct off     關
```

竪排也一樣——它跟着 `,` 一起轉過來，畫在那一格裏。**它跟正文不是一個顏色**：正文是
正文的墨色，它是編輯器指東西用的那個色，一眼分得開。

**它不是文件裏的字。** 光標永遠停不到它上面，`x` 刪不掉它，`:w` 存下去的還是你寫的
那一段——它跟輸入法的候選、表格對齊用的補白是同一路東西，只是排版時借了幾格地方。改對了那個標點，它自己就沒了。

**只看一行之內看得出來的那兩樣**：半角標點、`...`。少一個 `」` 它不說——**一行看不
見下一段**，而跨段的引文本來就是每段重開一個「（見 `:check-punct`）。那一樣仍舊歸
`:check-punct` 管。

`:render off` 的時候不畫。那個模式是「把文件原樣給我看」，多畫一個字就不是原樣了。
代碼塊、圍欄裏面也不畫，那裏的 `,` 本來就是對的。

## 六、輸入法

宇夢引擎是嵌進來的——沒有 FFI，沒有另一個進程。Insert 模式下打編碼就出候選框。

**三個狀態，兩個開關。** 外面那個是 `:yume on`／`:yume off`：yume 接管鍵盤，還是把鍵盤
整個交還給系統——系統自己的輸入法要用的正是「交還」那一個。**單獨輕點 Shift** 是裏面那
個：接管着的時候，在 中文 和 ABC 之間切。

| 狀態 | 怎麼進去 | 底下那行寫什麼 |
| --- | --- | --- |
| 中文 | `:yume on`／輕點 Shift（從 ABC） | `[靈明]` |
| ABC | 輕點 Shift／`:yume abc` | `[ABC]` |
| 關 | `:yume off` | 什麼都不寫 |

ABC 和「關」在鍵盤上看起來一樣——按鍵都打它自己——**差別在 yume 還在不在**，而這個差別
是實的：下面那段說為什麼。

**外面那個開關沒有快捷鍵，是有意的。** 試過的兩個都退了回來：`C-Space` 被 macOS 花掉兩
次（Spotlight、切換輸入源），根本到不了終端；`Shift+空格` 在多數輸入法裏是全／半角，而
yume 「關」着的時候鍵盤正在系統那個輸入法手上——最要緊的那個方向（關→開）恰恰按不動。
寫字的人一直在按的是裏面那個（輕點 Shift），它不佔鍵位；外面那個一天按不了一次，值不起
一個鍵。

| | |
| --- | --- |
| 空格 / `1`–`9` | 選中候選 |
| `-` / `=` | 上一頁／下一頁 |
| 退格 | 修改編碼 |
| Esc | 取消這次輸入 |
| Tab | `bare` 下召出候選框，管這一個詞 |

**輕點 Shift 要終端報得出「單獨按下的那一個 Shift」**，而按 Kitty 鍵盤協議，這件事
只有一個開關管得着（`REPORT_ALL_KEYS_AS_ESCAPE_CODES`）——偏偏同一個開關會讓**系統輸入
法組不了字**：上屏出來一排空格。兩件事要的是同一個開關，所以 yumete 只在 **yume 接管着
鍵盤的時候**推上去，一交還就撤掉。這就是「ABC」和「關」為什麼必須是兩個狀態。

終端要支持 Kitty 鍵盤協議：Ghostty、kitty、WezTerm、foot、Alacritty、Konsole 都行。
Apple Terminal 報不出單獨的 Shift，在那裏三個狀態都用 `:yume on|abc|off` 進。

**哪些地方能打中文：** Insert、搜索（`/`）、Ruby 模式。**不包括** `:` 命令行——命令
名全是 ASCII。

**候選框**在竪排下用宇夢的**墨香**深色皮膚。候選用 ㊀㊁㊂ 編號，從右往左排，方向和
它即將加入的文字一致；已打的編碼順著最右一列往下讀，每個候選還差的鍵（下標）順著它
自己那一列往下讀。

`;` 和 `'` 是**選二、選三**——這是方案的綁定表決定的，不是 yumete 自己定的，所以自
定義碼表把 `-` 拿去當編碼鍵時，`-` 就還給碼表。組字中的方向鍵、Tab、Home/End 一律不
漏給編輯器（漏了的話光標會被移走而編碼還在，之後上屏的字就落在別處）——Tab 在 `bare`
下另有用處，見下面「空空如也」。打了一串死碼時候選框**不會消失**，裏面就剩你打的那
幾個字母——不然你不知道要退幾格。

`:yume-chaifen` 打開高亮候選的**二重注解**（拆分＋編碼）；單寫是反過來，
`:yume-chaifen on`／`off` 是說死。

**上屏方式**用 `:yume-commit delayed|unique|fluency`（不寫模式就是問現在是哪一個）：

- **`delayed`** 延遲上屏（頂字）——碼成立了先等着，下一鍵拼不成碼時纔把前面那段頂上去。
- **`unique`** 唯一上屏（也可以寫 `auto`）——碼成立而且只有一個候選，直接上屏。
- **`fluency`** 整句——一路打下去，空格確認整句，從不自己上屏。

三個名字是 yume 自己的（`CommitStrategy`），三層合成也在 yume 的核心裏做，所以這裏選的
那一個，在 macOS／Windows 的輸入法面板裏是同一件事。選了以後**換方案不會丟**；只有拼音
例外——它沒有碼表可以逐段查，永遠是整句，命令會直接說出來而不是假裝設上了。配置檔的
`[ime] commit` 是同一個設置，不寫就交給輸入法自己按方案定。

注意 `:yume-c` 現在同時像 `chaifen` 和 `commit`，兩個都不算——`:yume-ch` 與 `:yume-co`
各自明確（打 `:yume-c`，選單會把兩個都列出來）。

**換方案**用 `:yume-scheme lingming|xingchen|qingyun|riyue|pinyin`，或者配置檔的
`[ime] scheme`。yumete 自帶靈明（編進二進制）；其餘四個方案的碼表跟 yume 一樣，從
yuhao-assess-data 下載後裝進資料目錄（yume 的 `scripts/build.sh` 會裝）。碼表不在機器
上時它會說清楚是「沒裝」而不是「沒這個方案」，並且留在原來能用的方案上。使用者自己裝進
yume 的方案跟着一起列出來，名字是 `custom.<八位>`（見上面「自己造的方案也一樣掃得到」）。

**用你自己的碼表**：

```
:yume-table ~/.yumete/wubi86.dict.yaml
```

**Rime 的 `.dict.yaml` 直接能用**——五筆、倉頡、粵拼、朙月拼音，下載下來就打得了，
不用轉檔：yume-core 的碼表讀取會自動認出 YAML 檔頭並掐掉，也會自動判斷是
`字<TAB>碼` 還是 `碼<TAB>字`、是空格分隔還是製表符分隔。手寫的兩列文字檔一樣能用。

語言層（詞頻、詞彙）還是從裝好的資料裏來——換的是**拼法**，不是語言。

### 空空如也——把候選框收起來

`:yume-panel full|bare`（不寫模式就是問現在是哪一個）：

- **`full`** 候選框——光標旁邊那張帶框的表，一直以來的樣子。
- **`bare`** 行內預覽——**首選直接畫在正文裏**，光標停在它末尾；已打的編碼畫在光標下
  面那一行（下面擠不下就往上一行，再擠不下就只剩狀態欄右端那一份）。候選框一個都不
  畫，**`Tab` 把它召出來**，管這一個詞，詞上了屏它就跟着走。

宇夢自己的輸入法面板已經有一張完整的候選框了；寫小說的這張紙上不需要第二張。九成的
按鍵都是取首選，為了它蓋掉九行稿子並不划算——所以首選就寫在句子裏，你讀的是句子而不
是列表。真要挑的時候 `Tab` 一下。

畫在正文裏的那幾個字**不在檔案裏**，但它們**在頁面上**：光標、`j`、滑鼠、折行、禁則
算的是同一頁（這是 #210 那一層的意思），所以行內預覽不會把後面的字擠到你看不見的地
方去，也不會讓光標和你看到的位置對不上。

`/` 搜索是例外：它在狀態欄上組字，那裏沒有正文可以畫，所以搜索框的候選框照畫。

配置檔是 `[panel] display`。這和**上屏方式**（`:yume-commit`）是兩件互不相干的事——
一個是「字什麼時候落到紙上」，一個是「候選在哪兒讀」，六種組合都成立。

### 分頁條

開了不止一個檔案時，最上面會有一條**分頁**，像終端的 tab 一樣：每個檔案一格，正在寫
的那個亮著（用頁面本身的底色，所以它讀起來像是疊在最前面的那張紙），改過沒存的後面
掛一個 `+`。滑鼠可以直接點——鼠標本來就為滾輪捕獲了，這一項不多花什麼。

`[editor] tabs` 可設 `"auto"`（默認，開了一個檔案就不畫，省一行）、`"always"`、
`"never"`。分頁條在的時候狀態欄就不再重複 `[2/3]`——同一件事說一次就夠。

### 空格選單

按**空格**（Normal 模式）會列出它能接的鍵——不用離開頁面就看得見有哪些：

| | |
| --- | --- |
| `空格 e` | 檔案側欄（開／關） |
| `空格 o` | 側欄直接開在大綱 |
| `空格 f` | 開啟檔案（項目內模糊搜尋） |
| `空格 b` | 切換緩衝區 |
| `空格 d` | 字典：游標下那個字的拆分、編碼、讀音…… |
| `空格 r` | 改這裏的注音（開 Ruby 模式，見 5.5） |
| `空格 /` | 全項目搜索（開好 `:grep `，等你打） |
| `空格 ?` | 命令一覽 |
| `空格 y` | 把選區複製到系統剪貼簿（`:clipboard-yank`） |
| `空格 p` | 從系統剪貼簿貼上（`:clipboard-paste`） |
| `空格 "` | 貼上取過的東西——列出最近 16 次 yank／刪除，和帶名字的暫存器 |

**側欄和挑選器不是同一件事。** 挑選器回答「帶我去我心裏那個檔案」，開一下就走；側欄
回答「讓我看見這本書的形狀」，一直開着。一百章分在卷一卷二裏，那棵樹本身就是目錄。

**挑選器裏打得了中文。** 中文稿子的檔名多半是《第三章 雪》，所以輸入法在那張清單裏
照常跑——候選面板掛在查詢那一行下面，單按 Shift 切中英，和 `/` 搜索是同一套。

`空格 e` 開側欄，並且**直接停在你正在寫的那個檔案上**。在側欄裏，移動用的還是正文那
幾個鍵：`j` `k` 上下，`l`（或 Enter）進去——目錄展開，檔案打開，`h` 收起或退回上一層。

**在兩邊之間切換用 `C-w`**——vi 的窗口鍵，而這裏永遠只有一個「另一邊」，所以一個鍵來
回都管。`Esc` 是單向的：交還給正文，樹留着。`q` 直接關掉。

鍵在側欄那邊的時候，狀態欄會**寫出側欄的鍵**（包括怎麼回去）——拿走鍵的那一半有義務
說清楚怎麼還。

`空格 e` 和 `空格 o` 都是「**給我看這個視圖**」，一條規則：側欄沒開就開在那個視圖上，
開着但在別的視圖就切過去，開着而且就在那個視圖但鍵在正文那邊就把鍵拿回來，鍵已經在
側欄裏就收掉。所以同一個鍵按兩次一定回到原點——這是任何開關最起碼的事——而按另一個鍵
是「換視圖」，不是「關掉」。

**`空格 d` 開第四個視圖：字典。** 游標下那個字，宇浩拆分表知道的全部——拆分、編碼、
分節編碼、讀音、注釋、字集、統一碼碼位，還有沒被截短的全息拆分。陸、臺、港三家對幾千
個字的拆法是不一樣的，所以**一個字有幾種拆法就列幾段**，每段頭上寫是哪一家的，而不是
悄悄拿第一個當答案。打字的時候也能問：候選面板開着的時候按 `Tab`，問的是高亮那一條
（是詞就問它的頭一個字）——候選欄一條只有一行，只寫得下拆分和一個碼，其餘的都在這裏。
拆分表裏沒有那個字（或者當前方案是純音碼，根本沒有拆分這一層），它會直說「拆分表裏沒
有這個字」，而不是給你一個空欄。

字典**不在 `Tab` 的輪換裏**：另外三個視圖永遠有東西可看（一個目錄、開着的檔案、這一
章），而它只在你問了之後纔有內容，輪進去多半是空的。所以只能問進去，`Esc`／`C-w` 出來，
`Tab` 出來直接回檔案樹。

**`Tab` 在三個視圖之間走**：檔案樹、打開的緩衝區、當前檔案的大綱。它們回答的是同一個
問題的三個尺度——項目裏有什麼、其中開着什麼、眼前這一章是什麼形狀——所以放在一個地方
輪換，而不是三個面板。每個視圖各自記得自己停在哪裏，`Tab` 來回不會回到頂上。`空格 o`
直接開在大綱。

**`w` 換寬窄。** 平常側欄是窄的（`sidebar_width`，默認 24），因為欄是終端最缺的東西；
但「天門真境之傳家寶扇」這樣的章名在 24 欄裏是要被切掉的，而大綱最不該做的就是切掉
名字。所以按 `w` 它就開到**剛好放得下最長那一條**（最多佔窗口的一半），再按一次收
回去。

大綱認的是 Markdown 的 `#`（Typst 的 `=` 也認）——**不需要 parser**，標題就是行首那幾
個井號。選一條 Enter 就跳過去。

**Typst 的書，大綱會把 `#include` 打開。** 一個主檔案 `#include` 了三十章，源碼裏
只看得見三十個檔名。但章名就寫在那三十個檔案裏，是普通的 `= 標題`——**讀一下就知道
了，不用編譯**。所以大綱直接把它們讀出來：

```
天門真境
  傳家寶扇
  天門攬勝
  ch03.txt        ← 這一章自己沒有標題，只好用檔名
```

縮進是那條標題自己的層級（`=` 一層、`==` 兩層）。選一條 Enter，寫在別的檔案裏的那章
**就打開那個檔案**跳過去，落在標題那一行上。`#import` 不算章——那是借模板，不是加
一章。

## 七、日常

### 底下兩行

底下是**兩行**，回答兩個不同的問題：

```
 m 配對 · i 之內 · a 連同 · s 包起來 · d 去掉 · r 換掉        ← 上面：剛才怎麼了、現在能按什麼
-- NORMAL --  ch01.md   Ln 12, Col 8              螭 U+87ED · CJK Unified Ideographs
```

**下面那行是「我在哪」**——模式、中/英、檔名、位置、光標下那個字。它**永遠不變形**，
所以眼睛每次都在同一個地方找到同一樣東西。以前一條訊息會把位置擠掉甚至頂沒了，那是
因為兩個問題擠在一行上。

**上面那行是「剛才怎麼了、現在能按什麼」**，沒有話說的時候就是空的。它按這個順序回答：

1. **剛發生的事**——`存了 ch01.md`、被擋下的鍵、`找不到`
2. **你按了一半的鍵**——按了 `m` 不記得後面跟什麼，這一行直接列出來。這是它最有用的
   時候：以前這件事只有手冊上有
3. **拿着鍵盤的那塊面板**——側欄、表格（按格還是按字，各自的鍵不同）

`空格` 和挑選器不在這一行上，因為它們本來就開了一塊列着自己的鍵的面板——同一件事在
兩個地方說兩遍，比說一遍差。

代價是**一行**。竪排時那是每一縱少一個字，看得見。`[editor] hints = false` 關掉，關掉
之後訊息回到狀態欄上（沒人看得見的訊息不算訊息）。

### 你打了什麼——光標旁邊那個牌子

打了一半的命令（`3`、`2t`、`d3l`）在兩處說：狀態欄右端，和**光標旁邊**。右端是 vi
一九七六年就定下的位置，可它離眼睛二十行遠；旁邊那個是給眼睛的。

`:view-hud off|basic|full`（不寫就是問它現在是哪一檔）：

- **`off`** 旁邊不畫。狀態欄右端那一份還在——那是底線，哪一檔都不動它。
- **`basic`** 一顆**藥丸**：金字，暗底，一行高，`╰` 那個角指回光標。它**一個
  字都不蓋**——自己去找頁面上的空白，離光標越近越好（差一行等於差四個漢字），左右上
  下都算，找不到就不畫。竪排也一樣：空白在光標**左邊**的時候，角就掛在牌子右端指回
  來。
- **`full`（默認）** 一塊**帶框的面板**，釘在光標正下方，**蓋住那裏的正文**。

外框和「蓋字」是同一個決定，不是兩個。藥丸要的是一行上五個空格，一頁稿子總找得出來；
帶框的面板要的是光標附近一塊三行高的空地，一頁稿子上沒有這種東西——所以要框就得蓋。
反過來也成立：字一旦畫在跟正文同一張紙上，沒有框就沒有東西告訴你哪幾個字不是你寫的。

**蓋掉的是什麼**，值得說清楚：Normal 之下這個牌子寫的是**你打的那個數**，而它釘在光
標下面，蓋掉的正是 `3`、`2t`、`d3l` 要數的那幾個字——命令的賓語。這也正是 `basic` 存
在的理由：那一檔在最壞情況下和 `off` 一樣什麼都不損失，**醒目是用樣式買的，不是用藏字
買的**。不過**出廠是 `full`**（2026-09-08 定）：牌子先得一眼看得見，而被蓋住的那幾個
字，光標挪一下就露出來。嫌它蓋字，`:view-hud basic`。

`full` 會避開別的面板（`空格` 選單、`:` 選單、挑選器、表格側欄），但候選框比它大：兩
個都想要光標下面那一格的時候，候選框贏。

`:view-hud` **不歸 `:render` 管**。`:render` 寫的是「這份**檔案**怎麼畫」那四項；這一項是
「編輯器怎麼跟你說話」。把標記藏起來的人，並沒有說過他不想看見 `d` 前面那個數。

### 這是哪個字

狀態欄右端說出光標下那個字**是什麼**：

```
-- NORMAL --  ch01.md   Ln 12, Col 8              螭 U+87ED · CJK Unified Ideographs
```

一個生僻字在終端裏顯示成方框的時候，這一行回答的是「字錯了還是字體缺了」——區塊名
告訴你它在哪個平面，多數字體不帶擴展 B 以上。校稿時查一個字是不是你以為的那個字，
也是同一件事。

區塊表是 Unicode 自己的 `Blocks.txt`（17.0.0，346 個區塊）整份抄進來的，二分查找，
沒有依賴、不聯網。

擠不下的時候**先讓區塊名，再讓碼位**，左邊的位置讀數永遠不動——狀態欄最要緊的是
「我在哪」。不想要就 `[editor] char_info = false`。

### 註在句子旁邊

`[^1]` 是一個很小的記號，它指的那條註在檔案末尾一百行以外。所見即所得下更是如此。可是
腳註存在的意義**就是**要在句子旁邊被讀到——跑到檔尾去讀它，順序正好是反的。

所以光標停在 `[^1]` 上時，**下方會出現一條面板**，寫着那條註本身，以及它寫在第幾行：

```
那年冬天[^1]，山下起了大雪。

[^1] 據縣志，那是丁丑年。                                        第 24 行
```

`gd` 過去，`gd` 回來——**一個鍵，兩個方向**，因為從註那裏你只可能想回到剛才那個
句子。回來落在你離開時的那一個字上，不是那一行的行首。中途跑到別處去了，回程就作廢，
不會把你送到一個你已經不記得的位置。

批注 `%%…%%` 用同一條面板：它本來就在畫面上，面板給的是**讀一條長批注而不讓它把段落
撐開**的地方。

面板是同一個機制的三個用途（表格詳情、腳註、批注），`t i` 開關。表格的面板在右邊，
因為一行有二十八個欄位、那是個高的東西；正文的在下邊，因為一條註是一小段話，為它切掉
三十欄的寫作寬度是付錯了價錢。

### 表格模式

一個 CSV 是文字檔，yumete 編輯文字檔；它不是**格子**。二十八欄的拆分表讀起來是一整行
流水賬，欄對不齊，想到「這一行的第四個欄位」只能用眼睛數逗號。表格模式就是那個格子：
同一份文字的另一種視圖，移動的單位從字變成格。

```
yumete -t 表.csv          # 或者在裏面 :table
```

#### 四種看法

同一份文字，四種看法，`t` 那一組鍵切換。整頁的表格視圖不是另一種東西，它只是**把整個
窗口交給了一張表**——那張表是一份 `.csv`，還是一章裏的三行，沒有分別：

| | 原文 | 按鍵 | 折行 | 進 |
| --- | --- | --- | --- | --- |
| **源碼模式** | 看得見，`\|` 就是一個字符 | 正文那一套 | 照舊 | `t o` |
| **表格操作** | 看得見（逗號、跳格、`\|` 都在） | 格子那一套 | 表格那幾行**不折** | `t b` |
| **畫成表格** | 看不見，畫成格線，**四周的正文還在** | 格子那一套 | 不適用 | `t f` |
| **全窗表格** | 看不見，畫成格線，**整個窗口只有這張表** | 格子那一套 | 不適用 | `t t` |

#### 四種看法，逐項對照

上面那張表說的是「是什麼」，這張說的是「會做什麼」。每一格都是**量出來的**，不是從註釋
裏抄的——這份代碼裏已經有過三處註釋比代碼老。

| | **源碼 `t o`** | **表格操作 `t b`** | **畫成表格 `t f`** | **全窗表格 `t t`** |
| --- | --- | --- | --- | --- |
| 內部的層級 | `Off` | `Basic` | `Full` | `Basic` ＋ 佔住窗口 |
| **欄對齊**（補白） | 不排 | 畫出來的空格排齊 | 同左 | 窗格自己排 |
| 量欄寬看哪些行 | — | **只量屏幕上的** | 同左 | 只量屏幕上的 |
| 欄寬會不會隨滾動變 | — | 會 | 會 | 會 |
| **分隔符** | 原樣，就是一個字符 | 原樣，佔一格 | 畫成 `┆`；規則行畫成 `├┄┼┄┤` | 窗格自己畫格線 |
| 欄號尺（貼在表頭上） | 沒有 | **有** | 有 | 有 |
| 表頭滾出屏幕後，頂上的欄號＋欄名 | 沒有 | **有** | 有 | 窗格自帶凍結表頭 |
| 凍結行號 | — | 沒有 | 沒有 | **有** |
| **長單元格默認折疊** | 不折 | **不折** | **折**，上限 32 格 | **折**，上限 32 格 |
| `t w` 折／展 | 拒絕（提示按 `t b`），但記下答案 | 開／關 | 開／關 | 開／關 |
| 折疊記號 | — | `>`（折了纔有） | `>` | `>` |
| Normal 下光標移進折疊格 | — | — | **不展開** | **不展開** |
| Insert 下（按 `i`） | — | — | **展開光標那一格** | 展開光標那一格 |
| 折疊的格子怎麼讀 | — | — | `i`、`t w` | 右邊的面板（整格，折着行）、`i`、`t w` |
| `t a` 單元格內換行 | — | 拒絕：要整窗 | 拒絕：要整窗 | **可以** |
| **表格行 soft wrap** | 照常折 | **不折**（一行就是一行） | 不折 | 不適用 |
| 文件自己帶的補白空格 | 在頁面上 | 在頁面上 | 折疊時**從頁面上撤掉** | — |

| `hjkl` | 走字 | 走字 | 走字 | 走字 |
| `T` 切粒度 | — | 走格／走字 | 同左 | 同左 |
| `Tab` | 正文那一套 | 下一格 | 下一格 | 下一格 |
| 右邊的詳情面板（整行竪列） | 沒有 | **不開**，按 `t i` 纔開 | 開着 | 開着 |
| 四周的正文 | 在 | 在 | 在 | 不在 |

幾條容易誤會的：

- **`t t` 不是第四個層級**，它是「把窗口交給這張表」。層級還是 `Basic`——所以 `t q` 交回
  窗口之後，你回到的是剛纔那一種。
- **`t b` 的原則是只能多字、不能少字**：補白、欄號尺、頂欄都是**加**在頁面上的標註，所以
  它們在 `t b` 裏都有；折疊是**藏**字，所以要按 `t w` 開口。`t f` 還會**替換**（`|` 畫成
  `┆`），那是 `t f` 獨有的第三件事。
- **光標不會因為站上去就展開一個折疊的格子**——`i` 纔會。全窗表格裏本來會（量那一格用
  的是窗口而不是上限），作者 2026-09-11 把它收回來了：「列宽容易跳……建议这个和 tf 保持
  一致」。每按一次 `l` 就給那一欄一個新寬度，於是一個只說「下一格」的鍵把整張表往旁邊
  推。在 Normal 裏讀一個折疊的格子有三條路，而且都不動版面：**右邊的面板**本來就整格
  攤開着，`i` 就地展開，`t w` 一次全開。
- **詳情面板開在「有東西是頁面上看不到的」地方**：`t f` 和 `t t` 會把長單元格折起來，
  那時面板是讀全內容的路；`t b` 什麼都不藏，面板等於把頁面已經在說的再說一遍，還要佔掉
  五分之一的寬度。`t i` 一旦表過態就永遠聽你的，換層級也不會悄悄改回去——和 `t w` 一樣
  的規矩。

- **四種標點沒有分別**：markdown 的 `|`、csv 的 `,`、tsv 的 Tab、Excel 的 `;`，在 `t b`
  和 `t f` 下走的是同一條代碼，顯示效果一樣（#378）。

四種之間直接切，不用先退出去：在全窗表格裏按 `t b` 是回到表格操作，不是回正文。
**`t o` 是回正文的路**，四種裏哪一種都認。

**`t q` 只管全窗表格**：它把窗口交回去，並且回到剛纔那一種——`t f` `t t` `t q` 之後你
還在 `t f`。一份自己就是一張表的 `.csv`，它本來就沒有「剛纔那一種」，那裏 `t q` 就是
`t o`。

**表格操作**是給「我想看見我打的是什麼，但想按格子走」的時候用的——改一份 Markdown
表格、對一份 CSV 的原文，逗號和 `|` 一個都不藏，而 `Tab`、`t r`、`t1s`、`gd` 全是格子
的意思。那幾行**不再折行**：一行就是一行，數得清第幾欄。

**畫成表格**與**全窗表格**的差別只有一條：欄寬是誰算的。畫在正文裏的那一種，欄寬是**整
張表**算出來的一份，所以捲動的時候格線不動；全窗那一種，欄寬是**看得見的那幾行**算出來
的，所以它捲到哪裏就照哪幾行收緊——一份十二萬行的拆分表因此只花一頁的力氣。

**`t b` 與 `t f` 裏，光標上下走得出表格**：在最後一行按 `j` 就走進表格下面那一段話，在
標題行按 `k` 就走進上面那一段。走出去 `hjkl` 就又是字母了，走回來又是格子。`J`／`K`
（翻頁）不走出去——一頁數的是**表格的**行，數完就停。

**全窗表格裏，標題行是畫出來的，不是站得上去的**：它凍在最上面一行，`t t` 從標題行按下
去落在**第一條資料**上，在第一條上按 `k` 就停住——不然光標在標題行、游標畫在第一條，
打一個字進的是欄名。`t b`／`t f` 裏標題行還在頁面上原處，改欄名就是改欄名。

**全窗表格是一扇窗，開在一張表上，走不出去。** `G`、`gg`、`g30g`、`:120`、搜索——這些
本來是整份檔案的跳法，在窗裏一律**夾在表內**，並且說一句「全窗表格只走這張表」：`gg`
是這張表的第一條，`G` 是最後一條，滾輪滾到頭就停。出去的路只有三條：`t q` 把窗口交回
去（回到剛纔那一種），`t o`／`t b`／`t f` 換一種看法，`t ]`／`t [` 去下一張表。

從前它是漏的：`G` 一按光標就跳進底下那一章，窗裏沒有表可畫，於是窗口自己悄悄交回給正
文——**全窗表格會在沒有人要求的時候結束**。堵住這個口子，一整類邊角情況就沒有了，也纔
換得到下面這一條。

**窗裏的行號是這張表自己的行號**（第 1 條、第 2 條…），不是檔案的行號。狀態欄的「第 N
行」跟着它，`t1g`、`t20,20g` 數的也是它——**窗裏每一個數字都指同一件事**。走出窗子（`t
b`／`t f`／`t o`）行號就又是檔案的了，那時 `t20g` 也就又是檔案的第 20 行（夾在表內）。

**`t ]`／`t [` 走到別的表格，欄數不一樣也認得**：欄名、欄號、寬窄都照**那一張**表畫，
狀態欄報的也是那一張表的欄名。

**哪些行會跟着變**，看檔案自己說了什麼：

- **整份檔案就是一張表**——`.csv` `.tsv` `.md`，旁邊有一份 schema，**或者它從第一行
  到最後一行都對得齊**（副檔名是 `.txt` 也算，看的是內容不是名字）——那麼 `t b`／
  `t t` 是**整個檔案**的狀態。在兩張表中間的段落上按也算數，檔案裏每一張表一起變；
  光標走出表格，表格照樣是表格。
- **只有中間一段是表**——貼進稿子裏的一段跳格分欄、一段坐在 `## 第三章` 底下的碼表、
  `dict.yaml` 裏 `---` 之後那些條目——那麼它管的只有**光標底下這一段**，走出去就回
  正文，想再看要再按一次。

`|` 表格自己每一行都寫明了它是什麼，所以它走第一條，哪怕它坐在一份 `.txt` 裏。猜出來
的那一段纔走第二條——猜的東西不該在讀者走開之後還留在畫面上。

Markdown 裏**只有能被正確 parse 的表格**纔會變：缺了 `|---|` 那一行的、圍欄裏引用的，
都當正文。

**欄與欄之間怎麼分開**，是這張表的事，不是編輯器的事：二十八欄一個字寬的拆分表讀起來
是格子，要一條線才分得清；六欄很寬的表讀起來是頁面，欄欄之間都畫一條反而是字與字之間
的噪音。默認是**虛線**——畫得出邊界，又不會自己變成一欄：

```
:table-rules line dash      虛線 ┆（默認）
:table-rules line           一條實線 │
:table-rules line double    雙線 ║
:table-rules color          每欄一條淡底，紙從縫裏透出來
:table-rules off            什麼都不畫，靠對齊分
:table-rules                說現在是哪一種
[editor] table_rules = "off"
```

**放一份 schema 在資料旁邊，它就自動是表格。** `.yumete/tables/*.toml`，從**檔案所在
目錄**往上找（不是工作目錄——schema 是資料的屬性，不是這次會話的）：

```toml
[table]
file = ["yuhao_division_golden_source.csv", "yuhao_division_pending.csv"]
key = "char"                  # 哪一欄是這一行的名字
delimiter = ","
quoting = "none"              # 目前只支持這一種，見下

[[table.column]]
name = "char"
label = "字"                   # 表頭顯示的名字，不寫就用 name

[[table.column]]
name = "d1"
hidden = true                 # 這一欄照樣讀、照樣寫，只是不畫、光標也不停

[[table.detail]]              # 只在詳情欄出現，不進格子、不寫回檔案
name = "block"
compute = "block(char)"       # codepoint(欄) / block(欄) / range_label(欄, 區間表)

[table.link]                  # 「這一格指着本表的另一行」——正反兩個方向都靠它
from = ["ids_y", "ids_g"]     # 這些欄的內容是別的行的名字
to = "char"                   # 名字寫在這一欄

[ranges.cjk_blocks]           # 你自己的叫法，不是 Unicode 的
"CJK-D" = [0x2B740, 0x2B81F]
```

沒有 schema 也能用：`-t` 會拿**檔案自己的首行**當表頭，欄名有了就能對齊、能按格走。
分隔符也是猜的，規矩和 `:table-pipe` 那條一模一樣：跳格、逗號、分號裏哪一個每行都出
現同樣多次就是哪一個，猜不出來纔當逗號。所以 `:export tsv` 寫出去的檔案，`-t` 讀得
回來——從前這裏寫死了逗號，跳格分欄的檔案一律說「不是表格」。

**碼表沒有表頭。** 「字⇥碼」一路到底，首行當表頭就少了一行、還把一欄叫成「一」。
`t H`（或 `:table-header off`）說明這件事：第一行變回普通的一行，欄名改用編號——就是
欄號那一行畫的那些數字（`3gd`、`t20,20g` 數的也是它）。再按一次換回來。**寫了 schema
的不受影響**：欄名是人取的，不會因為一個鍵就沒了，變的只是資料從第幾行開始。這一鍵
只對「整個檔案是一張表」的那種有意義——`|` 表格的表頭是檔案自己說的（底下那行
`---`），文中認出來的那一段（見下）本來就沒有表頭。

**`t e` 把這張表的規格開在另一半。** 整份檔案是一張表的時候，`t e`（或
`:table-schema`）就把說明它的那份 `.toml` 開在另一個工作區——鍵還在表格這一半，
`空格 w` 過去改。**沒有 schema 的話，先寫一份出來**，放在資料旁邊的
`.yumete/tables/` 裏，名字跟着資料檔。

寫出來的那份說的**就是眼下看到的樣子**：分隔符是它猜到的那個，`t H` 說過的「第一行
是資料」也在裏面，欄名照首行。所以開了它、讀回去，一格都不會變——接下來你改的每一
項，改的都是眼前看得見的東西，而不是對着一張白紙猜格式。改完存檔，`:table off` 再
`:table`（或 `t o` `t t`）就照新的讀。

已經有那個檔名的不會被蓋掉：那是別人的東西，把它打開看看它說什麼纔是對的做法。文中
認出來的那一段（見下）和 `|` 表格沒有這一項——它們是**文件裏面**的表格，不是一份表格
檔案。

#### 文中的一段也可以是表格

**整個檔案不是表，裏面那幾行是。** 一張碼表貼進了章節，`dict.yaml` 的正文在 `---` 前
言底下，LaTeX 的 `tabular`——把光標放進那幾行裏，`:table`，它就是格子；`:table off`
出來，檔案一個字節都沒動過。

怎麼認的：

* **站在哪個分隔符上就是哪個。** 一行裏跳格和逗號都有，站在逗號上按 `:table`，就按逗
  號分。選中幾行也行，選區裏每行都一樣多的那個字符就是它。都沒說的話，按跳格、逗號、
  分號、`&` 的順序試（`&` 是為了 LaTeX 和 Typst）。
* **從光標那一行往上下走，走到不含那個分隔符的行為止。** 空行是一個界，`## 第三章` 也
  是一個界——它裏面沒有跳格。所以碼表緊貼在標題底下也認得出來。
* **進去之前先對一遍。** 兩三行的區塊要求每行欄數完全一樣；四行往上，三分之二的行一致
  就算數——`dict.yaml` 有些條目帶權重有些不帶，為了那幾行拒絕整張表是不對的。對不齊就
  是分隔符猜錯了，寧可不進去，也不要在別人的稿子上畫一張歪的格子。
* **欄數按最寬的那一行算。** 那個權重欄還在，走得進去。
* **首行是資料，不是表頭。** 碼表沒有表頭，欄名就是 1、2、3。

**它只讀不改寫。** 走格、`t g`、`t /` `t ?`、`t y` `t p` 照常用（`t p` 只寫到區塊的最
後一行為止，不會順着往下寫進正文）；會重排整行的那些——`t1s` `t1S` `t r` `t R` `t d`
`t D` `t c` `t C`——一律不做。碼表是別人的資料，它周圍是別人的文章。真要整理它，先
`:table-pipe` 或者 `:table-csv` 把它**變成**表格，那樣檔案自己每一行都寫明了它是什麼。

#### 鍵

|---|---|
| `h` `l` | 左右一格 |
| `j` `k` | 上下一行，停在同一欄 |
| `0` `$` | 這一行的第一格／最後一格 |
| `c` | **換掉這一格**——整格清空，直接打新的。網格裏最常用的那個 |
| `d` | **清空這一格**（分隔符留着）；有選區的時候還是刪選區 |
| `i` | 進格子，停在**第一個字之前**（`I` 一樣） |
| `a` | 進格子，停在**最後一個字之後**（`A` 一樣） |
| `t/` `t?` | **誰用了它**——一欄一欄地找。`/` 這邊找，`?` 另一個工作區看。`t1/` 只找第 1 欄，`t2-10?` 找第 2–10 欄 |
| `n` `N` | 走剛才找出來的那些行 |
| `gd` | **它自己那一行**：這一格（或選中的字）在 key 欄裏完全相同的那一格，跳過去 |
| `gD` | 同上，但在另一個工作區給你看，你不動 |
| `3gd` | 改成在第 3 欄裏找；`2-5gd` 是第 2 到第 5 欄 |

| `o` `O` | 新開一**行**——連分隔符一起，不是一條空行 |
| `t r` `t R` `t d` | 加一行（下／上）／刪這一行 |
| `t j` `t k` | 這一行下移／上移 |
| `t y` `t p` | 取整整一欄／把取到的那一欄貼在這一欄上 |
| `Tab`（格子裏） | 下一格；`S-Tab` 上一格。填一行不用碰分隔符 |
| `:table-jump 木` | 跳到表格裏叫「木」的那一行 |
| `t i` | 詳情欄開關 |
| `t H` | 第一行是欄名，還是跟別的行一樣是資料 |
| `t e` | 這張表的規格開在另一半，沒有就先寫一份 |

#### `gd` 去，`t/` 找：一格兩個方向

表格裏有兩個問題，長得像但不是一回事，所以是兩個鍵。

**`gd`：它自己那一行。** 這一格——或者你選中的那幾個字——在**某一欄**裏完全相同的那
一格在哪。站在 `⿰木目` 的木上按 `gd`，就到木自己那一行的 key 格裏；`gD` 是同一件事，
只是畫在另一個工作區，你不動。

搜哪一欄：schema 的 `[table] key`（拆分表就是 `char`），沒有 schema 就是第一欄。
臨時要別的欄就用數字前綴：**`3gd`** 是第 3 欄，**`2-5gd`** 是第 2 到第 5 欄——一張表
把同一個拆分寫了四種，這一鍵就把四種一起問了。

「這一格」是什麼，由 `Tab` 決定，跟 `hjkl` 走的單位是同一件事：**按字**就是光標下那一
個字，**按格**就是整格。所以 `⿰木目` 按格問是「有沒有哪一行叫 ⿰木目」——沒有，它就
這麼說，不猜你指的是三個裏的哪一個。

⿰⿱⿲ 這些**結構符不算部件**——它們說的是怎麼擺，不是擺了什麼，沒有哪張表會給它們一行。
詳情欄不列它們，`gd` 落在上面也只是說一句「這是結構符」。

**`t/` `t?`：誰用了它。** 問題正好反過來。站在 卵 上，你
想知道的是哪些字的拆分裏有卵，而那可能有四十處。這不是跳轉，是搜索——所以它就是搜索，
而且是**另一個方向的**搜索：

```
「卵」 第 2/17 行（n N 走）
```

`n` `N` 走這些處。它們就是「最後一次搜索」，所以 `n` 本來的意思沒有變；打一個新的 `/`
就把 `n` 收回去。

#### 搜索有兩個方向

一頁紙是**一行一行**讀的，`/` 就這麼找。表格多了一個文檔沒有的讀法：**一欄一欄**。問
「誰用了卵」，問的就是一欄一欄，答案也該按那個順序來。

```
:table-find row 卵         一行一行地找 —— 就是 `/`
:table-find column 卵      一欄一欄地找 —— 表格裏 t/ t? 就是它
:table-find 卵             不寫方向就是 row
```

**除了方向，兩者一模一樣**：模式是正則、命中的那一段就是選區、`n` `N` 走、到底了繞
回開頭。不搞特例——`林` 的拆分是 `⿰木木`，那裏面有**兩個**木，就是兩處，和 `/` 在一行
裏數出兩處是同一回事。

**搜哪幾欄**：schema 的 `[table.link] from` 列了哪幾欄就搜哪幾欄，按它列的順序——這正
是 schema 的用處，二十八欄的表只搜兩欄。沒列就搜全表，並且說一句：

```
本表格文件未指定快速跳轉之範圍，從第一欄起搜索——第 1/17 處
```

**光標先落在第一欄的第一處**，不管你剛才站在第幾欄。同一個字每次 `t/` 得到的是同一
條路線——「把所有用到它的地方過一遍」就是這個意思。

按字的時候找的是光標下那**一個字**，按格的時候找的是**整格**。

#### `Tab`：按格走，還是按字走

預設按**格**走——那是網格存在的意義。可是拆分是個**序列**：`⿰木目` 是三個部件，想看
中間那個是什麼、或者想跳到它自己那一行，單位就得是**字**。`Tab` 說了算，狀態欄右邊寫
着現在是哪一種：

```
-- NORMAL --  拆分表.csv   第 50000 行 · ids_g · 格
```

按字的時候，`hjkl`、操作符、選區全都恢復成平常的意思——這時它就是一個畫成網格的普通
檔案。只有 `gd` 還認格子：**光標停在哪個部件上，就查哪個**——按格的時候問的是整格，
沒有哪一行叫 `⿰木目`，它就這麼說。

**格子裏怎麼移動光標**：進去之後（`i`／`a`／`c`）用**左右方向鍵**按字移動，`Home`／`End`
是這一格的兩頭。走到格子邊上就**停住**，不會邁進隔壁那一格——這就是「Insert 關在一格
之內」的意思。上下方向鍵會被擋（那會把半個值留在這一格、半個留在下一行），先 `Esc` 再
`j`／`k` 換行。

改一整格用 `c` 比 `i` 快得多：落在格子上、`c`、打新值、`Esc`。`u` 一次就全撤銷。

`HJKL` 還是翻頁，`gg`／`G`／搜索／操作符都不變——那些是關於行和文字的，格子沒改變它們的意思。

##### `:table-check`——把整張表看一遍

四個問題，123,380 行時用眼睛答不了：

```
:table-check
```

- **哪一行的名字重了**（同一個字有兩行）
- **哪個部件查無此行**（拆分裏寫了它，表裏沒有它）——⿰⿱⿲ 不算，那是結構符
- **哪一行欄數不對**
- 排好序的一個結果緩衝區，`gf` 跳到那一行，和 `:grep` 一模一樣的形狀

沒查出問題就只說一句，不開緩衝區。

**在稿子裏查的是你站着的那一張表**，不是整份檔案——一份 markdown 文件裏有幾張表就是
幾張，中間那些段落不是誰的行。分隔行（`|---|`）既不查也不算進行數。

#### 三件不會讓你出錯的事

**逗號進不了格子——從任何一條路都進不去。** 這張表沒有任何引號，一格就是兩個逗號之間
的東西，這條規則讓 8 MB 的手改表能逐字節原樣存回去。代價是**沒有一格可以含有分隔符**。

這條守衛不在「打字」那裏，在**所有文字進出緩衝區的那兩個函數**上。第一版只守住了打字，
一次審查找出另外七條路都能繞過去——⌘V 貼上、`空格 p`、輸入法上屏、`:s`、`r`、`R`、以及
在空格子上按 `d`（空格子的位置正好就是那個逗號，於是兩格併成一格；而這張表大多數欄在
大多數行上是空的，那是最容易誤傷的一條）。現在它們走同一道閘門，說同一句話。

不變式是：**表格模式下，一行的分隔符數量永遠不變。** `:s` 也照這條檢查——只改格子**裏面**
的替換照跑（`:%s/⿰木/⿰禾/g` 沒問題），會改變格數或行數的直接拒絕並告訴你是第幾行。

**schema 有錯會說出來。** 打錯一個字的 schema 曾經是被默默丟掉的——二十八個標籤、兩個
算出來的欄位、整個跳轉全部消失，唯一的線索是狀態欄寫「照首行」而不是「照 division.toml」。
現在它直接告訴你哪個檔案第幾行錯在哪。

**欄數不對的行標出來，但照樣能編輯。** 表格模式正是拿來修這種行的工具，一行壞掉就打不開
它，等於工具在最需要的時候缺席。多出來的欄位照畫——藏起來就是把問題藏起來。

**竪排和 CSV 網格互斥。** 格子是橫着讀的，`:layout vertical` 會被拒絕（而不是畫出一個說不通的
東西），`-t` 也蓋過 `-v`。文檔裏的 `|` 表格不受這條管——它是頁面的一部分，頁面是什麼排版
它就是什麼排版。

#### Markdown 的 `|` 表格

同一套格子，指向文檔裏的**一段**而不是整個檔案。光標放在任何一行 `|` 上，`:table`：

```
| 字 | 讀音 |
| -- | ---- |
| 木 | mu   |
```

**`t F` 會把表格排齊，排進檔案裏。** Markdown 表格本來就該在自己的原文裏對齊（所以大家
都在手動敲空格），所以「對齊」就是編輯，而排好的結果在 GitHub、在別的編輯器、在任何地方
都是對的。

**而頁面上的每一張表，不用你動手就是齊的。** 不只是光標所在的那一張，也不用進表格模式：
補出來的空格是畫上去的，檔案裏一個字節都沒多。這件事非在頁面上做不可——所見即所得把
`` ` `` 和 `**` 藏起來之後，每一行少掉的格數都不一樣，**同一份原文不可能在兩邊同時是齊
的**。所以原文歸 `t f`，頁面歸它自己，兩件事各做各的，互不礙着。

量的是兩根 `|` 之間**整格的寬度**，你自己敲的空格照舊算數；每一行都對欄寬有一票，
`|---|` 那一行也算——畫上去的只能加，不能減，所以檔案裏已經排好的表，畫出來原樣不動。
`:render off` 之下不補（那時候頁面就是檔案），直排之下也不補。

**齊了，鍵也就跟着是表格的鍵。** 補齊只是「基本」這一級的一半，另一半是鍵：光標一站到
表格行上，`hjkl` 走的就是格子，狀態欄報的是第幾行第幾欄，那幾行也不跟着正文折行——**都
不用按 `t b`**。`t o` 把兩半一起關掉。直排之下兩半都不來（直排不補齊），那裏要不要進表格
是你自己的決定，按 `t b`。


**按終端寬度量，不是按字符數。** 這是這個功能存在的理由：所有編輯器的表格格式化都是數
字符，於是一欄漢字排出來是歪的，漢字混拉丁排出來歪得更厲害。這裏一欄有多寬，量的是它
在終端上佔幾格。

沒有 `|---|` 分隔行也能進——你正在寫的那個表格就沒有——它會替你補一行。

##### 貼進來的東西作成表格，表格拆回去

從別處抄來的一段，逗號、分號或者跳格分欄的，**選中它，`:table-pipe`**：首行當表頭，
分隔行替你補上，欄寬按終端量齊，然後直接進表格模式。沒有選區就取游標所在的**一段**
——空行是界，上下各走到空行為止，所以稿子裏一段一段的東西不會被連累。

分隔符**看不出來就問你**，不猜。判斷的只有一件事：跳格、逗號、分號這三個裏，哪一個
**每行都出現同樣多次**。一份 CSV 每行的逗號一樣多；一段中文散文斷句用的是 `，、。`，
三個猜測一個都不沾，於是原樣不動，狀態欄叫你寫明：

```
:table-pipe          自己看：跳格、逗號、分號，哪個每行一樣多就是哪個
:table-pipe ,        寫明用逗號
:table-pipe tab      跳格（`Tab` 在命令行是補全，所以拼出來）
:table-pipe 、       任何一個字符都行——你比誰都清楚自己的資料
```

打不出來或者打出來看不見的，都有名字可寫：`tab`／`\t` 是跳格，`space`／`\s` 是空格，
另外 `comma`、`semicolon` 也認，引號裹一個空格（`" "`、`' '`）也認。

**一個空格它永遠不會自己猜**，多整齊也不算：一個空格是把句子連起來的那個字符，猜它，
一段散文就成了格子。**寫明 `:table-pipe space` 是可以的**——那是你說的，不是它猜的。

不過這條規矩問的是「每行齊不齊」，**不是「這是不是散文」**：兩行英文剛好各帶一個半角
逗號（`Yes, it works.` 配 `No, it doesn't.`），它照樣當成兩行兩欄。`u` 撤得回來。行數
越多越不會撞上，兩行是它敢下判斷的下限。

反過來，`:table-csv`（或者 `:table-csv tab`、`:table-csv ;`）把游標所在的 `|` 表格拆
回分隔文本，`\|` 還原成 `|`、`\\` 還原成 `\`，襯的空格去掉。落在**已經是** `|` 表格
的段落上的 `:table-pipe` 會拒絕：那一段本來就是表格，沒有可作的。

**某一格裏本來就有那個分隔符，它會停下來告訴你是哪一格，不會替你加引號。** 這和表格模
式裏不讓你把分隔符打進格子是同一條規矩：一份「有的格加了引號、有的沒加」的檔案，在這個
程序裏讀着是對的，換一個程序讀，出問題那一格右邊的每一欄都錯位。換個分隔符，或者先改
那一格——你知道那份資料該怎麼辦。

**不想動稿子就用 `:export csv`**（`:export tsv` 同理）：游標所在的那張表另存一份，檔名
跟着稿子走，稿子本身一個字節不動。整檔就是一張表的（`.csv` 開着表格模式）也認，於是
「讀 `.csv` 寫 `.tsv`」就是同一件事。

##### 鍵

走格、`c`、`i`／`a`、`y`／`Y`／`p` 都和 CSV 那邊一模一樣。多出來的是**結構**：`t`（表），
後面跟一個鍵，提示欄會列出來。方向就是意思，`jk` 是行、`hl` 是欄，不用記哪個是哪個。

| | |
|---|---|
| `t r` `t R` | 加一行（下／上） |
| `t c` `t C` | 加一欄（右／左） |
| `t d` `t D` | 刪掉這一行／這一欄 |
| `t j` `t k` | 這一行下移／上移（光標跟着走） |
| `t h` `t l` | 這一欄左移／右移 |
| `t1s` `t1S` | 照第一欄順排／倒排（`t0s` 是你站的這一欄，`t1a2d8as`、`t1,5,9s` 一次排幾欄） |
| `t y` `t p` | 取整整一欄／把取到的那一欄貼在這一欄上 |
| `t <` `t =` `t >` | 這一欄靠左／居中／靠右 |
| `t F` | 重新排齊，排進檔案裏 |
| `t o` `t b` `t f` `t t` | 源碼／表格操作／畫成表格／全窗表格（見下） |
| `t w` | 太寬的格子摺起來／攤回去（源碼以外都算數） |
| `t a` | 太寬的格子折行——尾巴畫在它自己那一欄的下面幾行（只在全窗表格） |
| `t i` | 這一行攤成側欄，一欄一行地讀 |
| `t q` | 全窗表格交回窗口，回到剛纔那一種 |
| `t ]` `t [` | 下一張表／上一張表 |

`o`／`O` 直接就是加一行，不用走 `t`。標題行刪不掉——它是欄名。

`t p` 貼進來的格子**帶了分隔符就整批拒絕**，不會替你把它濾掉：`長, 久` 貼進一份 CSV
裏原本會靜靜變成 `長 久`。狀態欄報的是它本來要落在的那一行那一欄，一個字都還沒動，
不用撤銷。貼進 `|` 表格則是照 Markdown 的規矩轉義（`|` 寫成 `\|`，反斜槓跟着加倍），
所以格子裏原本有什麼，讀回來還是什麼。

`t1s` 排序：**數字當數字比**（19、200、1900，不是 1900、19、2），其餘按碼位。漢字按
碼位不是任何人想要的排法，但那是這個編輯器目前能誠實給出的唯一一種——按拼音排要等
語言模型接進來。

**排幾欄**：`t1a2d8as`——第一欄順排、第二欄倒排、第八欄順排，最後那個 `s` 纔動手。
`a`／`d` 只記下一欄，不排；動作永遠是 `s`（或 `S`，最後一欄倒排），所以打到一半的
`t1a2d` 不會自己排起來，`Esc` 一按就全丟了。狀態欄按打過的樣子回顯：`t1a2d`。
**排序一定要說是哪一欄。** 光按 `t s` 什麼都不會發生——十二萬行的表排一次是真的要等，
而 `u` 退得回內容退不回時間，所以起手不是一個字母。站着的那一欄是 `t0s`／`t0S`：
`0` 不是欄號，正因為如此它空着可以用來說「這一欄」。

**`-` 是範圍，`,` 是點名或成對。** `t2-10/` 是第二到第十欄（一種東西的一段），
`t1,5,9s` 是第一、第五、第九欄（同一種東西的好幾個），`t20,20g` 是第 20 行第 20 欄
（兩種東西）。一個鍵原本兩件事都做，寫下 `t20,20g` 那天就撞上了。

**行號是行號槽裏那個數。** 正文裏那是檔案的行號，全窗表格裏那是這張表自己的行號（見
下）。兩邊都**夾在表內**：`t1g` 落在這張表的第一條，不是整份稿子的第一行——表格的鍵不
該把光標帶到三屏以外的段落裏去。

`|---|` 那一行是**畫出來的**，不是寫出來的：光標落在上面（`gg`、`G`、`:N`、搜索都會落
上去）時 `c`／`i`／`a` 會被擋掉，`t` 系列則當作是站在標題行上。要改對齊用 `t < = >`。

**注意 `t` 蓋掉了 vi 的 `t`（跳到下一個某字之前）**——只在表格裏，只在按格移動的時候。
出了表格 `t` 還是原來那個 `t`。

一欄最寬排到 **32 格**。比這還長的格子照樣完整寫出來（什麼都不會被截斷），只是別的行
不再陪着它一起變寬——否則人物表裏一句備註就能把整張表撐到兩百格。

**`t w` 把超出的尾巴摺起來**，摺到哪裏就在那裏立一個 `>`。那個 `>` 是**金色加粗**的
——整頁的字都是灰的，這一個不是，所以它不會被讀成你自己打的那個大於號。（記號本身只能
是這個半形符號：Unicode 那幾個省略號在東亞環境下寬度不定，一格量成兩格，它後面每一欄
就都錯位了。）再按一次 `t w` 全部攤回去。檔案一個字都沒動：`t F` 排齊寫進檔案的時候
讀的是原文，不是頁面。

**走過去不會攤開，要改字纔會。** 光標停在一個摺起來的格子上，它照舊摺着——**要讀全文
就開 `t i` 的詳情欄**（那裏一個字都不會少，而且會折行）。一按 `i`／`a`／`c` 進那一格，
它整格攤開，因為光標不能停在頁面上沒畫出來的字裏；`Esc` 一回 Normal 又摺回去。

這條規矩是拿卡頓換來的，換得很值：**攤開與否只跟「有沒有在改字」有關，跟光標在哪裏無
關**，於是整張表的排版一份算好就一直用着，走一步不用重排。從前是「走進哪一格哪一格就
攤開」，那等於每按一次 `j` 都要把整張表重新量一遍——一張 286 行的表，在兩個字
寬的 `#` 欄裏上下走，每一步 15 毫秒。

**攤開的那一格不會把整欄撐寬**：它從自己那道牆往右頂出去，同一行後面的欄跟着右移，
**別的行一格都不動**。頂出去的地方牆還是畫的，兩邊也還留着空格，所以看得出邊界在哪裏。

**「基本」自己不摺，你叫它摺它就摺。** 那一級不准**自作主張**藏東西，所以出廠是全文；
按下 `t w` 就是你自己說了要摺，它照做，級別不動。真正沒得摺的只有**源碼**——那一級照
原樣畫，沒有一欄是排齊的，也就沒有東西可以拿來量，`t w` 在那裏會直說要 `t b` 或 `t f`。
你按過的那一次算數：在「基本」裏攤開了，走到「畫成表格」還是攤開的。

**全窗表格裏 `t w` 也算數**，只是摺的辦法不一樣：正文裏摺的是**字**（尾巴下頁去），
全窗裏摺的是**欄寬**（那一欄畫到 32 格為止）。斷口一樣立 `>`，光標所在的那一格一樣整
格畫出來——量它的時候拿的是窗口寬而不是上限，所以走進去就讀得到全文，`i` 進去改字也
走得到尾巴上。攤回去之後每一欄都畫到它自己那麼寬，最寬不過一個窗口——比窗口還寬的
那一欄再寬也沒有用，格子是一欄一欄橫向捲的，捲不進去的部分誰也走不到。

##### `t a`：折行——尾巴畫在下面，不是收起來

**全窗表格裏還有第三個答案**：`t a` 把每一個過寬的格子**折到它自己那一欄的下面幾行**，
一個字都不藏，也不用左右捲。一行有多高，看它最高的那一格要幾行；行號只畫在起頭那一
行，下面幾行是同一行的續行，所以數得清第幾條。

`t w` 和 `t a` 是同一件事的兩個開關，**永遠不會同時亮**。`t a` 走進折行：摺起的時候按
它就換成折行，攤平的時候按它就折起來，折着的時候按它攤平。`t w` 只認「摺不摺」：攤平
的時候按它就摺起，摺着的時候按它攤平，**折着的時候按它也是攤平**——一個字都不藏，要摺
起再按一次 `t w`。

**為什麼只有全窗有。** 正文那一頁的行是編輯器共用的折行層算出來的（所有移動鍵、滑鼠、
縱書、分屏都讀它），而它沒有「懸垂縮進」——續行只能從最左邊開始，同一行剩下的欄會跟在
折出來的文字後面，那不是任何人講的折行。全窗那一張格子是表格自己畫的，所以它做得到。
在正文裏按 `t a`，它會說要先 `t t`，**設定照樣記下**，按 `t t` 進去就是折行的。

##### `Tab`：填表的時候

進了格子（`i`／`a`／`c`）之後 **`Tab` 跳下一格，`S-Tab` 跳上一格**，一路排齊。這是所有
表格工具的那個鍵，也是表格能填得快的原因：**你從頭到尾不用碰 `|`**。走到最後一行的最後
一格再按 `Tab`，它給你開新的一行——你顯然還沒填完。

##### 這個模式只在表格上生效

進了之後不用關。走出表格、進到下面那段話裏，`hjkl` 就是字母、`|` 就是一個普通字符；走
回表格裏，格子又回來了。**一個只在它所關心的東西上生效的模式，不需要被關掉**——這也是
為什麼它不會像 CSV 那樣把整頁翻成橫排：`|` 表格是文檔的一部分，為了改三行而把整頁翻過來，
是把周圍的東西全扔了。

排版隨時是對的，因為每次編輯之後它都重排一遍；重排是冪等的，所以排一百次和排一次一樣。
`u` 一次撤銷「編輯 + 重排」——你加了一欄再後悔，要回到的是**加之前那張表**。

**從表格軟件直接貼進來。** Excel、Numbers、LibreOffice、瀏覽器裏的表格——它們往剪貼板
上放的都是**製表符分隔**的行。在格子上按 `p`（或者 `空格 p` 從系統剪貼板，或者直接
⌘V／Ctrl+V 讓終端把它送進來），它從**光標所在的那一格**開始往右往下填，不夠的行和欄自己
長出來：

```
木→mu          在「字」那一欄上按 p
目→mu          三行兩欄就進去了
禾→he
```

裏面本來有 `|` 的格子會寫成 `\|`，不會把一行切成兩行。CSV 那邊欄是 schema 定的，貼不下
就直說，不會偷偷把每一行往右擠。逗號分隔的也認，但**要求每一行的逗號一樣多**——一段
帶兩個逗號的話是一段話，不是表格。

沒有製表符也沒有換行的，還是照舊當一格的文字貼。

**光禿禿的 `|` 打不進格子**（和 CSV 的逗號同一道閘門），格子裏真要寫它，寫成 `\|`——
那是 Markdown 表格唯一的轉義，這裏認它：`a\|b` 是一格。

代碼塊裏的 `|` 表格**不是**表格，是引文：`:table` 會拒絕，不會去重排別人貼進來的例子
（這份手冊裏就有好幾個）。只有一欄的行也不算表格。

#### 詳情欄

右側——**在 markdown 稿子裏也是右側**。一行表格有二十八個欄位，那是個高東西，寫在
哪裏都是高東西；貼在底下的那條四行高的欄是留給**註**的（腳注、`%%批註%%`），一段短話
鋪底下纔對。

**部件列在最上面**——那是這個面板真正被用來看的東西；底下才是欄位。**每一欄都列，空
的也列**，前面帶欄號：空本身就是拆分表裏的一個發現，而「這一格是不是空的」正是你開這
個面板要問的。欄多了它會捲到光標所在的那一欄，`t20,20g` 也認那個號碼。算出來的欄位名
字後面帶 `*`，提醒你檔案裏沒有這一欄。

部件後面跟着行號；沒有自己那一行的部件標成紅色的 `—`，對拆分表來說那個「沒有」本身就
是發現。

**`t i` 開關**（從前是 `空格 d`）。它是表格的鍵，就該住在表格那一組裏；`空格 d` 現在
是字典。空格或 Tab 隔開的表格（碼表那一類）也列得出來——那種表沒有表頭，欄名就是欄號。

**放不下的欄位會折行，不會被切掉**。這個面板正是摺起來的那一格該去讀的地方，所以它自
己再切一次就等於什麼都沒答；折行走的是頁面那一套折行規矩（禁則照樣管），欄位名對齊在
左邊，續行縮在同一格起。面板窄了就多幾行：`:table-detail 40` 給它更寬一點。

### 沒有名字的緩衝區也有崩潰副本

`yumete` 不帶參數啟動、寫一個小時——這是開一場戲的正常方式，而它以前是**唯一沒有安全網
的緩衝區**：恢復副本放在檔案旁邊，而它沒有檔案。

現在它在資料目錄裏有一份（`drafts/scratch-<進程>-<第幾個>.yumete`），和有檔案的緩衝區
走同一套自動保存。**只有真的打了字之後才給名字**——從沒打過字的空緩衝區不該留下任何東西。

崩了之後下一次啟動會說：

```
有 1 份沒存的草稿——`:recover` 打開
```

`:recover` 把它們各開成一個緩衝區（叫「草稿 scratch-…」），同時**把檔案拿走**，免得下次
再問你一遍。`:recover!` 直接丟掉。這是唯一會去找它們的命令——那份工作沒有檔名，別的東西
永遠不會提起它。

### `u` 不會撤銷「什麼都沒發生」

撤銷點以前是在命令**宣稱**要編輯的時候記下的，不是在它真的動了字的時候。所以三個什麼都
沒刪掉的 `d`，就留下三個什麼都撤銷不了的 `u`；`i` 按完馬上 `Esc` 也是一個。`u` 於是變成
「有時候管用」——那是最快讓人不再信任一個編輯器的方式。

現在撤銷點是**掙來的**：宣稱的時候先記着（ropey 的複製共享結構，記着一個沒發生的編輯只
花一個指針），字**真的動了**才進撤銷棧。被守衛擋下的編輯同理——它沒動字，就不是一個值得
回去的地方。

### 剛才剪掉的那段去哪了

每一次 yank、每一次刪除都蓋掉同一個暫存器，所以「三次編輯之前剪掉的那一段」以前是沒有
答案的。現在它們留在一個**最近十六個**的環裏，`空格 "` 列出來：

```
系統剪貼簿
0   那年冬天，山下起了大雪。 …（4 行）
1   阿寧從門後探出頭來。
2   「你來得正好。」
"a  第三卷的開頭
```

第一行是**系統剪貼簿**——它不在這個列表裏（只有前端讀得到它），所以那一行是「去問一下」
而不是「已經拿着」。下面是不帶名字的暫存器的歷史（新的在上），再下面是 `"a`–`"z` 這些
帶名字的。

選一條就貼上。`yy` 兩次不會在列表裏留兩條——那是你**取了一次**的東西。

### 檔案在外面被改了

一個檔案在 yumete 裏開着，同時被外面改掉——git 切分支、同步資料夾、`:!sed -i`、或者
你在另一個編輯器裏也開了同一個檔案。以前 `:w` 會**一聲不響地蓋過去**，另一個版本就沒了。

現在讀進來和寫出去的時候都記下這個檔案的**大小和修改時間**；對不上就停下來：

```
這個檔案在外面被改過了——`:reload!` 讀它的，`:w!` 用你的
```

- `:reload` 重讀檔案。這裏乾淨就直接讀；有沒存的改動會被攔下來
- `:reload!` 重讀，**丟掉**這裏的改動
- `:w!` 用這裏的蓋掉外面的

**`:reload-auto on` 讓它自己讀。** 打開之後，每兩秒問一次磁盤（便宜的那一問是一個
`stat`）：檔案在外面變了、而你這裏**乾淨**，就直接讀進來，狀態欄說一聲。你這裏**有改
動**的時候它不動手，只提醒一次——合併不是編輯器該替你做的決定。

`:reload-auto` 不帶詞就是問現在是開是關。

**被碰過不算被改過。** 大小和時間只是一個便宜的問句——「這可能變了嗎」——而它說「可能」
的次數，遠多於真的變了：同步資料夾把一模一樣的字節重寫一遍、`touch` 一下、git 切回原來
那個版本。為這些攔下來，比不檢查還糟：撞上三次假警報，`:w!` 就成了反射動作，然後**真的
那一次也照打**。

所以時間對不上的時候，它會**把檔案讀出來對一下雜湊**：字節一樣就當沒事，安靜地存。八兆
的表大約兩毫秒半，而且只在便宜的那一問答不出來的時候才付。

**檔案被刪掉算「改過了」**——把它寫回去等於復活一個別人刪掉的東西。

### 這一存把檔案撐大了很多

一個鍵可以把一份稿子變成三份那麼大。`t F` 對齊一張表，最寬那一格是一整段，於是每一行都
補到那麼寬——這個項目自己的 `development.md` 就一鍵從 425,694 字節變成過 2,945,642。那一
次修在對齊上（太寬的欄現在整張表不動），可這一類事沒有修完的一天，而稿子和磁盤之間最後
一道門是存檔。

所以 `:w` 遇到**又翻倍、又多出 256 KB 以上**的時候，會在螢幕中央停下來問：

```
╭安全核驗────────────────────────────────────────────────╮
│ 這一存會把《第一章.md》從 25 KB 變成 1.1 MB，44.1 倍。 │
│                                                        │
│ y  繼續儲存                                            │
│ d  檢視區別                                            │
│ n  取消儲存                                            │
╰────────────────────────────────────────────────────────╯
```

- `y` 照存
- `d` 看改了什麼——就是 `:diff`。**這一存不做**，看完你自己再決定
- `n` 不存。`Esc` 也是這一個

它說的是**數字**，不是「幅度較大」：形容詞正好是你沒法覆核的那一半，而你要決定的就是這
個數字對不對。

**兩個界限缺一不可。** 只看「翻倍」，一份 3 KB 的草稿寫成 7 KB 就會被攔——那是一個早上
的活；只看「多 256 KB」，一本長篇加一章就會被攔。兩個一起纔說得出這件事的形狀：檔案
**成倍**地大，而多出來的量**不是人打得出來的**。

**新檔案第一次存永遠不問。** 磁盤上還沒有那一份，沒有「從多少變成多少」可言。

**問題開着的時候，鍵盤全歸它。** 不是那三個答案的鍵，一個都不會漏到底下的稿子上去。

⚠️ **今天只有 `:write` 裝了這道門。** `:w!` 自己就寫着「蓋過去」；`:wq` 和 `:wa` 各差一
行，留到這個問法用順手了再說。

### 和外面交換文字

**`Cmd+C` / `Cmd+V` 永遠到不了 yumete**——macOS 的終端自己截走它們。這不是可以繞過的
事，是終端定的。所以：

| | |
| --- | --- |
| `空格 y` | 把選區送到系統剪貼簿（也同時進內部寄存器） |
| `空格 p` / `空格 P` | 從系統剪貼簿貼上 |
| `Cmd+V` | 照樣可以用——終端把文字送進來，yumete 當**文字**收 |
| 鼠標拖選 | 在 yumete 裏選，然後 `空格 y` |

**任何帶 ⌘ 的按鍵都不進編輯器。** 開了 Kitty 鍵盤協議之後 ⌘C 其實**真的會送進來**，
而讀成一個光禿禿的 `c` 就是 Normal 模式的 **change**——於是「我想複製」變成「刪掉選
區」。所以 ⌘／⌥⌘／Hyper 一律丟棄，交還給終端。複製用 `空格 y`。

**寫**剪貼簿走終端自己的 OSC 52，不靠任何庫，而且是唯一能穿過 ssh 和 tmux 的路（有些
終端默認拒絕，狀態欄說的是「已請求」而不是「已複製」）。**讀**不能走同一條路——幾乎所
有終端都拒絕 OSC 52 讀取，而且拒絕得對：那等於讓管道另一端的任何程序把你的剪貼簿倒進
一個檔案。所以讀走的是本機的 `pbpaste`（Linux 上是 `wl-paste`／`xclip`），沒有就明說。

`Cmd+V` 能用是因為開了**括號粘貼**。這順帶修掉一個真的 bug：沒有它的時候，粘貼是一串
按鍵，在 Normal 模式下粘進來那一段的**每一個字符都會當命令執行**——那不算粘貼出錯，那
是編輯器在跑一個沒人寫過的宏。

鼠標現在可以在 yumete 裏**拖選**（點擊定位、拖動選取）。終端自己的選區仍然在——按住
Option 拖（Ghostty／iTerm2）就是它，用來複製狀態欄之類不在緩衝區裏的東西。

### 一本長篇

一本小說是一百多個檔案。yumete 對付它們的方式是**把結果變成文本**，而不是多開一種
面板——文本這個編輯器已經有好工具了。

`:grep 阿寧` 掃工作目錄下所有檔案（跳過隱藏目錄、`target`、太大的檔案；**已經打開但
還沒存的內容按當前的算**），把命中結果做成一個 `path:行號: 內容` 的緩衝區。然後就用
平常那套：`/` 再篩、`j`／`k` 走、看中哪一條按 **`gf`** 打開它並跳到那一行。`gf` 認的
是 `path:line:` 這個所有工具都在印的格式，所以從 shell 裏貼一行 ripgrep 的輸出進來
也一樣能跳。

**早上接着昨天。** `yumete` 不帶檔名啓動時，它把上次開着的那些檔案重新打開，每一個都
停在你離開時的那一行，然後在狀態欄說一句「接着上次：開了 5 個檔案」。**只有不帶檔名時**
——說了要開哪個檔案的人，得到的就是那個檔案。

不想要就 `[editor] session = false`，那樣不帶檔名就還是從空白緩衝區開始。

記在資料目錄裏（按工作目錄分開，所以一本小說和一個代碼倉庫不會共用一份），不在你的專案
裏留東西。中途被移走或刪掉的檔案就不開了：這是個方便，方便沒有資格每天早上往屏幕上放一
條錯誤。最多記 **24 個**，你正在的那個排第一——`:replace` 會把改到的每個檔案都打開，
不設上限的話明早就是一百二十個。

**記號。** `M` 加一個字母把這裏記下來，`'` 加同一個字母回去——**跨檔案**，那個檔案會
自己打開。`C-o` 再回到你按 `'` 的地方。用 `M`／`'` 而不是 vi 的 `m`／`'`，因為 `m` 在
這裏是配對模式。

**這本書自己的詞。** 阿寧——每一頁都有的那個名字——是任何詞典都不會有的那個詞。以前它
被切成 `[阿][寧]`：`w` 要按兩次才走過去，分詞著色把它畫成兩個詞。

在 `.yumete/words.txt` 裏一行一個寫下來（`#` 開頭是註釋）：

```
# 人物
阿寧
沈鶴年
# 地名
落霞鎮
```

從**正在編輯的那個檔案**往上找（和表格 schema 一樣：這份詞表是稿子的屬性，不是這次會話
的）。啓動時讀一次，**中途加了名字，`:w` 存下就生效**——存這個檔就是重讀它，狀態欄會說現
在有幾個詞在用。（在別處改了它，`:word-list reload` 手動重讀。）

它是**疊在**現有分詞之上的，不是換掉：宇浩的語言模型（或者 `segmentation.txt`、或者
自帶的那份小詞表）照樣決定其餘的邊界，只有拼得出你的詞的那幾段會被併起來。長的優先，
所以「阿寧」贏過「阿」。

**問這本書自己：`:word-discover`。** 一本有四十個人物、三個門派、一省地名的小說，正是
沒有人記得住要把誰寫進去的那一本。所以別自己想——把整個專案交給它，讓它把書裏「像詞而
字典裏沒有」的那些串找出來：

```
:word-discover
```

它掃專案裏的每一個檔（開着的以你眼前這一份為準），數三件事：

    內聚度   這幾個字擠在一起的次數，遠多於各自獨立時該有的次數嗎
    左熵右熵  它前後跟得住各種各樣的字嗎，還是永遠只跟那一個

第一件把「阿寧」和「的時」分開；第二件把「阿寧」和「阿寧說」分開——真正的詞前後什麼都
接得住，碎片只有一個習慣的鄰居。兩件缺一不可。**最後纔問分詞器**：它已經會併的一概不
報，所以「說道」「突然」不會出現在清單上，門檻也因此可以放得寬。

**它不會把你從稿子裏拽走。** 找到的詞寫進 `.yumete/words.txt` 那個緩衝區——寫進去，
不是打開給你看——你眼前還是剛纔那一章。想過目就 `:word-list edit`。那份清單每行後面注着
出現次數，按次數排：

```
# 本書自己的詞：:word-discover 掃了 118 個檔找出來的，刪掉不要的
阿寧	# 213 次
王語嫣	# 176 次
落霞鎮	# 84 次
```

**一個字都還沒有落到磁盤上。** 你自己看一遍，把不是詞的那幾行刪掉（總有幾行不是），
`u` 可以整段撤回，`:w` 纔是你說「好」的那一刻——和 `:replace` 同一個約定。

**但它們已經在切了。** 還沒存的這一刻，分詞器就已經按這張清單走：就在你眼前這一章按
`w`，光標一下跨過整個「落霞鎮」，分詞著色也把它畫成一個詞。要判斷一個候選是不是詞，靠的就是這
個——一份存下去纔算數的清單，你沒有辦法在存之前看出它對不對。刪掉的那幾行在 `:w` 的那
一下退場：存檔會把這個檔重讀一遍，留下的纔算。

一次最多寫 200 行（一部長篇能找出六千個候選，那不是給人看的）；已經在詞表裏的詞不會再
被報一次，所以下個月再跑一次，出來的只有這個月新寫的那些名字。

**改一個名字，改遍全書。** 一個角色改名，一百二十章都要改，以前意味着開一百二十次檔。

```
:grep 阿甯          先找 —— 結果就在眼前，一條一條看得見
:replace 阿寧       再換 —— 換的就是剛才那些
:write-all                 確定了再存
```

安全在**順序**上：**沒有一條可以閉着眼睛打的全局替換**。模式是你剛剛 `:grep` 用過、
命中結果也已經讀過的那一個。而且 `:replace` **一個字節都不寫磁盤**——它把每個有命中
的檔案開成緩衝區、在裏面改，所以每一個都能各自 `u` 撤銷、`gn` 逐個看過去，`:write-all` 才是
你說「好」的那一下。

`:toc` 開大綱欄，`:toc 3` 直接跳到第三條。標題是 Markdown 的 `#` 和 Typst 的 `=`——
沒有 parser，標題就是行首的那幾個井號。

**沒有標記的小說也有章節**：一個 `#` 都不用的 `.txt`，「第一章」「第四百一十二卷」
「楔子」「後記」這樣自成一行的短行就是它的標題。只在整份稿子找不到一個 markup 標題
時才這樣找——用 `#` 的稿子已經說清楚它怎麼標章節了，正文裏偶爾出現的一行「第三章」
不是第二種意見。

`:buffer` 看開了哪些，`:buffer-close`（短寫 `:bc`）關掉一個。同一個檔案不會被打開兩次——第二次
`:open` 是切過去，因為兩個緩衝區共用一個檔案意味着兩份撤銷歷史、兩個修改標記、兩個搶救
稿在搶同一個位置，那是丟稿的方式而不是開檔的方式。

**`:q` 關掉的是這一個檔案，不是編輯器。** 開着三章按 `:q`，你回到第二章；只剩最後一個
時它纔真的退出。這是 Vim 與 helix 的規矩，也是寫作時想要的那個：關掉手上這一份，不等於
收工。真要走人是 **`:qa`**（`:qa!` 連沒存的一起丟）。

沒有 `:Q`。它跟 `:q` 只差一個 Shift 而意思不同，那正是手會滑的地方；短寫要用 `:bc`。

### 今天寫了多少：`:count-progress`

寫長篇的人跟自己約的那件事——一天兩千字——沒有人替他數。數了也記不住昨天是多少，更
記不住上一次斷在哪一天。

```
:count-target 2000        每天兩千字，記下來
:count-progress           今天寫了多少，這本書寫到哪了，連了幾天
```

`:count-progress` 開出來的是一份清單：一天一行，最近的在最上面，後面那條長條是那一天的份量。

```
2026-09-06　1830 字　███████████
2026-09-05　2440 字　████████████＋
2026-09-04　260 字　█
今天 1830／2000 字（91%），本書 62480 字，連續 3 天
```

`＋` 是超過目標的那一天。`－` 是**刪多過寫**的那一天——刪掉一千字的下午也是幹活，只是
那個數字是負的，畫不成條。沒有設目標時條照樣畫，比的是這些天裏最好的那一天。

**它數的是字，不是字符。** 和 `:count` 同一個算法：漢字算一個，`ABC` 三個字母不是三個
字。所以「今天 1830 字」是責任編輯認的那個 1830。

**記在 `.yumete/progress.tsv`，一行一天一個檔：**

```
# yumete 寫作進度：日期 ⇥ 檔名 ⇥ 起 ⇥ 現
目標	2000
2026-09-05	第一章.md	0	1830
2026-09-06	第一章.md	1830	2440
```

⇥ 是一個 tab。**這是一份可以自己改的文本**——手抖了改回去、把哪一天刪掉、換臺機器合
併兩份，都是編輯這個檔案的事。看不懂的行原樣跳過，不會整份作廢。

「起」是這一天第一次打開它時的字數，「現」是最後一次存盤時的字數，兩個相減就是那一天
的份量。所以它記的是**存盤之間的變化**——沒存過的改動不算數，這一點和 `:count` 不同。

**「本書」是每一個檔案最後一次存盤時的字數加起來**，一百二十章各記各的。

**連續幾天**是往回數的：昨天有寫、前天有寫，就一直數下去；今天還沒開始不算斷（早上八
點打開編輯器不該看見「連續 0 天」）。

**它不會自己在你的目錄裏留東西。** `:count-target` 或第一次 `:count-progress` 纔建那個檔；建好之
後，這本書底下每一次 `:w` 都往裏記一筆。不想要了就 `:count-target off`，或者把那個檔刪掉。

### 一本書裏兩個寫法：`:check-usage`

寫了一年的稿子，前面是「裏」，後面是「裡」。兩個都對——都是規範的漢字，沒有任何一個
拼寫檢查器會說話：Word 查的是病句，Grammarly 是英文的，而所有的拼寫檢查器都按空格切
詞，一整章在它眼裏是一個詞。於是這件事只能自己看，而自己看不見。

`:check-usage` 不問字典，問**這份稿子**。同一組的兩個寫法**都在這裏出現過**才算一
條：「裏」四百次、「裡」三次，那三次就是稿子還沒定下來的地方，而多的那個就是它想要的
那個。只寫「裡」而從不寫「裏」的稿子，一個字都不會被報出來——那是風格，不是不一致。

結果和 `:grep`、`:table-check` 是同一個形狀：一個 `檔名:行號: 這裏是「裡」3 次，全文
多用「裏」400 次` 的緩衝區。三百條不是一句狀態欄裝得下的，**`gf`** 跳到那一行去改。

自帶的那張表有六十來組——裏/裡、為/爲、臺/台、著/着、才/纔、群/羣、甚麼/什麼、身分/
身份……收的是真會兩邊寫的那些。面/麵、谷/穀、困/睏 這種**兩個字義不同**的沒有收：那
不是寫法之爭，報出來只會吵。

**這本書自己的那些**——阿嬌和阿姣、落霞鎮和落霞鄉——任何異體字表都不會有，而恰恰是一
年下來最容易走樣的。寫在配置裏，一行一組，想留的那個寫在前面（並列時它贏）：

```toml
[editor]
usage_groups = ["阿嬌 阿姣", "沈鶴年 沉鶴年", "落霞鎮 落霞鄉"]
```

長的寫法贏過它裏面的短的：有「甚麼 什麼」這一組時，「什麼」不會再被當成「麼」算一次。

### 這一章你說了幾次「然後」：`:word-habit`

把稿子裏的詞數一遍再按次數排，第一名永遠是「的」，第二名是「了」——中文就是這樣的，這
件事任何一本書的答案都一樣，所以它什麼也沒告訴你。有用的是另一個問題：**這一章比尋常
的文章多說了哪些詞**。

`:word-habit` 問的是這個。它拿分詞器的詞頻表當底：一個詞在你這裏出現 `c` 次、全篇 `n` 個
詞（**只數詞頻表認得的那些**——`P` 就是在那本詞表裏的比例，兩邊要在同一個宇宙裏數，
不然一本人名滿篇的小說每個「倍」都被攤薄），而尋常文章裏它的比例是 `P`，那麼

    多 ＝ (c / n) ÷ P          倍
    分 ＝ c × ln(多)

排的是**分**不是**倍**。差別就在這裏：一個說了三次、比別人多三倍的詞不值一提，而
「然後」多四倍卻說了四十七次，那纔是你自己看不見的那個口頭禪。「的」在哪本書裏都多，
所以它的「倍」是一，一個字都不會被報出來。

    ch03.txt:12: 「然後」47 次——比尋常文章多 4.2 倍

結果和 `:check-usage` 一樣是可以 `gf` 跳過去的清單，行號是那個詞**第一次**出現的地
方。

**它有意不說三件事。** 詞頻表裏沒有的詞跳過——「阿甯」不是口頭禪，是個人名，一本書自
己的詞是另一件事。單個字跳過——分詞器把不認得的漢字一個個拆開，那些是它的碎屑不是你
的選擇。說了一兩次的跳過——三次纔算習慣。

**它需要一張詞頻表。** 裝了宇浩字料層就是那 125 萬條；沒裝時內置的那份只有六百多個
詞，報得出來的自然少。一張詞頻都沒有的詞表（比如關掉了分詞）會直接說出來，而不是給你
一份空清單讓你以為自己寫得很乾淨。

### 沒有收尾的那個「：`:check-punct`

`:check-punct` 看三樣東西，前兩樣是體面，第三樣纔是它存在的理由。

**半角。** 中文裏的 `,` 不是逗號，是一個擠在字身左下角的東西——輸入法晚切了一下就會
有一個，而排版社退稿最常見的理由就是它。`,` `.` `;` `:` `!` `?` `(` `)` 都查。

**`...`。** 中文的省略號是六點，`……`。三個點是英文的。

**開了口沒收尾的「」『』（）《》〈〉【】。** 這一條纔是重點：少一個 `」`，**它那一行
看不出任何問題**，而從那裏往後，這一章每一個引號的意思都反了過來。校對的人盯着出事
那一頁看，什麼也看不出來——因為那一頁是對的。

**只在中文旁邊纔算數。** `3.14`、`1,000`、`README.md`、一整句英文，裏面全是半角標
點，而且全都對。決定一個標點對不對的是**它旁邊的那個漢字**，所以只有貼着中文的纔報；
`` `代碼` `` 和 ``` 圍起來的整塊一概不看。小數點和千分位另外還擋了一道。

**跨段的引文不會被冤枉。** 一段引文分好幾段時，中文的排法是每一段開頭都重開一個
「，只有最後一段收 `」`。所以一行末尾還開着的 `「`，只有在**下一段不是也用「開頭**
的時候纔算漏。括號沒有這個說法，開了就得在同一段裏收。

結果和 `:check-usage` 一樣是個可以 `gf` 跳過去的清單。

### 排版社沒有的那個字：`:check-charset`

`:check-charset` 找出**不在任何字集裏**的字——通用規範、臺灣、香港、古籍，四個都沒
有的那些。

這件事的可怕在於它**不在你這邊出錯**。你屏幕上的字體有那個字，它看起來一切正常；排版
社的沒有，於是三個星期以後它變成一個豆腐塊，或者變成另一副字體裏一個大小不對的字，
而且每一次印刷都這樣。沒有一個寫作工具問這個問題，而答案早就在編輯器裏了——`:yume
scheme` 載進來的那份拆分表就帶着每個字的字集。

**一個字一行，不是一處一行。** 一個帶生僻字的人名會出現四百次，而它是**一個**決定：
留着，或者整本換掉。四百行只會把另外那三個字埋掉。所以每一行給的是這個字**第一次**出
現的地方、全文多少處，以及它在哪個 Unicode 區塊——區塊纔是「字體會不會有它」的答案。

```
書.txt:37: 「𠮷」不在任何字集裏（CJK擴展B），全文 412 處
```

沒載方案的時候它只說一句「沒有字集資料」，不會假裝查過。

「只在古籍裏」的字**不報**——那是 `:ruby-auto rare` 的事（它給生僻字注音），古籍是一
個字集，字體多半有。這裏報的是四個都沒有的。

### 簡繁：`:convert`

`:convert s t` 把整份稿子從簡體轉成繁體，`:convert t s` 反過來。

**這件事 yumete 自己不做。** 发 在 头发 裏是 髮、在 发现 裏是 發；干 是 乾、幹 還是
干；里 是 里還是裏，要看它是路上的里還是裏面的裏。一張字表答不了這些，要一本詞典加
上分詞，而那本詞典
[OpenCC](https://github.com/BYVoid/OpenCC) 已經認認真真做了十五年。所以 `:convert`
就是去跑 `opencc`——自己再寫一個，只會寫出一個更差的 OpenCC，而稿子要信它。

沒裝 opencc 的時候它說一句怎麼裝，一個字都不動。`:convert-opencc install` 在 macOS
上會替你跑 `brew install opencc`；別的系統上它只把命令印出來，因為那需要 sudo，而全
屏的編輯器不是該問你密碼的地方。裝好之後 opencc 要在 `PATH` 上，`:convert` 纔找得到
它。

七個代號，前五個就是 opencc 自己的配置名：

| | |
| --- | --- |
| `s` | 簡體 |
| `t` | OpenCC 的繁體——爲 説 裏 着 |
| `tw` | 臺灣正體——為 裡 著 |
| `hk` | 香港繁體 |
| `jp` | 日本新字体 |
| `c` | **大陸通規繁體**——爲 裏 着 説 内 吴 |
| `g` | **古籍通規繁體** |

`:convert` 不帶參數，列出這七個以及每一個能去哪裏。opencc 不是每兩個之間都有路
（`jp` 只回得了繁體），列出來的就是能走的。

**`c` 和 `g` 是這裏自己加的。** OpenCC 的繁體是港臺字形，而大陸出版社排一本繁體書用
的是通規字形，宇浩自己那份字料也是照通規寫的。兩者差的是**字形，不是用詞**：説 對
說、内 對 內、吴 對 吳，幾十個字，一個換一個。這麼小的事情就該是數據，所以它是一張
表——`:convert s c` 先讓 opencc 跑 `s2t`，再拿那張表把字形掃一遍。表抄自
[GujiCC](https://github.com/forFudan/GujiCC)。

從 `c` 出發也走得通：先把那張表**倒着**走一遍，回到 opencc 認得的字形，再交給它。所
以 `:convert c tw` 是「通規 → 繁體 → 臺灣正體」。有幾個字倒不回去——通規把 蝨 併進
虱、把 嶽 併進 岳，一個 虱 沒有唯一的來路——那幾個原樣留着，不猜。

**`force` 是換詞，不是換字。** opencc 有幾個帶 `p` 的配置（`s2twp`、`tw2sp`）連詞彙
一起換：内存 變 記憶體，鼠標 變 滑鼠。那和上面所有事情都不是一回事——它會改字數，而
且回不去——所以要明說：`:convert s tw force`。沒有 `p` 配置的那幾對，`force` 直接回
絕。

**反悔按 `u`。** 一次轉換是一步撤銷，整份稿子一起回來。**別拿反方向當撤銷**：`s t`
之後再 `t s` 得到的不是你原來那份稿子，是它繞了一圈的樣子。

### 導出

排版資訊——竪排、標點旁置、注音——本來只活在屏幕上。`:export html` 把它們寫進一個
可以直接打開的檔案：竪排用 `writing-mode: vertical-rl`（瀏覽器是終端以外唯一一個一
行 CSS 就能排縱書的地方），旁置用 `hanging-punctuation`，注音用 `<ruby>`。不給路徑
就用文稿自己的名字換個後綴：`chapter.md` → `chapter.html`。

**那個檔案也能直接印。** 同一份 HTML 帶着一段 `@media print`：紙張大小、天頭地腳、
每一章從新的一頁起、標題不落在頁腳。字號是**算出來的**，不是挑的——竪排的行往下走，
版心就是「字數 × 字身」：你已經說了一縱幾個字，紙又說了那一縱要走多遠，字有多大就
沒有剩下的選擇了。小紙上要長縱，字自然就小，跟真排一本書一樣。

紙張在配置裏（`[export] page`，默認 A5），因為開本是一本書定一次的事。一縱幾個字則
是 `[editor] zong_length`——**沒寫的話那是窗口此刻給多長**，所以要印之前先把它定下來。

⚠️ **頁碼與書眉沒有**，導出的檔案裏寫明了為什麼：那要用 `@page` 的邊欄框
（margin boxes），瀏覽器一個都沒實現。列印對話框自己的頁眉頁腳是眼下唯一的頁碼。

`:export typst` 出的是**橫排**，而且在檔頭寫明為什麼：Typst 目前沒有竪排。與其出一
個看起來像竪排、實際不是的檔案，不如說清楚。注音會改寫成 `#ruby(base, reading)`，並
且在檔頭附一個可以自己改的定義。

兩種導出都只認**標題、段落、注音**——一份稿子就是由這三樣構成的，猜其餘的只會做出一
個「看起來對，直到它不對」的檔案。

**標記會被排出來，不是照抄。** `**很好**` 導出的是 `<strong>很好</strong>`（Typst 是
`*很好*`），不是四個星號——照抄標記的那個不叫導出，叫複製。

**批注不進書。** `%%這裏要改%%` 是你對自己說的話，手冊一直是這麼說的，可它以前會原樣
寫進交給出版社的那個檔案。現在它和標記符號本身一樣，導出時什麼都不留。

### 搶救稿

改了還沒存的時候，yumete 每隔幾秒在文件旁邊寫一份副本：`chapter.md` 的副本叫
`.chapter.md.yumete`。存檔和正常退出都會把它刪掉，所以順利的時候你根本看不見它。

「每隔幾秒」是**最多五秒**，而且**停筆也算數**——寫完一段停下來想情節，那幾秒鐘的字
照樣會被寫進副本。（2026-09-11 之前不是這樣：副本只在你按下一個鍵的時候才寫，所以一
停筆就再也不寫了，斷電丟掉的正好是你正看着的那一句。）

要是這中間終端崩了、電斷了，下次打開同一個文件，狀態欄會說有一份更新的搶救稿，並且
文件名後面一直掛着 `[draft]` 直到你處置它。它**不會**自動載入——悄悄給你看一份和硬
盤上不一樣的文字，是讓人分不清自己在讀哪一版的開始。`:recover` 載入（載入以後 `u`
可以退回硬盤上那版，`:w` 才算採納），`:recover!` 直接丟掉。

**沒被認領的搶救稿不會被動。** 打字不會蓋掉它，`:q` 和 `:q!` 也不會刪掉它——只有
`:recover!` 會。這條規矩也順帶擋住了同一個文件開兩個 yumete 時互相踩的大半情形：第
二個進程看見的是一份「別人的稿子」，於是既不寫也不刪。真正的鎖（像 vim 那樣）還沒
有，所以同開兩個窗口寫同一章仍然不是好主意。

沒有名字的臨時緩衝區沒地方放副本，所以沒有。副本寫不下去（目錄只讀之類）會在狀態欄
說一次。`[editor] autosave = false` 可以整個關掉。

`:q` 和 `:wq` 查的是**所有**打開的檔案，不只是眼前這個。`gn` `gp` 能走到每一個，
所以在乾淨的檔案上退出而丟掉另一個沒存的，是編輯器該攔下來的事；攔下來時會直接跳到
那個沒存的檔案，`!` 才是對一個有名字的文件做的決定。

檔案一律當 UTF-8 讀。開頭的 BOM 會去掉（不然它就是第一段看不見的第一個字）；Big5 或
GB18030 的舊稿會被擋下並告訴你用 `iconv` 轉，而不是丟一句 Rust 的內部錯誤。

**字數**用 `:count`（或 `:wc`）。注音標記不算寫作——`<ruby>永和<rt>えいわ</rt></ruby>`
是兩個字兩個字符，不是磁盤上那二十幾個字符。它同時報三個數，因為「寫了多少」在中文裡有三個答
案：出版社數的是**字**（漢字本身），文字處理軟件數的是**字符**（連標點一起），對話
多的段落兩者能差一成以上。有選區時統計選區——量一場戲，而不是量一本書。

**改了什麼**用 `:diff`。所有你按得到的比較工具都是**按行**比的，而中文的一段就是一行：
把五百字裏的一個「的」挪個位置，`git diff` 就把整段抹掉再畫回來——說的沒錯，但你想知道
的那件事（**哪個詞**）埋在五百個字裏。`:diff` 按**詞**比，用的是這個編輯器自己的分詞，
就是 `w` 走的那一套：

    ch01.txt:2: 那年冬天，雪下得[-很早-]{+極早+}。

`[-…-]` 是去掉的，`{+…+}` 是加上的，`⏎` 是換行加了或者少了。結果是一份可以 `gf` 跳過
去的清單，跟 `:grep` 一樣。

不帶參數就是跟**磁盤上那一份**比——「這一坐下來我改了什麼」，這個問題保質期最短。帶一
個路徑就是跟那一份比：昨天的那一章，重寫之前留的那份底稿。路徑是相對**當前這個檔案**
所在的目錄算的。

兩份差得太遠（一千二百處以上）就不逐詞列了，會直接說差得太遠——那已經不是同一篇稿子的
兩稿，逐詞比不出東西來。

**分詞**——`w`／`b`／`e` 和詞語著色靠的東西——來自同一個引擎的詞頻表（125 萬條帶權）
和詞彙表，以引用共享，不會佔第二份內存。沒裝輸入法數據時，退回數據目錄裡的
`segmentation.txt`，再退回內置的小詞表。

**兩邊本來就分得開的詞不著色。** 一個詞如果左右都是空格、換行或者標點，頁面上已經把它
斷開了，再上一層底色是把同一件事說兩遍——西文句子大半如此，中文句子也有不少：
「今天天氣很好。」裏 `今天` 要標，`好。` 不必。剩下的正是眼睛得自己切的那幾串漢字。
整個著色不想要就 `:word-show off`，或者配置裏 `show_segmentation = false`。

**兩種畫法。** 出廠是**底色**：隔一個詞在紙上鋪一層極淡的色，一眼掃得過整頁。
`:word-show 字色`（`:word-show ink`）換成另一種——**紙不動，換墨色**：隔一個詞的字
本身退後一格，像注音那一級的淡。有兩種人會要它：頁面上本來就有底色的（`==標記==`、
`::: 提示` 那一類，底色一多就分不清哪層是哪層），以及覺得字底下壓一條帶子比字本身還重
的。`:word-show 底色`（`:word-show tint`）換回去，配置裏是 `word_mark = "tint"` ／
`"ink"`。兩種都是嚴格隔一個詞，所以沒被標的那個詞永遠夾在兩個標了的中間，說的話一樣多。

## 八、命令

打 `:` 就在命令行上方列出命令，邊打邊篩。**即將補全的部分**用淺色顯示在光標後，
**Tab** 採納它，再按 Tab 換下一個匹配，**Shift-Tab** 往回。

一個**打完了的**命令會連它收的詞一起列出來：打到 `:yume` 就看見 `yume scheme`、
`yume chaifen`……所以「這個命令下面還有什麼」是看得見的，不必先知道才找得到。Tab 選
中子命令時整句一起寫上去。

**有前提的命令會先說前提。** 標點旁置要竪排、而且密排關着才有地方掛；密排和段組只管
竪排；`:table-jump`、`:table-check`、`:table-rules` 要先在表格模式裏；`:yume-chaifen` 要先有
碼表。這些條件**寫在命令旁邊**，於是三處都說得出來：

- 菜單裏那一條就標着 ⟨需要 竪排、密排關，句末加 force⟩；
- 真按下去也不會默默設一個沒人讀的旗標，而是說「還不行，需要：竪排、密排關」；
- **句末加 `force`** 就一併打開：`:view-hanging on force` 等於 `:layout vertical` +
  `:view-dense off` + `:view-hanging on`。

沒有 `force` 的時候**什麼都不動**——一條小命令不該把整個版面翻成竪排；缺什麼你看得見，
換不換由你。

搜索行也會猜：它給出**上一次搜索詞**的剩餘部分，所以再搜一次同樣的東西就是 `/` 加
一個 Tab。

**每種檔案自己說要跑什麼**（`[language.…]`）。`tinymist` 以前是寫死在程序裏的，
其實那是你這台機器的事，不是編輯器的事：

```toml
[language.typst]
preview = { run = "tinymist preview --no-open {file}", kind = "server" }
format  = { run = "typstfmt {file}" }

[language.markdown]
format = { run = "rumdl check --fix {file}" }
zhuyin = { run = "pandoc {file} -o {dir}/{name}.docx" }   # :run zhuyin
```

`kind` 有三種：`once` 跑完就完（跑完重讀檔案），`server` 一直跑着（`:view-preview` 用它，
`:view-preview off` 停），`filter` 把稿子從 stdin 送進去、把回來的東西換上（不碰檔案，
`u` 可以撤銷）。佔位符：`{file}` `{dir}` `{name}`。

**動詞不分語言**：`:view-preview`、`:format` 在每種檔案裏都是同一個鍵，設定說這種檔案怎麼做；
自己起名的用 `:run <名字>`。

**項目自己的 `.yumete/config.toml` 也可以定**，因為安全不靠「誰能寫」，靠**怎麼跑**：
不經過 shell（所以 `;` `&&` `$( )` 只是普通字符，不是語法），佔位符**整個當成一個參數**
（檔名叫 `我的 稿;rm -rf ~.md` 也還是一個參數），而且載入時就檢查——引號不配對、
不認識的佔位符、出現 shell 元字符，都會在狀態列指出是哪個檔案的哪一條。

```

右邊可以是**一串**鍵，不只一個。這樣默認值可以照我們認為對的來定（`J`／`K`／`H`／`L`
是翻頁，因為這是一本書），而不同意的人花一行配置，不是離開。左邊必須是**一個**鍵——
那是你按下去的東西，沒有「按一串」這回事。

編號字符**必須是全角**（兩格寬），否則列會錯開。帶圈中文數字 ㊀㊁㊂ 是全角；帶圈阿
拉伯數字 ①②③ 屬於東亞「模糊寬度」，不同終端可能畫成一格也可能兩格，不要用。列表用
完之後的候選退回普通數字。

### 主題：墨香

默認主題叫**墨香**（`moxiang`，兩個名字都認）。它是**四種墨**：

- **黑墨**——紙面，也就是正文的底。
- **白金墨**——正文。白裏帶一點金，不是骨白：整屏都用骨白的話，色階上每一格都變暖，
  於是正文、標題、傢俱一個顏色，頁面就沒有層次了。
- **金墨**——**不是正文**的那些字：標題、表頭、面板裏的欄名。整屏是灰的，它才找得到。
- **紅墨**（朱）——**不對**的那些：欄數不齊的行、沒有字根的部件、腳注的號。不做強調。

黑墨和白金墨之間的深淺全部插值算出來——一條色階，0（純墨）到 1000（純紙）。換主題是
改幾個數，不是填一張表；改了之後各處的關係仍然對，因為關係本來就是算出來的。

色階上的位置有它的道理：

| 色階 | 用在哪 |
| --- | --- |
| 0 | 正文，以及一切**就是**正文的東西 |
| 300 | 退一階：注音、拆分、候選的編號 |
| 400 | 傢俱：行號、沒選中的分頁、鍵名、批注 |
| 450 | 標記本身（`**`、`#`、表格的豎線） |
| 550 | 線：邊框、想寫多長那條線、稿紙刻度 |
| 800 | 選區的底色（**只有**底色，字保留自己的顏色） |
| 880 | 要看得見的一條：竪排的段落號帶、亮着的那個分頁 |
| 940 | 安靜的底：表格的隔欄、超出想寫多長的那一塊 |
| 970 | 傢俱：側欄、分頁條、表格的行號欄和表頭、詳情面板、狀態欄 |
| 1000 | 紙 |

350 以下是**讀得動的墨**，730 以上是**寫得上的底**，中間那三分之一除了線以外不放東
西——放進去的東西太淡讀不動，又太濃當不了底。

傢俱那一格離紙面只差一點，是有意的：**主題色是墨黑**。側欄和表頭跟正文分開，靠的是那
條線和金墨，不是把底色調成灰的——底色一灰，整屏就往色階中間擠，反倒什麼都不分明。

**金墨**和**紅墨**不在這條色階上，因為它們不是墨的多少。金墨給標題、表頭、面板的欄名
和側欄的目錄名；紅墨給腳注、參差的行號、光標所在那一段的號碼。`==標記==` 用的是紅墨
**沖淡到快要變成紙**——那是讀者自己的筆，不是「這裏不對」。分詞的底色是同一支紅墨再沖
淡一層，所以它跟着深淺走，不必另外配。

`mode = "auto"` 會**問終端**它的底色是什麼（OSC 11），據此決定深淺——問的是終端而不
是桌面，因為淺色桌面上開一個深色終端的人，已經回答過這個問題了。終端不答就照配置裏的
`dark`／`light`；寫死 `mode = "dark"` 則根本不問。

`ground = "terminal"` 把底色還給你的終端：yumete 不畫紙，只按色階決定各處退多遠。適合
配色是自己調過的人。

### 【黑白】

第二套主題，`[theme] name = "黑白"`（`bw`、`heibai` 也認），或者 `:theme bw` 當場換。
**只有黑、白和灰**：沒有金墨也沒有紅墨的顏色，它們說的話改由**位置**說——金墨比正文
還亮（整頁只有它比正文亮），紅墨再亮一階，是唯一走到色階盡頭的東西。深淺兩個模式都有，
`mode` 照舊。

它不是墨香關掉顏色的版本，而是「把顏色全拿走以後，這套設計還立不立得住」的那個問題本
身——順帶也是色弱、色盲和單色終端上看到的東西。

臨時要換用 **`:theme`** 和 **`:theme`**——**主題是主題，深淺是深淺**，兩個問題兩
條命令：`:theme bw` 換一套墨，`:theme light` 只換深淺（`system` 是回到終端
開機時答的那個），`:theme ink dark` 是一句話問完兩件事。`:theme` 不帶參數說現在是
什麼。它們**不改配置檔案**——這是為了下午房間亮起來的那一次，寫進 `[theme] mode` 的才
是你每天想要的。

## 十、還沒有的

明說出來，免得你去找：

- **多光標。** Helix 的 `C`、`s`、`S` 需要內核持有**一組**選區而不是一對錨點／光
  標。那是改造編輯器而不是給它加東西，所以寧可不做也不半做。`gt`／`gc`／`gb`（跳到
  屏幕頂／中／底）缺席是同一個原因的小號版本：滾動位置在渲染層，不在編輯器裡。
- **圈點**（着重號）——能畫，用注音那一列；標記語法還沒定。
- **拉丁串真旋轉。** 終端轉不了字形，所以長的拉丁串只能逐字母往下堆。縦中横 能處理
  兩個字符，整個詞沒辦法。
- **代碼的語法高亮、LSP、分屏。** 見 [development.md](development.md) 裡的功能表。
  （Markdown 和 Typst 的著色是有的，見「Markdown 著色」；大綱側欄也是有的，`空格 o`。）
- **`:s` 的 `c` 旗標**（一處一處問你要不要換）。`n` 先數一遍是有的。
