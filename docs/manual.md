# yumete 使用手册

> 本手册有[繁體](manual.md)與[簡體](manual_sc.md)兩個版本。簡體版本爲自動轉換生成。

**yumete**（宇夢終端編輯器）採用 Helix 的設計哲學、對 CJK 文本環境深度優化、内置中文分詞功能、自帶宇夢輸入法引擎、提供大量專爲中文寫作設計的功能，是一款更加符合漢字文化圈用户習慣的終端編輯器。

Yumete 這個名字，取自`Yume` ＋ `TE`（Text Editor／Terminal Editor）。Yume （宇夢）是我爲宇浩系列輸入法而設計開發的一款通用輸入法軟件。Yumete 集成了 Yume 核心引擎，且可以直接調用 Yume 裏的輸入方案，讓你能够在終端環境下高效輸入中文。

安裝 Yumete 後，你可以使用其全名 `yumete` 和别名 `ye` 來使用它進行文本編輯。

## 一、設計哲學

Yumete 採用了 Helix 設計哲學：先選擇，後動作。

Vim 一脉的編輯器是「動詞 + 賓語」，比如 `dw` 是「删一個詞」，兩個鍵都敲完之前什麽都不會發生。Yumete 和它相反：一次移動就是一次選擇。按 `w` 時光標向前走一個詞語，同時會把走過的那個詞選中。你會先看見將要操作的範圍，再決定對他施加怎樣的動作。比如用`d` 删除這一個選中的詞語。

因此上，有兩件事情我們應該注意：

- 首先，**每次移動都會留下選區。** `w`（按詞移動）、`f`（移動到某個字符）、  `x`（選取一整行）都會以高亮方式標記出一段範圍。`d`（删除）、`c`（修改）、  `y`（複製）、`R`（替換粘貼）都作用在這段範圍上。
- **光標所在的那個字，本身就在選區裏。**方塊光標蓋住的字，就是 `d` 會删掉的字。

Yumete 雖然采用了 Helix 的設計哲學，但是在很多方面和 Helix 不盡相同。這主要是为了照顧漢字文化圈用户的習慣。

比如，傳統的终端编辑器，都是以英文使用者設計的，`w` 移動詞語時，按照空格爲邊界。這在中文狀態下顯然會出問題，因爲中文的詞語間不存在空格分界。再比如，英文只有橫排的書寫習慣，但中文使用者會有「縱書」的習慣，我們也應當予以支持。

以下是 Yumete 專爲漢字文化圈用户設計的特色功能：

- 中文詞語由詞典決定，不由空格決定。 `w` 按真正的中文詞語（包括單字詞和多字詞）移動。它使用的是宇夢自己的語言模型（見第六節）。而 `e` 和 `b` 纔是按句子移動。
- `gJ` 併行時不一定補空格。 兩個漢字之間合併時，應直接接上。拉丁詞之間則照補空格。
- 匹配模式（match mode）認得中文括號。 `mi「`、`ms《`、`md` 這些對「」『』（）《》【】〔〕 和 ASCII 括號一樣有效。
- 支持竪排（見第五節），標點會轉向，還可以在字旁注音。
- 輸入法是編輯器的一部分，而不是上面疊加的一層。Yumete 自帶宇夢輸入引擎，你再也不需要頻煩使用 shift 切換輸入法模式以在 Normal 模式中不會造成吞鍵問題。

## 二、開始使用

```sh
scripts/build.sh             # 編譯出 ./yumete，安裝輸入法數據，並接上全局的 yumete 與 ye
scripts/build.sh --no-data   # 只編譯二進制
scripts/build.sh --no-link   # 不動全局那一條命令
```

最後一步是把 `~/.local/bin/yumete` **和 `~/.local/bin/ye`** 都指到剛編出來的那個
二進制上，所以在任何目録裏打 `yumete` 或 `ye` 用的都是這一次的編譯。
**`ye` 是同一個程序的短名字**，不是另一個程序——就像 helix 裝出來叫 `hx`。
（`ye` ＝ **y**ume **e**ditor，和 `yumete` ＝ `Yume` ＋ `TE` 是同一條線。）
想放到别處：`YUMETE_BIN_DIR=/usr/local/bin`。
那兩個位置上如果已經有一個**真的文件**（不是我們建的鏈接），腳本就繞開它——别人裝
的東西，不該被一個編譯腳本悄悄換掉。`ye` 短，所以這一條對它比對 `yumete` 更要緊。

**第一次用**：進去之後打 `:tutor`——它會把一課抄成**你自己的一個文件**，
邊改邊學，裏面每一個會破壞東西的鍵都可以放心按（`u` 是第一課）。
忘了某個鍵：`:help`，一共四節，能像讀稿子一樣讀、一樣搜。

```
yumete <文件>...       打開一個或多個文件
yumete                 接着上次——上次開着的那些文件，各自停在離開時的那一行

  -v, --vertical       這次以竪排（縱書）打開
  -H, --horizontal     強制横排
  -t, --table          當表格讀（CSV 没有 schema 也行，用首行當表頭）
  -R, --readonly       鎖住這一次開的每一份，不許改
  -n, --new            這次不接上次，開一個空白的
  -p, --preview        只打印内容，不進編輯器
      --shot[=寬x高]   把一幀畫成文字印出來就退出（默認 100x30）
      --html           跟 --shot 一起用：連顏色一起，輸出一段自足的 HTML
      --keys=…         跟 --shot 一起用：先餵一串按鍵再拍
  -h, --help           按鍵與命令一覽
  -V, --version        版本，帶構建時間與提交號
```

**版本號説得出「我跑的是哪一份」。** 開發期間一天十幾個提交，光一個 `0.1.0` 答不了
這個問題，而這恰恰是所有故障報告要問的第一件事：

```
$ yumete --version
yumete 0.1.0-dev.20260905110744+bbc1485.dirty
       │     │   │              │       └ 編的時候工作區有没提交的改動
       │     │   │              └ 從哪個提交編出來的
       │     │   └ 什麽時候編的（本地時間）
       │     └ 不是發布版
       └ Cargo.toml 裏那個號
```

`.dirty` 比看上去要緊：没有它的話，只要樹上有没提交的改動，那個提交號就是**假的**；有
它，那個號誠實地只是一個「起點」。發布版（`YUMETE_RELEASE=1` 編的）就是乾淨的 `0.1.0`，
後面什麽都不帶。

同一行也印在每一張**畫出來**的圖最下面（`--shot`、`--html`、編輯器裏的 `:shot html`／`txt`
都是），畫在頁面**外面**，所以貼過來的圖自己説得出它是哪一版畫的：

```
-- yumete 0.1.0-dev.20260905110744+bbc1485.dirty
```

`--preview` 不進編輯器，直接把内容打印出來，也認 `--vertical`——不離開命令行就能看
排版效果。

`--shot` 更進一步：它把**整整一幀**——行號、狀態行、面板、竪排的縱，全部——按編輯器
真正會畫的樣子印成文字。所以一張「當時長這樣」可以貼進 issue，也可以讓没開這個編輯器
的人看見版面到底是什麽樣子。`yumete --shot=64x16 -v 第一章.txt` 就是一頁竪排。

編輯器裏面的 `:shot` 有四種，第一個字説的是**拍什麽、留下什麽**：

| | |
| --- | --- |
| `:shot`（＝`:shot screen`） | 拍窗口，圖進**剪貼板**，直接貼進聊天窗或 issue |
| `:shot png` | 同一張，存成 PNG 文件 |
| `:shot html` | **不截屏，自己把這一頁畫出來**，帶顔色、自帶樣式的 HTML |
| `:shot txt` | 同上，不帶顔色的純文字那一版 |

拍窗口那兩種交給系統的截圖程序，命令寫在配置的 `[editor] screenshot` 裏；`png` 那一種
把去處寫進 `$YUMETE_SHOT` 交給它（出廠那條命令收得到，自己寫過那一行的話照着補一句
`"${YUMETE_SHOT:--c}"`，没補的話 `:shot png` 會告訴你圖還是進了剪貼板）。

畫出來的那兩種不經過屏幕。截屏要知道終端窗口在屏幕上的位置與顯示器的縮放倍率，
這兩樣編輯器都拿不準，於是圖裏總會多出標題列、標籤頁、終端自己的留白——**畫出來的
那一張從一開始就只有頁面**，而且遠程連上去的機器上一樣畫得出來。

存成文件的那三種，文件名默認是**稿子的名字加上年月日時分秒**：`第一章.md` 存成
`第一章_20260906143012.png`，**放進下載文件夾**，不落在稿子旁邊。兩件事出於同一個
道理——圖是拍完就發出去、發完就忘的東西，没有理由在稿子的文件夾裏積灰，也没有理由
跟上一張同名。自己寫文件名（`:shot html 給編輯.html`）就照你寫的來，那時候撞了名字會
停下來告訴你，`:shot! html 給編輯.html` 才蓋。

`ambiguous_width = "auto"` 在截圖裏落到**窄**——`auto` 是問終端的，一張圖没有終端可以
問。這也是對的：圖是從畫布上一格一格讀出來的，而那塊畫布本身就是按窄算的。配置寫死
`wide` 的稿子，圖裏 `——` `……` `“ ”` 會和實際的終端一樣偏一格，這正是那個配置要處理的
問題本身。

## 三、模式

| 模式 | 怎麽進 | 做什麽 |
| --- | --- | --- |
| **Normal** | `Esc` | 移動、選擇、發命令 |
| **Insert** | `i` `a` `I` `A` `o` `O` `c` | 打字；輸入法在這裏工作 |
| **Command** | `:` | 發命令。命令名是 ASCII，**參數走輸入法**（`:e 第三章.md`） |
| **找命令** | 空行上再按 `:` | 説出你要做什麽，找出它叫什麽；輸入法在這裏工作 |
| **Search** | `/` `?` | 打搜索詞；輸入法在這裏工作 |
| **Ruby** | `空格 r`（或 `:ruby`） | 改注音；輸入法在這裏工作（見 5.5） |

光標形狀告訴你在哪個模式：Normal 是**方塊**，Insert 是**竪線**。竪排時那根線跟着文
字轉了九十度，變成一條横線。

**`Esc` 太遠的話，把 Caps Lock 換成它。** 一天要按幾百次的鍵，值得放在左手小指底下。
這件事 yumete 做不了——終端根本收不到 Caps Lock，那一鍵在到達任何程序之前就被系統
吃掉了——但系統做得了，一次設好，往後每個程序都算數：

> 系統設置 → 鍵盤 → 鍵盤快速鍵… → 變更鍵 → Caps Lock 鍵 → 選 `Escape`

大寫還要不要？要的話按住 Shift；真正需要鎖定大寫的中文寫作場合，一年也没幾次。

## 四、按鍵（Normal 模式）

前面加**數字**表示重複：`3w`、`10j`、`5>`。單獨的 `0` 不算數字前綴，留給别的用途。
**動的鍵可以要很大的數**——走到頭就自己停了；**改的鍵一次最多一萬遍**，多出來的不做，狀態行會説。

### 移動

| | |
| --- | --- |
| `h` `j` `k` `l` | 左／下／上／右，按字素和**屏幕上看見的那一行**走；`h` `l` 走得過行尾，接上一行／下一行 |
| `Esc` | 離開延伸模式，選區收回光標 |
| `w` `b` `e` | 下一詞首、上一詞首、詞尾 |
| `W` `B` `E` | 同上，但按空格分的「大詞」 |
| `f` `F` *c* | 找字符 *c*，向前或向後。**中文也打得**（見 `r`）。**没有 `t`**——那個字母整族給了表格 |
| `A-.` | 重複上一次 `f` |
| `C-w` `C-u`（Insert） | 退掉前面一個詞／退到行首 |
| `g/` `g?` | **這個詞還在哪裏**——選中的那段（或光標下的詞）在整份稿子裏。`/` 在這邊找，`?` 在另一個工作區給你看，你不動 |
| `n` `N` | 下一處／上一處。`Esc` 關掉的是那個窗，不是這次搜索：關了以後 `n` 走到下一處，窗自己回來 |
| `gj` `gk` | 上下一行——**就是 `j`／`k`**：這裏本來就走螢幕上的行（helix 的 `j`/`k` 走的是段落，所以那邊要分兩套） |
| `gJ` `gK` | 併下一行／併到上一行去 |
| `gd` | **去**它指着的地方：腳注的那條註、鏈接、`[[章節]]`、`[雪](#雪夜)`（`C-o` 回來）。⚠️ **普通正文上按它没有反應**——要問「這個詞還在哪裏」是 `g/` |
| `gD` | **看**同一個地方——在另一個工作區，你不動 |
| （兩個都一樣） | 腳注還没寫就先寫一條，`gd` 落在它末尾，打字即可 |
| `空格 w` | 另一個工作區：没開就開，開着就過去 |
| `空格 W` `空格 q` | 只留這一個／關掉這一個到另一個去 |
| `C-w` | 下一個區域：邊欄、正文、另一個工作區，没開的跳過 |
| `]c` `[c` | 下一處／上一處合併衝突（`:check-merge` 列出全部） |
| `Delete`（Insert） | 删光標**前面**那一個字（Backspace 的鏡像；行尾删的是換行） |
| `Home` `End` `C-a` `C-e`（Insert） | 行首／行尾——和 `:` 那一行同一套 |
| `J` `K` | 前進／後退**半頁**——最常按的一對，不該是和弦 |
| `C-d` `C-u` | 同上，Helix 原本的和弦 |
| `C-f` `C-b` | **整頁**——`PageDown`／`PageUp` 的和弦寫法 |
| `PageUp` `PageDown` | 整頁——鍵盤上本來就有的那兩個，Insert 裏也一樣 |
| `gg` `ge` | 文件開頭／最後一行；`10gg` 到第 10 行 |
| `G` | 最後一行；`30G`（或 `g30g`）到第 30 行 |
| （打一半的命令） | 右下角和光標旁邊都會顯示（旁邊那個歸 `:view-hud` 管）；`g` `t` `m` `空格` 還會彈出一張表 |
| `gn` `gp` | 切到下一個／上一個打開的文件 |
| `gf` | 打開本行寫的 `文件名:行號`（`:check-usage` 那幾張清單用這個跳） |
| `gx` | 跟着光標下的鏈接走（見「跟着鏈接走」）；Ctrl 點一下同樣 |
| `空格` | 打開菜單（見下）|
| `gh` `gl` `gs` | 行首／行尾／第一個非空白字符 |
| `Home` `End` | 行首／行尾 |
| `{` `}` | 上一段／下一段——**一段就是一個邏輯行**，空行跳過 |
| `M` *字母* | 把這個地方記下來，叫這個名字 |
| `'` *字母* | 回到那個地方（跨文件，文件會自己打開） |
| `C-o` `C-i` | 跳轉表：回到剛才那個位置／再往前 |
| `H` `L` | 上一句／下一句——斷在 。！？ 和它後面的 」）之後 |

`{` `}` 爲什麽需要：開了折行以後，`j` `k` 走的是**屏幕上的一行**，而一段話有二十行。
「下一段」這個動作於是没有鍵了。一段就是一個邏輯行——這不是這裏發明的定義，是編輯器
其他地方本來就在用的那個（折行、分詞緩存都以它爲單位），也正是中文稿子的寫法。

`H` `L` 斷句斷在「。」和跟在它後面的收尾符號**之後**：「不。」斷在 」 之後，不是之前。
半角句點只有後面跟着空白時才算句末，所以 `3.14` 不是一句話。這一段没有下一句了就走到
下一段的第一句。

**按不到的鍵會告訴你這裏叫什麽。** `$`、`^`、`@` 這些在别的編輯器裏有意思、在這裏
没綁的鍵，按下去不會没反應——它會在命令行説「行尾是 `gl`」。它**不會替你做**那件事：
這不是兼容層，是一本用得上的詞典。

### 修改

| | |
| --- | --- |
| `d` `c` | 删除／改寫選區 |
| `A-d` `A-c` | 同樣是删除／改寫，但**不動寄存器**——剛複製好的那一段還在 |
| `i` `a` | 在選區前／後插入 |
| `I` `A` | 在行首／行尾插入 |
| `o` `O` | 在下方／上方開新行 |
| `y` `p` `P` | 複製／向後粘貼／向前粘貼。**貼在哪，看你複製的是什麽**：複製的東西**不帶換行**（半句話、一個詞），就貼在光標蓋着的那個字後面，選了一段就貼在選區後面；複製的東西**帶着換行**（`xy` 複製整行就帶），就整行貼成下一行，不會插進别的行中間。`P` 一律是「前面」那一頭 |
| `R` | 用寄存器内容替換選區 |
| `r` *c* | 把選區每個字都寫成 *c*。**中文也打得**：按 `r` 就開候選面板，選中什麽就替換成什麽；上屏一個字是逐字填滿，上屏一個詞是整段換掉 |
| `"` *a* | 下一次複製／删除／粘貼使用寄存器 *a* |
| `Q` `q` | 録製宏／回放上一個宏——和 Helix 同一個方向 |
| `gJ` | 與下一行合併（兩個全角字之間不補空格） |
| `` ` `` | 字形組：`` `l `` 轉小寫、`` `u `` 轉大寫、`` `` `` 大小寫互換。Helix 花三個一級鍵做這件事，而它在漢字上什麽都不做，所以收成一組。`~` 照 vi 與 Helix 的意思，也是大小寫互換（``A-` `` 在這裏没有綁定） |
| `>` `<` | 選中的行增加／減少縮進 |
| `C-a` `C-x` | 光標處的數字加一／減一 |
| `u` `U` | 撤銷／重做 |
| `.` | **再做一次剛才那個改動**——`r`、`d`、`c…Esc`、`ms(`、粘貼，都算 |

### 搜索

**五個都是正則**，分别在「找哪裏」和「改不改」上：

| | 找哪裏 | 改 | 正則 |
| --- | --- | --- | --- |
| `/` `?` | 這個文件，往前／往後 | 否 | ✓ |
| `g/` `g?`（`*`） | 這個文件，找選中的那段 | 否 | ✗ 照原文 |
| `:s/舊/新/` | 選區那幾行（`:%s` 全篇） | 是 | ✓ |
| `空格 /` `:search-cd/-wd/-gd` | 這個文件，或整本書 | 否 | 面板，見「找一個字」 |
| `:replace-cd/-wd/-gd` | 同上 | 是 | 同一扇面板，多一行 |

改東西的只有兩條，而它們都要求你**先看見**：`:s` 之前有選區與 `n` 旗標，面板的 `r`／`R`
之前有一整張命中清單。全項目替換没有一步到位的寫法，這是有意的（見「七、日常」）。

`:s` 的行範圍與旗標見下面〈取代〉。`g/` 照原文找，所以標點和括號都不必轉義。

| | |
| --- | --- |
| `/` `?` | 向前／向後搜索——**這裏能打中文** |
| `n` `N` | 下一個／上一個匹配 |
| `g/` `g?` | 找選中的那段：這邊跳過去／那邊看 |

**`/` 一按，上次找的那個就以灰字寫在命令行上。** 直接 `Enter` 就是再找一次它，
`Tab` 把它變成真的打上去的字，而直接打字就是找新的——打到第一個和上次對不上的字，
那行灰字自己退場；退格删回去，它又回來。`?` 反着找，記的是同一個。

搜到的**那一段就是選區**——所以 `/她説` 之後直接 `c` 就是改掉「她説」。每個移動都留下
選區，搜索也不例外，否則它就成了唯一一個「按 `d` 删掉的不是屏幕上指着的那一段」的
移動。

**搜索和取代用的是正則表達式**，和 vi、Helix 一樣。校稿的一半工作是模式而不是字符串：

| | |
| --- | --- |
| `/第.+章` | 找章節標題 |
| `:%s/[他她]説/X/g` | 兩種寫法一起換 |
| `:%s/。/。\n/g` | 每個句號後面斷行，把一牆字拆成段 |
| `:%s/(.+)説道/$1説/g` | `$1` 是第一個捕獲組 |
| `:%s/！{2,}/！/g` | 連續的驚嘆號收成一個 |

**没有大寫字母的模式不分大小寫**，有一個大寫就分——和 Helix 的 smart case 一樣。
稿子是漢字，漢字没有大小寫，所以絶大多數搜索白拿這一條；稿子裏的西文多半是專名和
縮寫（`TODO`、`ISBN`、人名），而打出那個大寫就是「這個要照字面找」的意思。
一次性反過來寫 `(?-i)`（`/(?-i)todo` 只找小寫的），一直反過來寫
`[editor] smart_case = false`。

代價是 `.` `*` `(` `[` 有了含義——要找句點本身得寫 `\.`。替換串裏 `\n` `\t` 是換行
和製表符，`$$` 是一個真的錢號。`g/`（找選中的那段）走的是**原文**不是模式，所以選中
「（甲）」按 `g/` 找的就是「（甲）」。模式寫壞了會説是哪裏壞，而不是靜靜地換零處。

**分隔符是 `s` 後面的那一個字符**，和 vi、sed 一樣。模式裏本來就有 `/` 的時候——日期、
路徑、網址——換一個就好：

```
:s#2024/01#2025/02#          # 井號當分隔符
:s,docs/a.md,docs/b.md,      # 逗號也行
:s/2024\/01/2025\/02/        # 或者照 vi 那樣轉義
```

**改哪些行**寫在 `s` 前面：

| | |
| --- | --- |
| `:s/…` | 選區蓋到的那些行（没選就是光標這一行） |
| `:%s/…` | 整個文件 |
| `:1-40s/…` | 第 1 行到第 40 行，中間全算 |
| `:1,5,9s/…` | 就這三行，别的不動 |
| `:.-$s/…` | 從這一行到文件末尾（`.` 是這一行，`$` 是最後一行） |
| `:40s/…` | 就第 40 行 |

⚠️ **`-` 是一段，`,` 是幾行**，這是全編輯器同一條規矩（`t2-10/` 一連十欄、`t1,5,9s`
就那三欄，也是這麽讀的）。所以 vi 裏 `:1,40s` 是四十行，這裏是**兩行**——第 1 行和第
40 行。要那四十行寫 `:1-40s`。兩種混着寫（`:1-5,9s`）不猜，直接説「範圍要麽是一段，
要麽是幾行」。

**旗標**寫在最後：`g` 一行裏每一處都換（不寫就只換第一處），`i` 不分大小寫，**`c` 一
處一處問**（下面那一節），**`n` 只數，不改**——<!-- verbatim -->`:%s/裏/裡/n`<!-- verbatim --> 先告訴你有幾處。不認識的
旗標會被説出來，不會被默默吞掉。

**`f` 是「照字面」**：`.` `*` `(` `)` `?` `+` `[` `$` 這些字符在正則裏各有各的意思，
稿子裏卻常常就是它們本身。寫上 `f`，你打的每一個字符就只代表它自己：

```
:%s/(注)/（注）/gf        # 括號就是括號，不是分組
:%s/A.B/A・B/gf           # 點就是點，不match「A 任意字 B」
:%s/$5.00/$6.00/f         # 錢就是錢
```

⚠️ **`f` 兩邊都照字面**。左邊没有分組了，右邊的 `$1` 也就没有東西可指，所以 `$` 一律
當錢號。`\n`（換行）和 `\t`（Tab）還是照舊有效——命令行上按 Enter 是送出，那兩個字符
没有别的辦法打。

**`c` 是「一處一處問」**：不寫 `c`，`:%s` 一按 Enter 就全換完了；寫上 `c`，它停在第一
處，把那一處選給你看，狀態欄上寫着「「這個」→「那個」？」，等你按一個鍵：

| 按 | |
| --- | --- |
| `y` | 換這一處，跳到下一處 |
| `n` | 這一處不換，跳到下一處 |
| `a` | 剩下的全換，不再問 |
| `q` | 停手（`Esc` 一樣）——已經換掉的保留 |
| `l` | 換這一處，然後停 |

别的鍵按了不算數，問題還在那裏。走完會説「換了 N 處，跳過 M 處」。

⚠️ **整趟只算一步**——中途換掉的不管幾處，一個 `u` 全還原。一處都没換就按 `q` 的話，
`u` 撤的是你上一次的編輯，這一趟什麽都没留下。

`c` 和 `n` 一起寫的時候聽 `n` 的：`n` 什麽都不改，那是更安全的那一個。

`t` 是給表格的：一次取代要是讓某一行多出或少掉一格，平時會被攔下來（見「表格」那一節
的那道閘），寫上 `t` 就是説「我知道，照改」。

搜到的**那一段就是選區**——所以 `/她説` 之後直接 `c` 就是改掉「她説」。每個移動都留下
選區，搜索也不例外，否則它就成了唯一一個「按 `d` 删掉的不是屏幕上指着的那一段」的
移動。

| `mi` *c* | 選中 *c* 這對括號**裏面** |

### 所見即所得

`:render full` 之後，`**` `` ` `` `[]()` `[[]]` `%%` 這些標記從畫面上消失，只留它們框住
的字；`:render basic` 回到著色的源碼（默認就是源碼——**文件裏是什麽，畫面上就是什麽**）。

**選區碰到的每一個結構都是展開的**（不只是光標那一個——錨點也是文本裏的一個位置，
高亮如果比 `d` 實際删的少，就是畫面在謊報一次編輯會做什麽）。 這一條是整件事的地基，不是修飾：因爲它成立，所
以「光標絶不會在看不見的文字裏」，於是 `d`、`x`、`w` 動的仍然是源碼字符，而你眼前看
見的就是源碼。靠近一個結構它自己打開，離開它自己收起——站在它的邊界上仍然算在裏面，
不然光標一離開行就抖一下。

**標題的 `#` 不藏。** 終端没法把標題放大，井號是唯一説明「這是章還是節」的東西，而層 級是你的結構。列表符號、`:::` 那幾行同理——**行内的噪音藏起來，區塊的結構留着**。

所見即所得也會**排出注音**（注音是標記的一種）。不過只在竪排看得見效果：横排没有地方
放讀音那一欄，所以那裏仍然顯示原始標記。

一點還没做完的：横排的折行寬度目前按**源碼**算，所以標記多的行會比右邊界早一點折。竪
排没有這個問題（隱藏的標記本來就不佔格）。

### Markdown 還是 Typst

`.md` 就是 Markdown，`.typ` 就是 Typst——問題只在**什麽都没説**的文件，實際上就是
`.txt`。用 Typst 寫小説卻存成 `.txt` 是很平常的事，而當成 Markdown 讀，`#import` 會
變成標題、`*粗*` 什麽都不是。

所以這類文件**打開時猜一次**（不是每幀）。兩種語法的信號是**互斥**的，不是「不同」：
`#let` `#import` `#show` `#set` 只可能是 Typst；`**粗**` 只可能是 Markdown（Typst 用單
個 `*`）；行首 `= ` 是 Typst 標題，行首 `# ` 是 Markdown 標題——Typst 的 `#` 後面必須跟
標識符，`# 第一章` 根本不合法。

**兩邊都湊不够證據的，就是純文本。** 一個 `.txt` 在説出自己是什麽之前是小説：當成
Markdown 讀，稿子裏自己約定的 `*` 和 `#` 會在頁面上一閃一閃，`空格 c` 會往一個没有註釋的文件
裏寫 `<!-- -->`，而 `第三章` 那條大綱會讓位給一個這個文件從没用過的 `#` 規則。門檻是
**一個強信號，或者兩個弱的**：標題和 Typst 關鍵字各自算強，`**`、圍欄、鏈接、行首 `//`
各算半個——兩百行裏只出現一次，那是散文碰巧含了這個字符，出現兩次纔是習慣。

但**最靠譜的是寫進配置**，因爲讀文件不一定判斷得出來：一章如果通篇只有散文，裏面根本
没有 Typst 可找。項目目録的 `.yumete/config.toml` 裏：

```toml
[syntax]
txt = "typst"                # 這個項目裏的 .txt 都是 Typst
"筆記.txt" = "markdown"       # ……除了這一個
```

確切文件名優先於擴展名，所以「我的 .txt 都是 Typst，除了那一個」説得出來。另外，從一個
Typst 文件按 `gf` 跳進 `#include` 的章節，那個章節**繼承** Typst——被引進一本 Typst 書
裏的章節就是 Typst，不管它叫什麽、裏面有什麽。

`:syntax typst` 可以臨時推翻，`:syntax` 不帶參數就説現在是哪個；命令行上
`yumete --syntax typst 稿子.txt` 是同一句話，它比擴展名和配置都大——你已經知道裏面是
什麽了，就没有什麽可猜的。

**`:syntax text` 是「没有標記」**：文件裏的每個字符都只是它自己。有人拿 `*` 當分場、拿
`#` 寫給自己看的批註，那不是 Markdown，按 Markdown 上色只會讓自己的標點在頁面上一閃
一閃。這種稿子寫 `text`（配置裏也可以：`"日記.txt" = "text"`）。

Typst 那邊認得 `= 標題`、`*粗*`、`_斜_`、`` `碼` ``、`$數學$`、`//` 註釋，以及
`#import` `#let` `#show` `#set` 和 `#chapter[…]` 這類調用。

**Typst 的代碼永遠不會被隱藏**，即使在所見即所得下——`**` 是圍着文字的裝飾，可以拿走；
`#chapter[初雪]` 是**産生**那一章的指令，藏掉它畫面就在説謊。它只是調暗。

`#import "ch01.typ"` 和 `#include` 那幾行，`gf` 可以**直接跳過去**（相對於引用它的那個
文件解析，和 Typst 自己一樣）。大綱邊欄還會把 `#include` 的那些文件**讀開**，列出裏面
的章名而不是文件名——一個把章節引進來的主文件，本身就是目録（見 5.4）。

### Markdown 著色

`**年**` 裏的「年」會**加粗**，而 `**` **仍然留在畫面上**——這是稿子，不是預覽；你要
看得見文件裏到底有什麽。標記本身調暗，讀起來是腳手架；它框住的字往前站。標題、
`` `碼` ``、`~~删~~`、`*斜*`、`[文字](目標)` 同理。`:render off` 關掉著色。

**横排竪排一樣。** 竪排以前只做隱藏、不上色，等於 所見即所得 只做了一半；現在
三層（塊底色、行内著色、選區）在兩個方向上是同一套。

認得的語法：

| | |
| --- | --- |
| `# 標題` | 六級 |
| `**粗**` `*斜*` `~~删~~` `==高亮==` | 高亮是底色，像熒光筆留下的 |
| `` `碼` `` | 裏面的標記一律不算標記 |
| `[文字](目標)` `[[第三章]]` `[[第三章｜那一夜]]` | 外鏈與内部引用 |
| `[^1]` 與 `[^1]: …` | 腳註號與它的正文 |
| `%%給自己的話%%` `<!-- -->` | 批注：**不是書的一部分**，設得很靠後，但從不隱藏 |
| `> 引文` | 整塊有底色 |
| `- 項` `1. 項` `- [ ]` `- [x]` | 列表與任務 |
| `---` `***` | 分隔線（場景轉換） |
| ` ``` ` | 代碼塊，裏面一律不當標記 |
| 文件開頭 `---` … `---` | 頁首元數據 |
| `::: tip/info/warning/danger` … `:::` | 整塊有自己的底色，四個框四個品色（見九） |
| `\| 甲 \| 乙 \|` | 表格行 |

**列表自己接下去。** 在 `- `、`* `、`+ `、`1. `、`> `、`- [ ] ` 開頭的一行按
`Enter`，下一行自動帶同樣的記號：縮進照抄，號碼加一，勾選框一律空的——下一件事還没
做。記號打完**一個字都没打**時再按一次 `Enter`，那一行清空，列表就到此爲止。
`-` 後面没有空格不算列表（那是還没打完的破折號），`|` 開頭的表格行也不算。
上面已經寫好的號碼不重排：重排一張列表是有人特意下的令，不是敲回車順手做掉的事。

**引用打一半，`Tab` 接完。** 在正文裏打 `[^`，本文件已有的腳注標號就列在下面，每條旁邊是那
條註的頭一句；最後一條是**還没人用的號碼**，選它就是開一條新註。打 `](#` 列的是本文件的章節，
寫成 Markdown 讀得懂的錨點（空格換成連字號，標點去掉）。打 `[[` 列的是**手邊那一疊文件**，
見下。`Tab` 換下一條，`Shift-Tab` 往回，
選中的那一條**當場寫進正文**，右邊的括號也一併補上（自己已經打了幾個就補剩下幾個）。
面板自己開，但**不按 `Tab` 就一個字都不動**——整個標號手打出來，裏面不會混進編輯器的猜測。
别的鍵原樣：`Enter` 還是換行，`Esc` 還是出插入模式，不在引用上的 `Tab` 還是製表符。

**`[[` 列的是手邊那一疊。** 掃的是**這個文件所在的文件夾，連同它的子目録**——不是整本書。
一本書的稿子、資料、舊稿、導出物常在同一棵樹下，往上取一層就把幾百個不相干的文件名倒進面板
裏，而 `[[` 要的是「近處那幾十個」。（`空格 /` 的搜索**有意不同**：那是「在整本書裏找一個
字」。）打的字同時比整條路徑和文件名，所以打 `雨` 就找得到 `卷二/雨夜`，不必先打文件夾；
右邊那一欄注着它在哪個文件夾；這個文件自己不列。

⚠️ 寫進去的是**篇名**，不是文件名——`[[卷二/雨夜]]`，没有後綴。後綴是這本書的事（見上面
「跟着鏈接走」那一節），你不必打，`gx` 跟過去的時候它自己補。

**區塊和行内是兩層，會合成。** 區塊染整行的底（`::: warning` 的底色横貫整行，不只在
字底下），行内出墨色和字重——所以 `::: warning` 裏的粗體字**兩樣都有**，不是二選一。

區塊那一層不能逐行判斷：三段之前開的一個 ``` 圍欄決定了這一行是不是代碼。所以它是從
文件**頂端順序掃**的——但只讀每行開頭的 64 個字符，而且**每次編輯算一遍**（不是每幀），
六十萬字的稿子一次 1.5 毫秒、一幀 0.6 微秒。逐字符的行内解析仍然是逐段緩存的。

圍欄和 `:::` 都**認得自己是誰開的**：`~~~` 不會關掉 ``` 開的塊，`::: tip` 不會關掉它
所在的 `::: warning`。代碼塊和頁首元數據裏**一切都不是標記**——那裏寫的就是那裏的字，
給 `**` 上色（更别説把它藏起來）等於謊報文件的内容。

這裏没有用 `pulldown-cmark` 之類的庫，是有原因的：一是它們**整篇**解析，而這裏每次按
鍵都要重畫（這個編輯器已經爲 O(全文) 栽過三次）；這裏是**逐段**解析並按段落文本哈希
緩存，和分詞、折行共用同一套。二是 CommonMark 的強調規則建立在西文的空格分詞上，
`中**文**中` 這類在各家實現裏長期出問題——這裏不受那套規則約束。三是渲染器的設計目標
是把標記**吃掉**，而我們要的正好相反。

#### 跟着鏈接走

`gx` 打開光標下面那個鏈接——vim 和 Helix 把「打開光標下這個東西」放在同一個鍵上。
**Ctrl 點一下**是同一件事，用鼠標説。光標在鏈接的哪一段都算數：文字、方括號、
所見即所得 藏起來的那個目標，都是這個鏈接。

三種去處，各走各的路：

| 寫的是 | 去哪裏 |
| --- | --- |
| `[宇浩](https://yuhao.forfudan.com)` | 交給系統的瀏覽器 |
| `[下一章](02.md)`、`[[第三章]]` | **在這個窗口裏打開**，成爲一個緩衝區 |
| `[雪](#雪)`、`[[第三章#雪]]` | 跳到那個標題（先開那一篇，再跳） |

`[[第三章]]` 是**篇名**，不是文件名：後綴是這本書的事，不用你再打一遍——它先找
`第三章` 加上當前文件的後綴，再找 `第三章.md`。`[[第三章｜那一夜]]` 竪杠後面是
「這裏怎麽稱呼它」，去的仍然是 `第三章`。相對路徑是**照鏈接所在的那個目録**算的：
一章的鄰居是它在磁盤上的鄰居。

**只有 `http` 和 `https` 交給系統。** `mailto:`、`obsidian:`、以及任何别的協議，
一律**説出來、不執行**。理由很直接：稿子是會從郵件裏來的文件，而 `open` 會啓動任何
一個聲稱認得某個協議的程序。絶對路徑（`/etc/…`）同樣不跟——那不是這本書裏的一篇。
另外，交給系統的那一步從頭到尾**不經過 shell**：網址是作爲一個參數遞給
`open`／`xdg-open` 的，没有任何地方拼過命令行。

### 想寫多長

`[editor] ruler = 80` 之後，**超過第 80 欄的部分底色不同**。這在開着折行時照樣有用：
它説的不是「這裏斷行」，而是「這一行已經超過你想要的長度了」——有些人開着折行，但仍然
想手工把長句斷開，這個視覺就是給那件事的。

**關掉折行時**（`:view-wrap off`，比如手工折行寫 Markdown）除了變色還多一條豎線，因爲那時
行長真的是你決定的。開着折行不畫線——變色的邊界本身就是那條線，再畫一條是把同一件事
説兩遍。

竪排没有這個：縱是往下跑的，限制它的是 `zong_length`，而每一縱都在那裏結束——那條「線」
已經是文字塊的下邊緣了。竪排對應的是**稿紙刻度**（見 5.2）。

**`:view-wrap 50` 更進一步：它不只是畫條線，是真的把稿子寫窄。** 行在第 50 欄折，第 50 欄
右邊那一整塊——不管那一行有没有寫到那裏——是另一種底色。這就是「紙」和「紙以外」：

```
那年冬天，山下起了大雪。          ▓▓▓▓▓▓▓▓▓▓▓
雪一直下到開春。                  ▓▓▓▓▓▓▓▓▓▓▓
```

在很寬的顯示器上，這是把一欄寫作區放在窗口左邊，而不是讓一句話横跨 200 欄——眼睛從行
尾回到下一行行首要走的那段距離，超過一定寬度就開始丢行。

`:view-wrap 0` 把窗口還回來。單獨的 `:view-wrap` 還是老意思——開折行——不動尺度。窗口比尺度窄
的時候窗口説了算：折不下的行讀不了。

**竪排也認這條命令**：`:view-wrap 40` 就是**一縱四十字**。横排的尺度是行寬，竪排的尺度是
縱長，是同一件事的兩個方向。

想每次都這樣，寫進 `config.toml`：`[editor] measure = 50`。`ruler` 只畫，`measure`
真的折。

### 首行縮進

中文的段落是**縮進兩格**開頭的，不是空一行——空行是 Markdown 説「這裏換段」的辦法，
在屏幕上它還白白佔掉一整行（竪排是一整縱）。

```
:indent full         每段開頭縮兩格，段間那個空行從頁面上撤掉
:indent basic        縮進照畫，空行留着
:indent off          不縮
:indent 2            縮幾格是另一個問題：改寬度，不動撤不撤空行
:indent-hint none    那兩格上什麽都不畫（默認）
:indent-hint color   那兩格帶一條淡底
:indent-hint symbol  第一格畫一個記號
[editor] indent = 2
[editor] indent_hint = "symbol"
[editor] indent_symbol = "↵"
```

**這是「看」，不是「改」。** 文件裏那個空行一個字都没動——它得留着，否則導出來就變成
一段了。縮進是排版層畫出來的：竪排用的是**空格子**（和一條長注音爲自己讓出來的那種格子
是同一個東西），所以光標永遠不會停在縮進裏，鼠標點不到那裏，也不會有一個「文件裏没有
的字」出現在你可以編輯的地方。

**`:indent full` 之下，段落之間那個空行會從頁面上撤掉**——條件是這一段已經被**别的方式**
標出來了：横排是縮進，**竪排永遠是**，因爲換段本來就是換一縱，空行是把同一件事説第二遍，
而在竪排説第二遍要花掉整整一縱的閲讀面積。一段話用縮進標，
還是用空行標，排版上只能選一樣——兩樣都上是没有人做的事。文件照舊留着空行，行號也照舊
是文件自己的號，所以頁面上會看見 1、3、5：**跳號本身就是那個空行還在的憑據**。

**光標所在的那一段，按文件本來的樣子畫**：不縮進，而且它上面那個空行畫回來。這樣「這裏
到底有没有空行」永遠不必猜——你站在哪一段，哪一段就是原文。代價很小：**同時只有一個空行
是展開的**，所以從一段走到下一段是關掉一個、打開一個，下面的頁面不會跟着動。

另外兩種空行也不撤：**連着兩行以上的空行**（寫了第二行的人是有意的，那是分場），以及
**代碼圍欄和文件頭裏的空行**（那裏的空行是内容，不是段落之間的縫）。`j`／`k`、`h`／`l` 都會跨過撤掉的那一行——頁面上没有的行，
光標不停在上面。

**那兩格默認是白的**，書上就是這麽印的；一個每段都出現的記號，讀三頁眼睛就不看它了。
真要在編輯的時候看見，`:indent-hint color`（淡底）或 `:indent-hint symbol`（第一格畫
一個 `↵`——它替掉的正是一個換行）。

以 `#` `=` `-` `*` `+` `>` `|` `` ` `` `~` 開頭的行**不縮進**——標題、列表、引文、
表格、代碼圍欄自己帶了開頭的結構，把它們往右推是在説一件不成立的事。`[^1]:`（腳註正文）
也不縮，但以 `[` 開頭的普通段落照縮——一段話當然可以從一個鏈接開始。本來就縮進了的行
也不再加。

`:view-dense` **不會**把它關掉。注音、旁置、刻度各佔一**欄**，那是密排要贏回來的東西；縮進
佔的是一段開頭的兩格，而且它正是密排的頁面上唯一還在説「這裏換段了」的東西——它替掉的
那個空行，本來要佔整整一縱。

### 段組：把頁面横着分成兩條

一縱五十個字讀起來是累的——眼睛從一縱的底回到下一縱的頂，那一趟太長。日文竪排的傳統
答案不是把字調小，是**把頁面横着切開**：上半頁從右讀到左，讀完再從下半頁的右邊接着讀。
報紙和文庫本都是這樣排的。

終端是個又寬又矮的形狀——那正好就是段組要對付的形狀。

```
:view-bands 2      分成上下兩條
:view-bands off    整頁一縱到底
[editor] bands = 2
```

**每一條就是一個獨立的短頁面**：自己的縱長、自己的段號行、自己從右往左填。條與條**一樣
高**，因爲頁面是被分的，不是被裝滿的——下面那條永遠不會比上面那條矮一行。閲讀順序還是
那一串縱，段組只決定它們被放在哪裏，所以 `hjkl`、翻頁、鼠標點選全都照舊。

窗口矮到一條裝不下一個縱的時候，它自己退回一條。

**只對竪排有效。** 横排的對應物是 Emacs 的 `follow-mode`（一段文字流過並排的幾欄），
那是另一件事，還没做。

### 密排

**密排是默認的。** 想要注音欄、句讀旁置的邊欄和稿紙刻度回來，`:view-dense off`（或者
`[editor] dense = false`）。

`:view-dense` 把竪排的頁面壓到終端能給的最緊——**只管竪排**：横排的注音是上面多一行，不佔
寬度，没有什麽可以省的，所以密排開着也照排。

| 拿掉的 | 省下 |
|---|---|
| 縱與縱之間的間隔（`zong_gap`） | 每縱 1 欄 |
| 注音欄 | 有注音的縱各 1 欄 |
| 句讀旁置的邊欄 | 有句讀的縱各 1 欄 |
| 稿紙刻度 | 每縱 1 欄 |

之後**一縱就是兩格**——正好一個漢字，終端能畫的最窄。`:view-dense off` 還原**你原來的**
配置，不是默認值：本來就關着注音的人，關掉密排不會發現它自己開了。

**首行縮進不在拿掉之列。** 上面那四樣各佔一**欄**，那是密排要贏回來的東西；縮進佔的是
一段開頭的兩格，而且它正是密排的頁面上唯一還在説「這裏換段了」的東西。

**字本身没法變窄。** 終端的格子是終端定的，yumete 只能決定用幾格。想要 90% 寬的
字身（更瘦長的縱），那是終端的配置，各家名字不同——Ghostty 是 `adjust-cell-width`，
kitty 是 `modify_font cell_width 90%`，WezTerm 是 `cell_width = 0.9`。改了之後整個
終端都會變瘦，横排和狀態欄也一樣。

### 跑一條命令：`:sh` 和 `:!`

兩個動詞，因爲有兩種情况，各有各的對的答案。

**`:sh wc -w ch01.md`** 想要的是一個**數字**，而且想要它**在文字所在的地方**——所以輸出
被收回來，開成一個緩衝區（和 `:check-usage` 的清單放在同一種地方）。可以搜、可以複製、可以
一邊寫一邊留着。`git log`、`typst compile`、`pandoc` 都是這一類。

**`:!make`** 想要的是**看着它跑**——帶顔色，帶進度條，可能還要問你一句話。捕獲的管道
做不到這三件事的任何一件。所以編輯器**讓開**：離開備用屏幕，把終端還給那條命令，跑完
之後印一行「按任意鍵回到 yumete」。

> 所以你問的「在哪裏看到它跑」——**就在你啟動 yumete 的那個終端裏**。`:!` 期間 yumete
> 整個從畫面上讓開，回來的時候再把畫面接管回去。這是 vi 從一開始就是這麽做的，也是唯一
> 誠實的答案。

命令走你的 `$SHELL -c`，所以管道和通配符都算數：`:sh wc -w *.md | sort -n` 是一條命令，
不是被拆開的幾個詞。

**第三種：`!`——把選中的字送出去，用送回來的換掉它。**

「pipe」就是 Unix 的管道：選中的那段文字**餵進**一條命令的輸入，那條命令**吐出來**的
東西，換掉原來那段。原文出去，結果回來，就地替換。

```
那年 冬 天        ← 選中這一行
!                 命令行變成 :pipe ▊
tr -d ' ' ⏎       tr -d ' ' 是「删掉所有空格」
那年冬天          ← 換好了
u                 一次撤銷，字回來
```

`tr -d ' '` 不是 yumete 的東西，是你系統上本來就有的一條命令。`!` 的用處就是**把你系統
上所有的命令都變成 yumete 的編輯命令**：

| 打什麽 | 選中的那段會變成 |
|---|---|
| `tr -d ' '` | 删掉所有空格 |
| `LC_ALL=C sort` | 按碼位排序（拆分表就是這樣排的） |
| `nl` | 每行前面加上行號 |
| `tail -r` | 行的順序倒過來 |
| `python3 -c '…'` | 你當場寫的任何處理 |

**排中文要小心 `sort`。** 它按你的 locale 排，不是按筆畫也不是按拼音；而且在
`en_US.UTF-8` 下 `sort -u` 會把「木」和「目」當成同一個而删掉一個。要按碼位排就寫
`LC_ALL=C sort`。

`!` 只是把動詞先替你打好——它不是第二套機制，而且**按錯了看得見它要幹什麽**，Esc 就退。
換行結尾跟着原來那段走：原來没有換行就不加，原來有就保留，不會把兩行黏成一行。

**命令失敗了不會動你的字。** 打錯一個 flag（`tr -D ' '` 而不是 `-d`）是常事，那條命令
吐出來的是一段錯誤信息——把段落換成錯誤信息，是一次没人要求過的編輯，能不能撤銷是另一
回事。所以只有命令説自己成功了（退出碼 0）才替換，否則原文一個字不動，狀態欄告訴你它
抱怨了什麽：

```
没有動你的字：tr: illegal option -- D
```

成功但有警告的，字照換，警告也照説。

順帶：`:sh` 相反——那裏 stderr 和 stdout 一起收進緩衝區，因爲在那裏它們**合起來才是
「發生了什麽」**，而且它没有在編輯你的文字。

### `:view-preview`：交給真正的排版器

`:render full` 是**這個畫面**顯示多少結果；`:view-preview` 是**真的那一份**——由做這本書的
工具做出來，在能顯示一本書的地方顯示。兩個不同的問題，兩個不同的詞。

| 文件 | `:view-preview` 做什麽 |
|---|---|
| Typst | 起 `tinymist preview`，把它開出來的地址交給瀏覽器。你在 yumete 裏改，瀏覽器裏跟着變 |
| Markdown | 導出一份 HTML 到臨時文件，交給瀏覽器 |

`:view-preview off` 停掉；退出 yumete 也會停掉——它是爲這次會話起的，没有理由在之後還佔着
一個端口。

**這不是一個終端面板。** 預覽服務器要説的話只有一行——地址——之後它就是個該被放着不管
的進程。給它一塊面板，等於在本來是稿子的地方看日誌滚動，還要爲此在 yumete 裏裝一個
終端模擬器——而 yumete 本來就跑在一個終端裏面。所以它是一個**任務**：一個句柄、一個
地址、一個停止的方法。

### 輸入法要自己開

yume 的數據裏有兩樣東西，它們該有不同的待遇。

**語言模型**——詞頻表和詞彙表，兩張都**與方案無關**——是 `w` `b` `e` 走詞用的東西，也是
這個編輯器的詞跳轉比一個編輯器有理由做到的更準的原因。**27 毫秒，每個人都有。**

**碼表**是另外 109 毫秒，而且只對來打宇浩的人有用。給所有人載入，等於每次啟動都替一個
多數人没要求過的輸入法買單。所以它**等你開口**：

```
:yume-scheme          用配置裏那個方案（默認靈明）
:yume-scheme riyue    指定一個
:yume-s l             一樣——不會有第二個詞的前綴就算數
```

前綴到哪一層都算：`s` 是 `:yume` 唯一以 s 開頭的詞，`l` 是唯一以 l 開頭的方案。有兩個
詞都能匹配的話它**兩個都不選**，而不是悄悄挑先寫的那個。

**什麽都没裝也能打字。** 每個 yumete 二進制都帶着一份靈明碼表：

- 編譯那台機器**裝了宇浩**，寫進去的就是完整那一份（3.69 MB ＋ 符號表）。`scripts/build.sh`
  先裝數據再編譯，所以它做出來的就是這種。完整的那份不放在倉庫裏——二進制文件不做 delta，
  提交一次倉庫就從 1 MB 漲到 4 MB，每更新一次再漲一次。
- **没裝**（CI，也就是發布包的來處），寫進去的是**靈明精華版**，0.25 MB。它收 CJK 基本區
  與擴展A**全部的字**、宇浩字根區、七張字集裏落在區外的字，各源都收，加上簡碼與符號表；
  **不收詞**，所以整句輸入退成逐字。面板上它報「出廠自帶 精華版 ⋯⋯」，跟完整那份分得開。
- **兩份都没有**（一台從没裝過宇浩的機器上 `cargo build`），就不帶碼表，面板照實説。

⚠️ **這些表一個都不在 yumete 的倉庫裏。** 它們是生成物——碼表從宇浩的 `ling.txt` 裁、
分詞詞表從它的語言模型裁——而生成物每換一版就整份重寫，提交進 git 等於每次再付一份全額。
所以它們是**建構時的輸入**：發布流水線從 `forfudan/yume-release` 的 `yumete-data` 那一頁
下載（公開，不用 token），`scripts/build.sh` 在你自己的機器上生成。配方在
`scripts/make_jinghua.py` 與 `scripts/make_words.py`。

裝好的碼表**優先**——出廠這一份是後備。其餘四個方案不帶，没裝就是老實地不可用，而不是
悄悄變成靈明。

**去哪裏找**：先是你自己指的（`[ime] data_dirs`、`$YUMETE_DATA_DIR`），然後是 yumete
自己的數據目録（`scripts/build.sh` 裝在這裏；`brew install yume-data` 也落在這裏，
`<yumete 執行檔>/../../share/yumete`），最後是 **yume 自己裝在哪裏**——每個平台按那個
平台的規矩：

- **macOS**：`~/Library/Application Support/Yume/data/compiled/`（重編過的那一份在最前
  面）、`~/Library/Application Support/Yume/`，然後是輸入法自己那個 App：
  `~/Library/Input Methods/Yume.app/Contents/Resources`（只裝給自己的）和
  `/Library/Input Methods/Yume.app/Contents/Resources`（裝給全機器的）。
- **Windows**：`%APPDATA%\Yume\data\compiled\`、`%APPDATA%\Yume\`，以及 `.exe`
  旁邊的 `Resources\`。
- **Linux**：`$XDG_DATA_HOME/yume/data/compiled/`、`$XDG_DATA_HOME/yume/`，`$YUME_DATADIR`，
  以及 `$XDG_DATA_DIRS` 裏每一個的 `yume/`（沒有設這個變量就照標準的預設看
  `/usr/local/share` 與 `/usr/share`——裝給全機器的那一份就在那裏）。

裝了 yume 的 macOS 上因此不用配置任何東西：`:yume-scheme` 直接就有那五個方案。（在
2026-09-07 之前它只認 Linux 那一套路徑，於是一台裝好裝滿的 Mac 一個方案都找不到。）

**自己造的方案也一樣掃得到。** 出廠那幾個方案是 `schemes/<名字>.toml` 一個文件一個；用戶
自己裝的則各佔一個**槽位**——`…/Yume/installed/<八位十六進制>/`，一格一個方案，裏面是
`custom.ytab`（碼表）、`custom.yzg`（字根）、`custom.ycdv`（這個方案自己的拆分）和
`custom.yscm`（這個方案自己的設置）。掃到一格就多一個方案，名字是方案作者寫在
`custom.yscm` 裏的那個：

```
:yume-scheme custom.6947b838      冰雪清韻
:yume-scheme custom.cc2d1290      天碼
```

碼長、選重鍵、頂不頂功**不猜**——照 `custom.yscm` 辦，跟輸入法裏是同一份。槽位另外兩個
位置也認（Windows 的 `data/custom/`、方案管理之前的裸 `custom/`），同一格只算一次。

**問一句現在用的是哪一個：**

```
:yume                 靈明 · 碼表 /Users/…/.local/share/yumete/schemes/ling.ytab · 拆分 關
:yume-builtin         改用出廠自帶那一份（裝的那份壞了、或者比它舊的時候）
```

出廠那一份會**説自己有多舊**——`出廠自帶 2026-08-28 13:08`，取自宇夢發佈包裏 `VERSION`
的構建時間；自己編譯的數據没有那個文件，就報碼表本身的日期。編進二進制的碼表是一張
**快照**，看到一個不認識的候選時，你該先知道這張快照有多舊，再去宇浩那邊找 bug。

（只報時間不報版本號：問題是「這有多舊」，而「3.12.0」要你先記得那是什麽時候。）

**裝了卻没用上的文件，`:yume` 也會説。** 二進制格式跟着 yume-core 走，換過格式之後舊的
數據目録看上去一切正常——文件都在，只是核心一個都不收，於是拆分注解整批消失而哪裏都
不提。現在那句話會接在後面：

```
靈明 · 碼表 …/ling.ytab · 拆分 開 · 上屏 延遲（頂字）
  · data/chaifen.ydiv 核心不認：bad division magic（期望 YDV20260904，文件頭是 YDV20260828）
```

看見這個就重跑一次 `scripts/build.sh`。**没裝的文件不算**——清單裏一半本來就是可選的，
真列出來反而把要緊的那一行埋了。

一直要打字的人寫進配置：

```toml
[ime]
scheme = "lingming"
start = true          # 啟動就載入碼表
```

啟動因此是**即時的**——`yumete --version` 和 `yumete -p 章節.md` 都是 0.00 秒。

### 命令：只記動詞，不記參數

打 `:` 列出全部命令，打幾個字母narrow下去——這是原來就有的。新的是：**打一個空格，它
就告訴你後面可以接什麽**。

```
:view-dense ▊          on 開   off 關
:syntax ▊         markdown 「#」標題、「**粗**」   typst 「=」標題、「#import」
:yume ▊           on 開   abc 暫時打英文   off 關（子命令見 :yume-scheme 那一族）
:ruby-html ▊      on 開   off 關
```

`Tab` 在這些詞之間輪換，補的是**你正在打的那一個詞**，不是整行。

**括號裏是最短的寫法**，而且它是**算出來的**：

```
:yume (y)     :render (ren)     :table (ta)     scheme (s)     format (f)
```

**名字是代號的那幾行，後面跟着灰色的備注。** 方案是唯一這樣的一組——yume 裝進去的方案
按槽位取名，一列十六進制看不出誰是誰：

```
scheme custom.6947b838   冰雪清韻
scheme custom.cc2d1290   天碼
scheme lingming          靈明
```

打進去的仍然是**代號**（名字會變、會撞，槽位不會），備注只管讓你認出是哪一個——**而且
它搜得到**：`:yume-scheme ` 之後點一下 Shift 切中文，打「冰雪」就只剩那一條。其餘的行
没有備注：`on` 旁邊再寫一次「on」是噪音，而高亮那一行的説明本來就在底下那條。

**`:` 和 `/` 這一行可以編輯。** `←` `→` 走，`Home` `End` 兩頭，`C-w` 退一個詞，
`C-u` 退整行，`Delete` 删光標下那一個字，`↑` `↓` 翻你這一次會話裏打過的——`:` 和 `/` 各有各的一份。長長一條
`:%s` 打錯一個字，不用退回去重打。

規則一句話：**不重複的前綴就算數**，命令和參數都一樣。`:y` 就是 `:yume`——一族的頭不會
和自己底下的命令撞——`:yume-s l` 就是 `:yume-scheme lingming`。前綴撞了兩個詞就**兩個都不選**——`:re` 同時是 `recover`、
`redo`、`render` 的前綴，所以它報「不認識」，而不是悄悄挑一個。

已經宣告的短名**勝過**前綴規則，所以你熟的拼法不會變意思：`w` 是三個命令的前綴，但
`:w` 仍然是 `write`；`:e` 仍然是打開文件，不是 `export`。

括號裏那個是**算的不是寫死的**，所以以後加一個和它撞的命令，這個提示會在**同一次修改
裏**自己變長，不會留下一個教你打錯的短名。

**「父命令」不是另一套機制。** `:yume-scheme` 就是一個「取值恰好是動詞」的參數——所以
實現一次參數補全，命令歸類就白撿了：没有第二條代碼路徑要維護，也没有第二樣東西要你
學。想多深就多深（`:ruby-format html` 是三層），補全並不知道有什麽區别。

歸類只在**真的存在一組**的地方做，而且**舊名字直接删掉**——留着兩套拼法，等於這條哲學
只是嘴上説説：

| 現在 | 没有了 |
|---|---|
| `:yume-scheme 靈明` `:yume-chaifen` | `:scheme` `:chaifen` `:cf` |
| `:ruby full/off` `:ruby-html on` `:ruby-format typst` | `:ruby-on` `:ruby-off` `:render-ruby-html` … |
| `:layout vertical` | `:vertical` `:horizontal` |
| `:view-wrap off` | `:nowrap` |
| `:render off/basic/full` | `:markup` `:wysiwyg` `:source` |
| `:buffer` `:buffer-next/previous/close` | `:buffers` `:ls` `:bd` |
| `:clipboard-yank/paste` | `:cy` `:cp` |
| `:view-wrap/dense/bands/sentence/hanging/numbers/typewriter/focus/meter/punct/hud/preview` | `:wrap` `:dense` `:bands` `:sentence` `:hanging` `:numbers` `:typewriter` `:focus` `:meter` `:note` `:hud` `:preview` |
| `:count-progress` `:count-target 3000` | `:progress` `:prog` `:target` |
| `:write-all` `:write-as 新名.md` | `:wall` `:saveas` `:sav` |
| `:table-jump 木` `:table-find column 甲` | `:row` `:search`（⚠️ `:search` 後來又活了，見下） |
| `:check-merge` | `:conflicts` |
| `:buffer-close` | `:bclose` |
| `:theme-mode system/dark/light` | `:appearance` |

判斷的標準是一句話：**這個名字是「一件事」，還是「某件事的一個取值」？** `vertical` 是
`layout` 的取值，`ruby-on` 是 `ruby` 的取值，`nowrap` 是 `wrap` 的取值——取值不配有自己
的命令名。而 `:w` `:q` `:e` `:s` `:toc` 各自就是一件事，名字又短，硬歸類只會更糟。

**歸了類，名字要重新起。** 舊名字得自己扛全部意思，所以它們長：`conflicts` `search`
`row` `note`。歸到父親底下之後，那個名詞已經由父親説了，孩子只剩下**動詞**那一半：

⚠️ **`:search` 後來又活過來了**：它讓給 `:table-find` 之後空了一陣，現在是高級搜索面板
的命令（#419）——同一個字，完全不同的一件事。`:replace` 也是：從前是「把剛才 `:grep`
找到的都換掉」，現在是那扇面板多一行。

| 現在 | 從前 | 父親已經説了 |
|---|---|---|
| `:check-merge` | `:conflicts` | check ＝ 查什麽有没有問題 |
| `:table-find` | `:search`（那個名字現在另有主人） | table ＝ 在表格裏 |
| `:table-jump` | `:row` | table ＝ 表格的行 |
| `:view-punct` | `:note` | view ＝ 只是怎麽看，不動字 |

`:table search` 讀起來是「表格搜索」，`:table-find` 讀起來是「在表格裏找」——後者纔是
你要做的事。`:view note` 更糟：它像「看筆記」，而那條命令是把標點畫成淡的。

**打舊名字，它會告訴你新的在哪。** `:dense` 不再是命令，可是打下去不會只説「不認識」：

```
:dense
没有「dense」這個命令；你要的是 `:view-dense`
```

這句話是**算出來的**——掃一遍命令樹，找名字對得上的孩子。所以以後再摺一次，指路的話
自己就對了，不用有人記得回來改。算不出來的只有「改了名」的那幾條——上表四條，
加上 `:bclose`→`:buffer-close`、`:wall`→`:write-all`、`:saveas`→`:write-as`、
`:appearance`→`:theme`——因爲 `conflicts` 這個詞在樹裏已經不存在了，另記一張表。

### 短寫

完整命令是摺過的，説得出它做什麽；**短寫是它的首字母，别的都不是**——`:bc` 有，
`:bclose` 没有，因爲那既不是完整的名字也不是首字母，正是摺疊要去掉的那種拼法。

**連字號分兩種用法**：一種是**樹**——`:buffer-close` 是 buffer 的一種、`:write-all` 是
寫的一種，菜單一層層點得進去。另一種是**並列**——`:write-quit` 不是「一種寫法」，是
「寫，然後退」，兩個動詞。

⚠️ **兩種都用連字號，都不用空格。** `:write` 後面跟的是**路徑**，所以 `:write all`
只能在「一個子命令」和「一個叫 `all` 的文件」之間猜——它從前猜的是後者，真在當前目録
寫出一個叫 `all` 的文件，而别的改過的緩衝區一個都没存。現在它會説「没有「write all」這個命令，
它寫作 `:write-all`」。
真要一個叫 `all` 的文件就寫 `:write ./all`。

| 短寫 | 就是 |
| --- | --- |
| `:bc` `:bn` `:bp` | `:buffer-close` `:buffer-next` `:buffer-previous` |
| `:qa` | `:quit-all` |
| `:wa` | `:write-all` |
| `:wq` | `:write-quit` |
| `:x` `:xit` | `:exit` |
| `:up` | `:update` |
| `:y` | `:yume` ＝ 開中文——一族的頭，兩個鍵 |

短寫只是**展開**：`:bc!` 就是 `:buffer-close!`，長命令以後長出什麽，短寫一樣拿得到。
補全也照這條走——打 `:wq` 提示的是 `write quit`，因爲那纔是説得出意思的那個拼法。

**`:wysiwyg` 這個詞也没了。** 它和 `:markup` 本來就是同一根軸上的三檔——代碼裏
`wysiwyg && show_markup` 早就承認了這一點：不著色的時候「把標記藏起來」没有意義，那不是
把標記收起來，是把「這裏本來是粗體」這件事**扔掉**。所以合成一個：

| | |
|---|---|
| `:render off` | 原文，不著色 |
| `:render basic` | 著色，標記留在畫面上（默認） |
| `:render full` | 標記拿掉，只在光標那一處展開（所見即所得） |

三個值一根軸，第四種組合在類型上就不存在了。

上一次這麽做（方案、注音、横竖、著色）命令從 42 個減到 26 個；2026-09-08 又摺了一次，
21 個名字進了 7 個父命令（`view` `check` `table` `count` `write` `buffer` `theme`），
**那一次**把頂層從 61 個減到 41 個。編輯器這期間長出來的功能比摺掉的名字還多——
**摺的是名字，不是功能**，而且摺完之後還會接着長：今天頂層是多少，按一下 `:` 看面板
右下角那個 `1/n` 就知道，這裏不寫死一個會過期的數。

### 整棵樹

上面説的是**怎麽記**，這一節是**查**：一級命令在外，二級命令縮進一格，再深一層的取值
跟在 `｜` 後面。同一份東西 `:help commands` 會開成一個可以搜的緩衝區，`::` 則按「做什麽」
找——這裏是給眼睛從頭掃一遍用的。

`（括號）` 裏是宣告的别名；最短的打法是**算出來的**，`:` 那一行自己會告訴你。

- `:open`（o／e／edit） — 打開一個文件
- `:new`（enew） — 開一個空的緩衝區
- `:write`（w） — 保存；給路徑存一份副本，`:write-as` 纔換過去
  - `all` — 存下所有改過的文件
  - `as` 路徑 — 另存成新文件並改編輯它（`:w <文件名>` 只抄一份，人還在這邊）
- `:wq`（x） — 存好再退出
- `:recover` — 載入搶救稿；加 ! 是丢掉它
- `:reload` — 把文件再讀一遍；加 ! 是丢掉你這裏的改動
- `:reload-auto` ｜ `on` `off` — 文件在外面改了就自己重讀——你這裏有改動時只提醒，不動手
- `:readonly`（ro） ｜ `on` `off` — 只讀：鎖住這一份，不許改
- `:goto`（g） — 跳到某一行（`:42` 就够了）
- `:count`（wc） — 寫了多少字
- `:count-progress` — 寫作進度：今天寫了多少，離目標還有多少
- `:count-target` <字數>｜off — 每天要寫多少字；`:count-target off` 不再算
- `:check-usage` — 查用字：全文寫了兩種寫法的<!-- verbatim -->（裏／裡、為／爲、你自己配的人名）<!-- verbatim -->，列出少數那一邊
- `:check-charset` — 查字集：不在通用規範／臺灣／香港／古籍裏的字，排版社的字體多半也没有
- `:check-merge` — 列出這份文件裏的合併衝突
- `:check-punct` — 查標點：中文裏的半角逗號句號、`...`、還有開了口没收尾的「」（）《》
- `:convert` — 簡繁轉換：交給 opencc 跑，:convert 看能走哪幾條路
  - `s` t｜tw｜hk｜c｜g [force] — 簡體（说 为 内 吴 里 发 台）
  - `t` s｜tw｜hk｜jp｜c｜g — opencc 繁體，<!-- verbatim -->港臺字形（說 爲 內 吳 裏 髮 臺）<!-- verbatim -->
  - `tw` s｜t｜c｜g [force] — <!-- verbatim -->臺灣正體（說 為 內 吳 裡 髮 臺）<!-- verbatim -->
  - `hk` s｜t｜c｜g [force] — 香港繁體（説 爲 内 吴 裏 髮 台）
  - `jp` t｜c｜g — 日本新字体（説 爲 内 呉 裏 髪 台）
  - `c` s｜t｜tw｜hk｜jp｜g — 大陸通規繁體（説 爲 内 吴 裏 髮 臺）
  - `g` s｜t｜tw｜hk｜jp｜c — <!-- verbatim -->古籍通規繁體（説 爲 内 吳 裏 髮 臺）<!-- verbatim -->
  - `opencc` ｜ `install` `update` — opencc 本身：没裝就裝，裝了就升級
- `:quit`（q） — 關掉這一個文件；只剩一個時纔真的退出（`quit!` 不管改動）
- `:quit-all`（`:qa`） — 全部退出，開着幾個都走（`:quit-all!` 不管改動）
- `:undo`（u） — 撤銷上一次改動
- `:redo`（red） — 重做
- `:word`（wd） — 分詞：哪一份詞表、著色、粒度
  - `show` ｜ `on` `off` `tint` `ink` — 分詞著色
  - `list` ｜ `reload` `edit` `global` — 詞表：用哪一份、重讀、編輯
  - `level` ｜ `strict` `balanced` `full` — 分詞粒度：多少個字算一個詞
  - `discover` — 挖出本書自己的詞：人名地名，字典裏没有的
  - `habit` — 口頭禪：這一篇比别人多説的那些詞
- `:layout`（lay） — 横排竪排互換
  - `vertical` — 竪排，縱從右往左
  - `horizontal` — 横排
- `:theme` — 主題：用哪一套墨（深淺在 `:theme-mode`）
  - `system` — 跟終端的底色走
  - `dark` — 深色
  - `light` — 淺色
  - `ink` ｜ `system` `dark` `light` — 墨香：黑墨、白金墨、金墨、紅墨，其餘的色階都算出來
  - `bw` ｜ `system` `dark` `light` — 黑白：只有黑、白和灰——輕重説話，顔色不説
  - `cyanotype` ｜ `system` `dark` `light` — 藍曬：普魯士藍的地、白線的字——十套裏唯一底色真帶飽和色的一套
  - `amber` ｜ `system` `dark` `light` — 琥珀：整頁只有一種顔色
  - `mogao` ｜ `system` `dark` `light` — 莫高：墨是壁畫氧化之後真正變成的褐黑；金不是金色，是石緑——洞窟自己的礦物
  - `morandi` ｜ `system` `dark` `light` — 莫蘭迪：十套裏最低的正文對比、最灰的地

### `::`：忘了名字就説它是做什麽的

前一節整節都建立在一件事上：**你記得那個動詞**。可是這些動詞是英文的，而你想的是
「竖排模式」。打不出來的命令等於没有。

**再按一次 `:`**（空行上），那一行就從「命令叫什麽」變成「命令做什麽」：

```
::竖排           → :layout vertical    把整頁轉成竖排，一行一行從右往左
::排序           → :table-sort         照這幾欄排
::lyt            → :layout             横排還是竖排
```

- **中文直接打。** 這一行開着輸入法（單按一下 Shift 切中文，跟 `/` 搜索一樣），
  因爲它本來就是給中文問句用的。
- **三種語言一起找，只顯示你在用的那一種。** 説明本來就寫了繁、簡、英三份。你用繁體
  版打「竖排」（簡體）也找得到，你只記得英文名也找得到。
- **打不全也行。** `lyt` 找得到 `layout`，`tbsort` 找得到 `table sort`——字母是**順序**
  對上就算，不必連着。手滑打成 `laoyut` 也還在（只對**命令名**，只對三個字母以上的英文，容錯兩個字母）。
- **`↑` `↓` 挑，`⇥` 選中。**

**`⇥` 不執行任何東西**，它把整條命令**寫回 `:` 那一行**，光標放在後面，然後你自己按
Enter。所以 Enter 跑的永遠是你**看得見的那一行**，不是它猜的東西——`:q!` 是不能撤銷的。

`::` 和 `:` 是兩個模式，可以互相走：空行上第二個 `:` 進去，退格退空了就回 `:`，
`Esc` 一次回正文。

**説明之外還有一層看不見的詞。** 每條命令在 `messages.toml` 裏可以寫一行
`find = "直排 縱書 tategaki columns"`——搜得到，但不顯示。所以説明可以寫得短，而
「同一件事的另外四種説法」照樣找得着。加一個説法就是加一個詞，不用動代碼。

### 折行

横排時一段太寬會**折到下一行**接着排。中文一個自然段常常就是一整行幾百字，不折就得
一路往右捲纔讀得完，所以默認是開的；`:view-wrap off` 關掉，`:view-wrap` 開回來。

關掉之後一段就是**一整行**，多長算多長，頁面跟着光標左右走——`gl` 走到行尾，窗口就跟
過去。行號欄不動，它是家具不是正文。**竪排没有這一項**：一縱斷在窗口高度上，`:view-wrap
off` 在那邊會直接告訴你這條命令只管横排（`:view-wrap 40` 兩邊都算數，見第五章）。

折行處遵兩條規矩：拉丁詞不從中間斷開（`Helix` 不會拆成 `Hel` 和 `ix`），行首不出現
。、」）這類收句的標點，行尾不出現「（這類開頭的括號——也就是**禁則處理**。

一段剛好排滿一行時，下面會多出一個空行：那是給光標站的。行尾之後的那一格在屏幕上不
存在，總得有地方放下一個字。

要緊的是 `j` `k` 走的是**屏幕上的那一行**，不是整個自然段。段落幾百字時，按邏輯行
移動的 `j` 一下就跳過整屏，那不是讀者眼睛所在的地方。行號只標在段落的**第一行**：
號碼是段落的號碼，逐行重複反而像是好幾段。

## 五、竪排（縱書）

`:layout vertical`，或 `yumete -v`，或配置裏 `layout = "vertical"`。

文字從上往下走，一條一條的**縱**從右往左排。「縱」就是竪排裏的「行」——之所以另起
一個名字，是因爲在這裏「行」和「列」各有兩個意思。一個段落會軟折成若干縱，默認**窗口能給
多長就多長**——一縱多長是關於這本書的決定，編輯器没資格替你做。`:view-wrap 32` 或
`[editor] zong_length = 32` 是你自己下的那個決定（32 字前後是散文舒服的上限）。

### 5.1 移動

`h j k l` 保持**屏幕方向**的意思。`j`、`k` 順著縱往下讀、往上讀，也就是文本的前進和
後退；`h`、`l` 換到左邊、右邊那一縱。長段落從一縱的底部自動接到下一縱的頂部，不用你
管。

**鼠標滚輪**翻頁：一格滚三縱。爲此 yumete 接管了鼠標，所以終端自帶的拖選複製需要按
住修飾鍵（macOS 上是 Option）——Helix 也是這麽取捨的。

狀態欄寫的是 `横 55, 縱 1, 字 20`：段落是横著往左排的，所以段號是個**横**向位置；
**縱**是這段的第幾縱；**字**是在這一縱裏往下第幾個。

### 5.2 版面自動做的事

`[editor] paper_ticks = 10` 會在邊欄上每十個字點一個淡刻度，像真的稿紙——傳統稿紙是
有格子的（20×20 = 400 字），寫作者靠它估篇幅，而竪排版面本來就是字格，這是它免費拿得
到、横排編輯器没有等價物的東西。刻度讓位給注音和旁置的標點（那兩樣有意義，刻度只是引
導視線）。開啓會給每一縱都留出邊欄，整頁因此往左退一格。

段落號那一條有自己的**底色**。别的編輯器靠**位置**把行號和正文分開——行號在一條專用
的欄裏，正文永遠進不去，所以再暗也不會被誤讀。竪排時號碼在縱的**正上方**、佔的是正
文同一列，位置分不開，只剩顔色可分；那條帶的底色是色階上的一格（見「主題」）。

狀態欄的座標是**兩個數**：「横 56-2, 字 23」——第 56 段的第 2 縱，往下第 23 個字。
段落不够長、只佔一縱時就只寫「横 56」。

- **標點會轉向**：`。`→`︒`、`「」`→`﹁﹂`、`《》`→`︽︾`、`——`→`︱︱`。只在屏幕上
  轉，文件裏還是原來的字符。
- **半角字符一行一個**，靠格子右邊，這樣拉丁字母和數字會沿著漢字右側排成一條線。想
  讓一對半角字擠進一格（**縦中横**），開 `[editor] tatechuyoko = true`。
- **字體很要緊。** 轉向後的標點是 U+FE10–FE48，思源／Noto CJK、更紗黑體、霞鶩文楷
  等寬都有，純拉丁的編程字體没有。

### 5.3 標點旁置

`:view-hanging`（單寫是反過來，`:view-hanging on`／`:view-hanging off` 是説死），或配置裏
`hanging_punctuation = true`。

古籍的排法裏，。，、？！：；「」 不佔一格，而是掛在它所屬的字旁邊，正文一路連下去
不斷——這樣一頁對話才不會看起來有一半是空的。

```
   關閉       開啟
   子         子
   曰         曰:
   ︓         學｢
   ﹁         而
   學         時
   而         之,
```

掛出去的標點用的是**半角形**——`。`→`｡`、`、`→`､`、`「」`→`｢｣`，其餘借 ASCII 的
`,?!:;()`。這不是將就：邊欄只有一格寬，全角的 `︒` 塞進去會壓到右邊那一縱、把那個字
整個蓋掉；把邊欄加寬到兩格則是每一縱都多佔一格，正好抵消了旁置本來要省的東西。而且
從版式上説，句讀本來就是寫在字右邊的**小**符號。

`《》【】〔〕『』` 没有半角形，所以**不掛**，照舊在正文佔一格——書名號比句號少得多，
而一頁之中邊欄寬度忽寬忽窄就不成其爲邊欄了。破折號和省略號同樣佔格：「——」是一條貫
穿的全角横線，塞進半角邊欄就斷了。

**開括號**掛在它引出的那個字旁邊，其餘的掛在它跟隨的那個字旁邊——即使那個字在一組注
音裏面（`「<ruby>漢…`）。

**連着兩個標點就不掛了，兩個擠進正文的一格**：`。」` 是 `｡｣`，一格兩欄，各佔一欄。這
是印刷的做法——JLREQ §3.1.4① 和 clreq §6.3.2.2 都説句點類後面接終止括號類要**去掉之
間的空**，而句讀和括號本來就是半角字身，兩個正好合成一格；clreq §6.1.3 從另一頭説了同
一件事：**連續標點不作懸掛**。中文對話稿的句尾差不多都是 `。」`，從前那裏第二個標點在
邊欄自成一行、正文那一格空着，讀起來就是一路上一個接一個的洞。

一個標點照舊掛——省下的地方本來就在那裏。`「冬」` 這種不算連續：`「` 是掛在它**引出**
的那個字前面的，把它拉出來就成了「冬「」」。

標點和注音搶同一個邊欄，**標點優先**——標點本來就該在它那個字的那一行——所以兩者同
時出現時，注音往上讓，佔據這個字上方的幾行。

### 5.4 注音（振假名／ruby）

注音以標記形式寫在文件裏，由 yumete **排出來**：基字被撑開對著它的注音（所以相鄰兩
個注音不會撞在一起），注音走在該縱右側那個半角格子裏。

標記不是 yumete 自創的。兩種都認，可以同時開，默認按文件後綴決定：

| 方言 | 寫法 |
| --- | --- |
| `html` | `<ruby>口<rt>kǒu</rt></ruby>` —— Markdown、HTML |
| `typst` | `#ruby("口", "kǒu")` —— Typst |

| | |
| --- | --- |
| `:ruby full` / `:ruby basic` / `:ruby off` | 排出注音／認得讀音但標記留在畫面上／源碼 |
| `:ruby-html` | 也讀 HTML 注音（`:ruby-html off` 停止） |
| `:ruby-typst` | 也讀 Typst 注音（`:ruby-typst off` 停止） |
| `:ruby-format html` | 把全篇注音改寫成 HTML |
| `:ruby-format typst` | 改寫成 Typst |
| `:ruby-auto` | 按詞把讀音注上去（見 5.6） |
| `:ruby-auto rare` | 只注生僻字 |

**改寫跳過代碼**：``` 圍欄裏的注音標記與文件頭的 front matter 原樣留着。講注音的書寫的
就是這種例子，而一本書裏最需要 `:ruby-format` 的正是它。

**横排也排注音了**：放在那一行**上面**的一行裏，落在它所注的那個字的欄位上。只有**有
注音的那一行**才多佔一行——一段話裏注了一個字，不會把整本書變成雙倍行距。兩個注音如果
會撞在一起，後一個**不畫**（而不是擠着畫）：注錯了字的注音比没有注音更糟。

竪排仍然是把注音放在該縱右側那個半角格子裏，基字撑開對着它——那是縱書本來的做法，也是
兩個注音永遠不會相撞的排法。

讀音可以是**全角**的——注音符號（ㄩㄥˇ）、日文假名——這時注音欄自動變成兩格寬，整頁
一致。以前寫死一格，每出現一個全角讀音，後面所有的縱就往左推一格，整頁階梯狀崩塌；
而這個功能本來就叫「振假名」。拼音是半角，仍然只佔一格（除非你把
`ambiguous_width` 設成 `wide` 而讀音裏有帶調母音，那也是兩格——因爲終端就是那麽畫
的）。

### 5.5 Ruby 模式

注音排出來以後，`<rt>` 根本不在屏幕上，光標走不進去。**`空格 r`**（命令行寫法是
`:ruby`）在狀態欄開一行專門改它：

- **光標在已有注音上**——載入現有讀音，直接改。
- **有選區**——空著，你打什麽就給它注什麽。
- **提交空的讀音就是取消注音**，連標記一起去掉。所以在這個模式裏退格退到空**不會**
  離開（跟搜索行不同），空的狀態必須能到達；退出用 `Esc`。
- **輸入法在這裏能用**，因爲讀音可能是假名或拼音。

**爲什麽是二級鍵。** 一頁裏注不了幾個，而且不必按下去就發生——一級鍵留給非立刻不可
的事（`r` 就是：見 `docs/development.md` §5.1）。

讀音裏用 `|` 分成和基字數目相同的幾段，就是逐字注音：`hàn|zì` 給 漢字 注出兩組；
`hàn zì` 則是整個詞一個注音。

### 5.6 自動注音：`:ruby-auto`

一個字一個字注是注不完的。`:ruby-auto` 把選中的那一段——没有選區就是整份稿子——按詞
走一遍，查得到讀音的就注上去，寫成這份文件本來的那種方言（`.typ` 出 Typst，别的出
HTML）。注了幾個詞狀態欄會説；不要就 `u`，一步全退回去。

**按詞，不是按字。** 了 在 爲了 裏是 `le`，在 了解 裏是 `liǎo`。一個字一個字查的工具
必然錯一半——Word 的「拼音指南」就是這麽錯的，所以没人用第二次。yumete 問的是宇夢的
讀音表，**問的是整個詞**，多音字由它所在的詞定下來。查不到讀音的詞原樣留着，不猜。

**已經注過的不動。** 你手改過的那個讀音，不會被這條命令蓋掉。

**同一個拼法只差聲調的分不出來。** 爲 在 認爲 裏是 `wéi`、在 爲了 裏是 `wèi`，可讀音表
本身不帶調（`ren wei`），所以這一類——爲、難（`nán`／`nàn`）、好、教、中——一律取常用的
那一個，可能要你手改。差在拼法上的（了、行、和、長）没有這個問題。

**你真正想要的多半是 `:ruby-auto rare`。** 每個字都有讀音的小説是課本，不是小説；只在
真正生僻的那幾個字上有讀音的小説纔讀得完。`rare` 只注**四套現行字集都没收**的字——大陸
的通用規範、通規繁、臺灣、香港，四套裏任何一套有它就不注；只有古籍字表有的、四套都没
有的纔注。就是讀者真會卡住的那些。

    :ruby-auto rare        整份稿子，只注生僻字
    :ruby-auto             選中的那一段，全注

讀音來自宇夢的**拆分表**（`:yume-scheme` 載進來的那一份）。没載的時候這條命令什麽也不
做，只在狀態欄説一句。

### 5.7 着重號

漢字不會斜。西文強調靠字母往右倒，漢字没有這回事——中文的強調是**在每個字旁邊點一個
點**，叫着重號，竪排時點在字的右邊。所以 yumete 竪排時就把 `*這樣*` 畫成着重號：

```
   一
   個·
   詞·
   而
   已
```

不需要新語法：`*字*` 本來就是 `<em>`，而 `<em>` 在中文裏的樣子**就是**着重號。`**粗**`
不點——那是另一種字重，兩樣都點的話半頁都是點。

點畫在邊欄裏，和注音、旁置的句讀、稿紙刻度同一欄，**排在最後**：有注音或者有掛出去的
標點，那一格歸它們。邊欄是**排版時買下來的**，和注音一樣：哪一段有強調，那一段的縱右邊
就留一格——所以密排（`:view-dense`、縱間距 0）也照樣點得出來，只是那一縱會往左讓一格。没有強
調的段落一格都不多花。`:render off` 時不點，那時候 `*` 是字面上的星號。

### 5.8 一句一縱：`:view-sentence`

校對的時候句子要一句一句地看。老辦法是 `:%s/。/。\n/g` 把稿子劈開，看完再撤銷——**這
是拿改文件當看法用**，撤銷少按一次就寫進去了。

`:view-sentence` 是同一件事，但**一個字都不動**：打開它，竪排就在每個句號、問號、嘆號、
省略號之後起新的一縱。

```
:view-sentence        一句一縱
:view-sentence off    回去
```

一句太長就照常換行——一縱裝不下的句子仍然接着往下一縱走，只是**下一句一定另起**。
句末的引號跟着句號走：`「你回來了。」` 是一句，收尾那個 `」` 不會被甩到下一縱去。

斷句用的就是 `(` `)` 兩個動作跳的那條界——你看見的縱頭，正是按 `)` 會停的地方。

它只是竪排的一個看法，跟 `:view-dense`、`:view-bands` 一樣：文件没有變，`:w` 存下去的還是原來
那一段。

### 5.9 平仄：`:view-meter`

寫舊體詩、填詞的時候，平仄是靠耳朵一個字一個字數的。`:view-meter` 把它畫出來——用的就是詞譜
自己那套記號，畫在注音和着重號共用的那一欄裏：

```
   春○
   眠○
   不●
   覺○
   曉▲
```

`○` 平，`●` 仄；句末那個字換成三角——`△` 平韻、`▲` 仄韻——因爲韻腳落在那裏。横排時
這一欄變成字上面那一行，位置對着每個字。

```
:view-meter        開
:view-meter off    關
```

**⚠️ 這是今音平仄，入聲是它會説謊的地方。** 調類是從現代漢語拼音讀出來的，因爲數據裏
只有這個。中古音的入聲派進了現代的四個聲調（入派三聲），所以 `竹` zhú、`白` bái、
`石` shí 這些字**在規則裏是仄，在這一欄裏是平**。拆分表裏没有中古音那一欄可查，從拼音
也推不回去——那個信息已經不在了。

按**中華新韻**寫，這一欄就是對的；按**平水韻**寫，它是頭一遍，把三聲四聲那一半的錯挑
出來，另一半它不出聲——知道它是這個形狀，就還是值得開着。

輕聲不畫。它既不平也不仄，舊體詩裏本來也没有這件事。

平仄從**詞**查起而不是從字查起（`了` 在「爲了」是 `le`，在「了解」是 `liǎo`），所以
它跟 `:ruby-auto` 讀的是同一份數據、走的是同一條路：**没裝拆分表就查不到**，那時候
`:view-meter` 會直説，而不是畫一欄空的給你。

那一欄有注音或者有掛出去的標點時，讓給它們——注音是文件裏寫着的東西，平仄是編輯器在
一旁説話。着重號排在平仄後面。

### 5.10 標點寫錯了就在旁邊寫上：`:view-punct`

`:check-punct` 給的是一張清單，要跳過去看。`:view-punct` 換一個做法：**該寫的那個標點，就
寫在寫錯的那個旁邊**，當場看見，不用離開這一段。

```
他説,，好          横排：逗號寫在半角逗號後面
```

```
:view-punct         開
:view-punct off     關
```

竪排也一樣——它跟着 `,` 一起轉過來，畫在那一格裏。**它跟正文不是一個顔色**：正文是
正文的墨色，它是編輯器指東西用的那個色，一眼分得開。

**它不是文件裏的字。** 光標永遠停不到它上面，`x` 删不掉它，`:w` 存下去的還是你寫的
那一段——它跟輸入法的候選、表格對齊用的補白是同一路東西，只是排版時借了幾格地方。改對了那個標點，它自己就没了。

**只看一行之内看得出來的那兩樣**：半角標點、`...`。少一個 `」` 它不説——**一行看不
見下一段**，而跨段的引文本來就是每段重開一個「（見 `:check-punct`）。那一樣仍舊歸
`:check-punct` 管。

`:render off` 的時候不畫。那個模式是「把文件原樣給我看」，多畫一個字就不是原樣了。
代碼塊、圍欄裏面也不畫，那裏的 `,` 本來就是對的。

## 六、輸入法

宇夢引擎是嵌進來的——没有 FFI，没有另一個進程。Insert 模式下打編碼就出候選框。

**三個狀態，兩個開關。** 外面那個是 `:yume on`／`:yume off`：yume 接管鍵盤，還是把鍵盤
整個交還給系統——系統自己的輸入法要用的正是「交還」那一個。**單獨輕點 Shift** 是裏面那
個：接管着的時候，在 中文 和 ABC 之間切。

| 狀態 | 怎麽進去 | 底下那行寫什麽 |
| --- | --- | --- |
| 中文 | `:yume on`／輕點 Shift（從 ABC） | `[靈明]` |
| ABC | 輕點 Shift／`:yume abc` | `[ABC]` |
| 關 | `:yume off` | 什麽都不寫 |

**那個記號任何模式都在。** 從前它只畫在真的在組字的地方——Insert、`/`、`:` 的參數——
於是 Normal 模式下看不出下一次按 `i` 會掉進中文還是 ABC，只能打錯了纔知道。現在狀態行
一直寫着它。窄到六十欄的時候先讓路的是光標底下那個字的讀數（`冬 U+51AC · CJK…` 縮成
`U+51AC`），不是它——那個字本來就在頁面上看得見。

ABC 和「關」在鍵盤上看起來一樣——按鍵都打它自己——**差别在 yume 還在不在**，而這個差别
是實的：下面那段説爲什麽。

**外面那個開關没有快捷鍵，是有意的。** 試過的兩個都退了回來：`C-Space` 被 macOS 花掉兩
次（Spotlight、切換輸入源），根本到不了終端；`Shift+空格` 在多數輸入法裏是全／半角，而
yume 「關」着的時候鍵盤正在系統那個輸入法手上——最要緊的那個方向（關→開）恰恰按不動。
寫字的人一直在按的是裏面那個（輕點 Shift），它不佔鍵位；外面那個一天按不了一次，值不起
一個鍵。

| | |
| --- | --- |
| 空格 / `1`–`9` | 選中候選 |
| `-` / `=` | 上一頁／下一頁 |
| 退格 | 修改編碼 |
| Esc | 取消這次輸入 |
| Tab | `bare` 下召出候選框，管這一個詞 |

**輕點 Shift 要終端報得出「單獨按下的那一個 Shift」**，而按 Kitty 鍵盤協議，這件事
只有一個開關管得着（`REPORT_ALL_KEYS_AS_ESCAPE_CODES`）——偏偏同一個開關會讓**系統輸入
法組不了字**：上屏出來一排空格。兩件事要的是同一個開關，所以 yumete 只在 **yume 接管着
鍵盤的時候**推上去，一交還就撤掉。這就是「ABC」和「關」爲什麽必須是兩個狀態。

終端要支持 Kitty 鍵盤協議：Ghostty、kitty、WezTerm、foot、Alacritty、Konsole 都行。
Apple Terminal 報不出單獨的 Shift——**啓動時會説一句**，不會讓你按半天纔發現。那裏中／
ABC 按 **`Ctrl+^`**（`[editor] language_key`，`"off"` 是不要這個鍵），它問的是與輕點
Shift 同一個問題，所以在 yume 裏把 Shift 改綁成别的，這個鍵也跟着改；三個狀態仍舊隨時
可以用 `:yume on|abc|off` 進。

⚠️ 舊終端把 `Ctrl+^` 與 `Ctrl+6` 送成同一個字節，分不出來——所以那兩個名字在
`language_key` 裏是同一個鍵。

**哪些地方能打中文：** Insert、搜索（`/`）、Ruby、`::` 命令查找、選擇器（`空格 f`、
`空格 b`），以及**在等一個字的那幾個鍵**——`f`、`F`、`r`、`mi`、`ma`、`ms`、`mr`。`:` 命令行只在**參數**那一段能打——命令名全是 ASCII，光標退回名字上就又
不能打了。

**打開一行提示都先把組字結清**，因爲那一行上没有東西可以把它打完。`:` 和 `::` 還會
**借走** Insert 的中／英：那兩行開頭要打的是命令名，`:layout` 剛寫完中文就打會被一個
字母一個字母吃掉，所以它們一律從 ABC 開起，出來的時候把 Insert 原來那一邊還回去。
`/`、Ruby 和選擇器**不借**——搜索詞和 `第三章.md` 本來就多半是中文，硬轉 ABC 等於把
它們的用處拿走。命令行上輕點 Shift 只改那一行；要改 Insert 的，回 Insert 再點。

**候選框**在竪排下用宇夢的**墨香**深色皮膚。候選用 ㊀㊁㊂ 編號，從右往左排，方向和
它即將加入的文字一致；已打的編碼順著最右一列往下讀，每個候選還差的鍵（下標）順著它
自己那一列往下讀。

`;` 和 `'` 是**選二、選三**——這是方案的綁定表決定的，不是 yumete 自己定的，所以自
定義碼表把 `-` 拿去當編碼鍵時，`-` 就還給碼表。組字中的方向鍵、Tab、Home/End 一律不
漏給編輯器（漏了的話光標會被移走而編碼還在，之後上屏的字就落在别處）——Tab 在 `bare`
下另有用處，見下面「空空如也」。打了一串死碼時候選框**不會消失**，裏面就剩你打的那
幾個字母——不然你不知道要退幾格。

`:yume-chaifen` 打開高亮候選的**二重注解**（拆分＋編碼）；單寫是反過來，
`:yume-chaifen on`／`off` 是説死。

**上屏方式**用 `:yume-commit delayed|unique|fluency`（不寫模式就是問現在是哪一個）：

- **`delayed`** 延遲上屏（頂字）——碼成立了先等着，下一鍵拼不成碼時纔把前面那段頂上去。
- **`unique`** 唯一上屏（也可以寫 `auto`）——碼成立而且只有一個候選，直接上屏。
- **`fluency`** 整句——一路打下去，空格確認整句，從不自己上屏。

三個名字是 yume 自己的（`CommitStrategy`），三層合成也在 yume 的核心裏做，所以這裏選的
那一個，在 macOS／Windows 的輸入法面板裏是同一件事。選了以後**換方案不會丢**；只有拼音
例外——它没有碼表可以逐段查，永遠是整句，命令會直接説出來而不是假裝設上了。配置文件的
`[ime] commit` 是同一個設置，不寫就交給輸入法自己按方案定。

注意 `:yume-c` 現在同時像 `chaifen` 和 `commit`，兩個都不算——`:yume-ch` 與 `:yume-co`
各自明確（打 `:yume-c`，菜單會把兩個都列出來）。

**換方案**用 `:yume-scheme lingming|xingchen|qingyun|riyue|pinyin`，或者配置文件的
`[ime] scheme`。yumete 自帶靈明（編進二進制）；其餘四個方案的碼表跟 yume 一樣，從
yuhao-assess-data 下載後裝進數據目録（yume 的 `scripts/build.sh` 會裝）。碼表不在機器
上時它會説清楚是「没裝」而不是「没這個方案」，並且留在原來能用的方案上。用戶自己裝進
yume 的方案跟着一起列出來，名字是 `custom.<八位>`（見上面「自己造的方案也一樣掃得到」）。

**用你自己的碼表**：

```
:yume-table ~/.yumete/wubi86.dict.yaml
```

**Rime 的 `.dict.yaml` 直接能用**——五筆、倉頡、粤拼、朙月拼音，下載下來就打得了，
不用轉格式：yume-core 的碼表讀取會自動認出 YAML 文件頭並掐掉，也會自動判斷是
`字<TAB>碼` 還是 `碼<TAB>字`、是空格分隔還是製表符分隔。手寫的兩列文本文件一樣能用。

語言層（詞頻、詞彙）還是從裝好的數據裏來——換的是**拼法**，不是語言。

**指錯了文件，它會説。** 一條碼、一個詞最多 255 字節——這是編出來的碼表能裝下的長度，
超過的那一行放不進去，載入之前就整行丢掉，回話後面接一句「跳過 N 條過長的」。真碼表兩側
都没有這麽長的東西，所以看見這句話，多半是路徑指到了别的文件。一行都不剩的，它會直接説
「讀不出碼表」。

### 空空如也——把候選框收起來

`:yume-panel full|bare`（不寫模式就是問現在是哪一個）：

- **`full`** 候選框——光標旁邊那張帶框的表，一直以來的樣子。
- **`bare`** 行内預覽——**首選直接畫在正文裏**，光標停在它末尾；已打的編碼畫在光標下
  面那一行（下面擠不下就往上一行，再擠不下就只剩狀態欄右端那一份）。候選框一個都不
  畫，**`Tab` 把它召出來**，管這一個詞，詞上了屏它就跟着走。

宇夢自己的輸入法面板已經有一張完整的候選框了；寫小説的這張紙上不需要第二張。九成的
按鍵都是取首選，爲了它蓋掉九行稿子並不划算——所以首選就寫在句子裏，你讀的是句子而不
是列表。真要挑的時候 `Tab` 一下。

畫在正文裏的那幾個字**不在文件裏**，但它們**在頁面上**：光標、`j`、鼠標、折行、禁則
算的是同一頁（這是 #210 那一層的意思），所以行内預覽不會把後面的字擠到你看不見的地
方去，也不會讓光標和你看到的位置對不上。

`/` 搜索是例外：它在狀態欄上組字，那裏没有正文可以畫，所以搜索框的候選框照畫。

配置文件是 `[panel] display`。這和**上屏方式**（`:yume-commit`）是兩件互不相干的事——
一個是「字什麽時候落到紙上」，一個是「候選在哪兒讀」，六種組合都成立。

### 分號——快捷符號

編碼欄空着的時候按 **`;`**，出來的不是候選框，是一張**對照表**：`a`–`z` 各對着一個
標點，**按那個字母就上屏**，不用選重、不用翻頁，`1`–`9` 也不是用來挑的。

| 排 | 鍵 | 上屏 |
| --- | --- | --- |
| 左上 | `q w e r t` | `：“` `“` `”` `‘` `’` |
| 左家 | `a s d f g` | `：「` `「` `」` `『` `』` |
| 左下 | `z x c v b` | `——` `……` `！` `？` `～` |
| 右 | `i j k l` | `·` `、` `〔` `〕` |
| 右 | `m n o` | `》` `《` 全角空格（畫成 `␣`） |

另有五個**改不了**的固定鍵，也在同一張表上：`;` `,` `.` 出全角的 `；，。`，`$` 出
`￥`，`` ` `` 出它自己——這幾個的直接鍵要麽在半角標點下出半角，要麽根本没有。

出路三條：按字母上屏那一條；**再按一次 `;`**（或**空格**）上屏「；」它自己；按別的任何
鍵就退出這張表，那一鍵當作剛按下的新鍵重走一遍（`Esc` 直接關掉）。

這張表是**宇浩的**，三端共用一份，所以在 yumete 裏按的鍵與在系統輸入法裏按的一模一樣。
冰雪那類把 `;` 拿去當編碼的方案，引導鍵由方案自己讓到別處。

### 分頁條

開了不止一個文件時，最上面會有一條**分頁**，像終端的 tab 一樣：每個文件一格，正在寫
的那個亮著（用頁面本身的底色，所以它讀起來像是疊在最前面的那張紙），改過没存的後面
掛一個 `+`。鼠標可以直接點——滚輪本來就已經把它捕獲了，這一項不多花什麽。

`[editor] tabs` 可設 `"auto"`（默認，開了一個文件就不畫，省一行）、`"always"`、
`"never"`。分頁條在的時候狀態欄就不再重複 `[2/3]`——同一件事説一次就够。

### 空格菜單

按**空格**（Normal 模式）會列出它能接的鍵——不用離開頁面就看得見有哪些：

| | |
| --- | --- |
| `空格 e` | 文件邊欄（開／關） |
| `空格 o` | 邊欄直接開在大綱 |
| `空格 f` | 打開文件（項目内模糊搜索） |
| `空格 b` | 切換緩衝區 |
| `空格 /` | 高級搜索面板：框裏打要找的字 |
| `空格 ?` | 命令一覽 |
| `空格 y` | 把選區複製到系統剪貼板（`:clipboard-yank`） |
| `空格 p` `空格 P` | 從系統剪貼板粘貼／貼在前面 |
| `空格 d` | 字典：查這個字的拆分與編碼 |
| `空格 r` | 改這裏的注音（開 Ruby 模式，見 5.5） |
| `空格 w` | 另一個工作區：没開就開，開着就過去 |
| `空格 W` `空格 q` | 只留這一個／關掉這一個到另一個去 |
| `空格 "` | 粘貼取過的東西——列出最近 16 次 yank／删除，和帶名字的暫存器 |
| `空格 c` `空格 C` | 行注釋／塊注釋，再按一次拿回來（見下） |
| `空格 m` | 合併衝突：`o` 留我方、`t` 留他方、`b` 兩方都留 |

**注釋這兩個鍵各説各的形式，不看情况。** `空格 c` 要**行**注釋，`空格 C` 要**塊**
注釋；哪一種格式裏没有那一種，才退到另一種——退的時候不是猜，是那個格式只有一個答案。

| | `空格 c`（行） | `空格 C`（塊） |
| --- | --- | --- |
| typst | `// ` 逐行 | `/* */` 包住 |
| markdown | `<!-- -->` | `<!-- -->` |
| 純文本 | 没有，會這麽説 | 没有，會這麽説 |

markdown 兩格一樣，是因爲它**只有**塊注釋這一種寫法（`<!-- -->`），不是兩個鍵合成了
一個。一個没説自己是什麽的 `.txt` 落在第三行——那是它應得的（見〈Markdown 還是
Typst〉），要註釋就 `:syntax markdown`。注釋永遠按整行走：選區先撑到它碰到的那幾行，
寫完那幾行還選着，所以再按一次就是撤銷。行注釋的記號對齊到那幾行**最淺的那一級縮
進**，空行不算數也不加記號。

**邊欄和挑選器不是同一件事。** 挑選器回答「帶我去我心裏那個文件」，開一下就走；邊欄
回答「讓我看見這本書的形狀」，一直開着。一百章分在卷一卷二裏，那棵樹本身就是目録。

**挑選器裏打得了中文。** 中文稿子的文件名多半是《第三章 雪》，所以輸入法在那張清單裏
照常跑——候選面板掛在查詢那一行下面，單按 Shift 切中英，和 `/` 搜索是同一套。

`空格 e` 開邊欄，並且**直接停在你正在寫的那個文件上**。在邊欄裏，移動用的還是正文那
幾個鍵：`j` `k` 上下，`l`（或 Enter）進去——目録展開，文件打開，`h` 收起或退回上一層。

**`C-w` 去下一個區域**——邊欄、正文、另一個工作區，按屏幕上的順序輪一圈，没開的跳過。
vi 的窗口鍵，一個意思：「鍵的下一個落腳處」。從邊欄按它就是交還給正文，樹留着。

邊欄有**兩扇門**：`C-w` 走人、樹留着；`q` 把這一格關掉。**`Esc` 在這裏什麽都不做**——
它是所有人的「出去」鍵，可面板將來有能打字的格子，`Esc` 要留給退出插入模式，多按一下
就把面板收掉是真會發生的事。狀態欄那一行寫着這兩扇門，所以按錯了也看得見往哪走。

鍵在邊欄那邊的時候，狀態欄會**寫出邊欄的鍵**（包括怎麽回去）——拿走鍵的那一半有義務
説清楚怎麽還。

`空格 e` 和 `空格 o` 都是「**給我看這個視圖**」，一條規則：邊欄没開就開在那個視圖上，
開着但在别的視圖就切過去，開着而且就在那個視圖但鍵在正文那邊就把鍵拿回來，鍵已經在
邊欄裏就收掉。所以同一個鍵按兩次一定回到原點——這是任何開關最起碼的事——而按另一個鍵
是「換視圖」，不是「關掉」。

**`空格 d` 開字典。** 它不在左邊欄，在**右邊欄的下半**——跟表格詳情一樣是「臨時的」
那一層。 光標下那個字，宇浩拆分表知道的全部——拆分、編碼、
分節編碼、讀音、注釋、字集、統一碼碼位，還有没被截短的全息拆分。陸、臺、港三家對幾千
個字的拆法是不一樣的，所以**一個字有幾種拆法就列幾段**，每段頭上寫是哪一家的，而不是
悄悄拿第一個當答案。打字的時候也能問：候選面板開着的時候按 `Tab`，問的是高亮那一條
（是詞就問它的頭一個字）——候選欄一條只有一行，只寫得下拆分和一個碼，其餘的都在這裏。
拆分表裏没有那個字（或者當前方案是純音碼，根本没有拆分這一層），它會直説「拆分表裏没
有這個字」，而不是給你一個空欄。

字典**不在 `Tab` 的輪換裏**，因爲它根本不是那一層的東西：左邊欄那三個視圖永遠有東西
可看（一個目録、開着的文件、這一章），而字典只在你問了之後纔有内容。**問一次它就在，
光標一離開那個字它就没有**——你不用關它，它也不會蓋掉你左邊開着的文件樹。

它和表格詳情不一樣的地方是**它收鍵**：`空格 d` 之後鍵就在字典裏，`j`／`k` 上下（陸、
臺、港三家拆法列下來常常一屏放不下），`C-w` 出去。鍵在裏面的時候光標不動，所以那個字
還成立，面板不會在你讀到一半的時候消失。⚠️ 打字打到一半按 `Tab` 問候選字則**不收鍵**
——那時你正在寫詞，面板只是給你瞄一眼的。

**`Tab` 在三個視圖之間走**：文件樹、打開的緩衝區、當前文件的大綱。它們回答的是同一個
問題的三個尺度——項目裏有什麽、其中開着什麽、眼前這一章是什麽形狀——所以放在一個地方
輪換，而不是三個面板。每個視圖各自記得自己停在哪裏，`Tab` 來回不會回到頂上。`空格 o`
直接開在大綱。

**哪一格在哪一邊是你的事。** 頁面兩側各有一個槽，每個槽分上下兩層：上層是**常駐**的
（文件樹、緩衝區、大綱——你開的，按 `q` 纔走），下層是**臨時**的（字典、表格詳情——光標
帶出來的，光標一走就没有，上層原樣不動）。

**`:sidebar-show-left` 與 `:sidebar-show-right` 當場挪一格。** 不寫名字就是手上這一格；
寫了就是那一格：`files` `buffers` `outline` `dictionary` `detail`。已經開着的會跟着搬，
那一邊本來有東西就跟你這一格對換，誰都不會被悄悄關掉。想記住就寫進配置：

```toml
[sidebar]
outline    = "right"   # 大綱擺到對面，寫的時候一直看得見
dictionary = "left"    # 字典疊在文件樹下面，只佔一列
```

⚠️ **`Tab` 只在同一個槽裏輪。** 三個視圖都在左邊就是出廠的樣子；把大綱挪到右邊，左邊
`Tab` 就在文件／緩衝區之間走，右邊只有大綱，按 `Tab` 它會説「這一邊只有這一格」。

**`C-w` 一路輪過去**：左槽上層、左槽下層、正文、（另一個工作區）、右槽上層、右槽下層，
没開的跳過。

**`w` 換寬窄。** 平常邊欄是窄的（`sidebar_width`，默認 24），因爲欄是終端最缺的東西；
但「天門真境之傳家寶扇」這樣的章名在 24 欄裏是要被切掉的，而大綱最不該做的就是切掉
名字。所以按 `w` 它就開到**剛好放得下最長那一條**（最多佔窗口的一半），再按一次收
回去。

大綱認的是 Markdown 的 `#`（Typst 的 `=` 也認）——**不需要 parser**，標題就是行首那幾
個井號。選一條 Enter 就跳過去。一個井號都没有的 `.txt` 小説也有大綱，那幾條規矩寫在
「一本長篇」那一節。

**大綱摺得起來。** 卷一底下有二十章，翻卷二的時候那二十章只是一堵牆。在大綱裏按
`h`，光標那一條就把底下的收起來，前面的記號從 `▾` 變成 `▸`，按 `l` 再打開。站在章上
按 `h`——它自己没有東西可收——收的是它上面那個卷，光標也跟着挪上去，所以連按 `h` 是
一路退出這條枝，和文件樹裏的 `h` 是同一件事。`Enter` 永遠是「去那裏」，摺着的標題也
一樣：那是一個地方，不是一個開關。摺法只跟着這一次邊欄，關掉再開就全展開了。

**Typst 的書，大綱會把 `#include` 打開。** 一個主文件 `#include` 了三十章，源碼裏
只看得見三十個文件名。但章名就寫在那三十個文件裏，是普通的 `= 標題`——**讀一下就知道
了，不用編譯**。所以大綱直接把它們讀出來：

```
天門真境
  傳家寶扇
  天門攬勝
  ch03.txt        ← 這一章自己没有標題，只好用文件名
```

縮進是那條標題自己的層級（`=` 一層、`==` 兩層）。選一條 Enter，寫在别的文件裏的那章
**就打開那個文件**跳過去，落在標題那一行上。`#import` 不算章——那是借模板，不是加
一章。

## 七、日常

### 底下兩行

底下是**兩行**，回答兩個不同的問題：

```
-- NORMAL --  ch01.md   Ln 12, Col 8              螭 U+87ED · CJK Unified Ideographs
 表格  t 表格菜單  T 按字  Tab 下一格             ← 下面：正在打什麽、剛才怎麽了、能按什麽
```

**上面那行是「我在哪」**——模式、中/英、文件名、位置、光標下那個字。它**永遠不變形**，
所以眼睛每次都在同一個地方找到同一樣東西。以前一條消息會把位置擠掉甚至頂没了，一個
`:` 更是把整行換掉，那是因爲幾個問題擠在一行上。

**下面那行是命令行**，没有話説的時候就是空的。它按這個順序回答：

1. **你正在打的命令或搜索**——`:` 和 `/` 打在這裏，命令菜單就疊在它上面
2. **剛發生的事**——`存了 ch01.md`、被擋下的鍵、`找不到`
3. **你按了一半的鍵**——按了 `m` 不記得後面跟什麽，這一行直接列出來
4. **拿着鍵盤的那塊面板**——邊欄、表格（按格還是按字，各自的鍵不同）

`空格` 和挑選器不在這一行上，因爲它們本來就開了一塊列着自己的鍵的面板——同一件事在
兩個地方説兩遍，比説一遍差。

第 3、4 條只列**猜不出來的鍵**。`hjkl`、`c`、`d`、`y`、`p` 在表格裏跟在正文裏是一回
事，列出來只是佔地方；表格獨有的那些按 `t` 就是一整張表。

代價是**一行**。竪排時那是每一縱少一個字，看得見。`[editor] command_line = false` 關
掉，關掉之後 `:`、消息、邊欄的鍵都回到狀態欄上輪流佔位（没人看得見的消息不算消息）。

### 你打了什麽——光標旁邊那個牌子

打了一半的命令（`3`、`2t`、`d3l`）在兩處説：狀態欄右端，和**光標旁邊**。右端是 vi
一九七六年就定下的位置，可它離眼睛二十行遠；旁邊那個是給眼睛的。

`:view-hud off|basic|full`（不寫就是問它現在是哪一檔）：

- **`off`** 旁邊不畫。狀態欄右端那一份還在——那是底線，哪一檔都不動它。
- **`basic`** 一顆**藥丸**：金字，暗底，一行高，`╰` 那個角指回光標。它**一個
  字都不蓋**——自己去找頁面上的空白，離光標越近越好（差一行等於差四個漢字），左右上
  下都算，找不到就不畫。竪排也一樣：空白在光標**左邊**的時候，角就掛在牌子右端指回
  來。
- **`full`（默認）** 一塊**帶框的面板**，釘在光標正下方，**蓋住那裏的正文**。

外框和「蓋字」是同一個決定，不是兩個。藥丸要的是一行上五個空格，一頁稿子總找得出來；
帶框的面板要的是光標附近一塊三行高的空地，一頁稿子上没有這種東西——所以要框就得蓋。
反過來也成立：字一旦畫在跟正文同一張紙上，没有框就没有東西告訴你哪幾個字不是你寫的。

**蓋掉的是什麽**，值得説清楚：Normal 之下這個牌子寫的是**你打的那個數**，而它釘在光
標下面，蓋掉的正是 `3`、`2t`、`d3l` 要數的那幾個字——命令的賓語。這也正是 `basic` 存
在的理由：那一檔在最壞情况下和 `off` 一樣什麽都不損失，**醒目是用樣式買的，不是用藏字
買的**。不過**出廠是 `full`**（2026-09-08 定）：牌子先得一眼看得見，而被蓋住的那幾個
字，光標挪一下就露出來。嫌它蓋字，`:view-hud basic`。

`full` 會避開别的面板（`空格` 菜單、`:` 菜單、挑選器、表格邊欄），但候選框比它大：兩
個都想要光標下面那一格的時候，候選框贏。

`:view-hud` **不歸 `:render` 管**。`:render` 寫的是「這份**文件**怎麽畫」那四項；這一項是
「編輯器怎麽跟你説話」。把標記藏起來的人，並没有説過他不想看見 `d` 前面那個數。

### 這是哪個字

狀態欄右端説出光標下那個字**是什麽**：

```
-- NORMAL --  ch01.md   Ln 12, Col 8              螭 U+87ED · CJK Unified Ideographs
```

一個生僻字在終端裏顯示成方框的時候，這一行回答的是「字錯了還是字體缺了」——區塊名
告訴你它在哪個平面，多數字體不帶擴展 B 以上。校稿時查一個字是不是你以爲的那個字，
也是同一件事。

區塊表是 Unicode 自己的 `Blocks.txt`（17.0.0，346 個區塊）整份抄進來的，二分查找，
没有依賴、不聯網。

擠不下的時候**先讓區塊名，再讓碼位**，左邊的位置讀數永遠不動——狀態欄最要緊的是
「我在哪」。不想要就 `[editor] char_info = false`。

### 註在句子旁邊

`[^1]` 是一個很小的記號，它指的那條註在文件末尾一百行以外。所見即所得下更是如此。可是
腳註存在的意義**就是**要在句子旁邊被讀到——跑到文末去讀它，順序正好是反的。

所以光標停在 `[^1]` 上時，**角落裏浮起一個面板**，寫着那條註本身，以及它寫在第幾行：

```
那年冬天[^1]，山下起了大雪。
                          ╭[^1]──────────────────╮
                          │ 據縣志，那是丁丑年。 │
                          ╰──────────────第 24 行─╯
```

**它站在光標的對角**——光標偏左它就靠右，光標低到它要蓋住你正在讀的那一行，它就翻到
上面那個角落去。**它不從頁面上收走任何一行**：從前那是一條通欄四行的横條，一條註一兩
行字，横條既把寬度空在那裏，又不管註有多短都無條件收走四行稿紙。竪排一樣有，角落按竪
排的方向算。

`gd` 過去，`gd` 回來——**一個鍵，兩個方向**，因爲從註那裏你只可能想回到剛才那個
句子。回來落在你離開時的那一個字上，不是那一行的行首。中途跑到别處去了，回程就作廢，
不會把你送到一個你已經不記得的位置。

批注 `%%…%%` 用同一條面板：它本來就在畫面上，面板給的是**讀一條長批注而不讓它把段落
撑開**的地方。

面板是同一個機制的三個用途（表格詳情、腳註、批注），`t i` 開關。表格的詳情**在右邊欄
裏**，因爲一行有二十八個欄位、那是個高東西，而且你會盯着它一格一格看；腳註與批注**浮
在角落**，一條註是一小段話，爲它切掉任何一塊稿紙都是付錯了價錢。

詳情這一塊是**臨時的**：光標站在表格的一行上它就在，走開就没有，右邊欄也跟着收掉——
它不是你開的，所以也不用你關。它**自己跟着光標滚**：你在行裏走到第 20 欄，面板就滚到
第 20 欄，所以它不收鍵，`C-w` 也不會停在它上面。

### 表格模式

一個 CSV 是文本文件，yumete 編輯文本文件；它不是**格子**。二十八欄的拆分表讀起來是一整行
流水賬，欄對不齊，想到「這一行的第四個欄位」只能用眼睛數逗號。表格模式就是那個格子：
同一份文字的另一種視圖，移動的單位從字變成格。

```
yumete -t 表.csv          # 或者在裏面 :table
```

#### 四種看法

同一份文字，四種看法，`t` 那一組鍵切換。整頁的表格視圖不是另一種東西，它只是**把整個
窗口交給了一張表**——那張表是一份 `.csv`，還是一章裏的三行，没有分别：

| | 原文 | 按鍵 | 折行 | 進 |
| --- | --- | --- | --- | --- |
| **源碼模式** | 看得見，`\|` 就是一個字符 | 正文那一套 | 照舊 | `t o` |
| **表格操作** | 看得見（逗號、跳格、`\|` 都在） | 格子那一套 | 表格那幾行**不折** | `t b` |
| **畫成表格** | 看不見，畫成格線，**四周的正文還在** | 格子那一套 | 不適用 | `t f` |
| **全窗表格** | 看不見，畫成格線，**整個窗口只有這張表** | 格子那一套 | 不適用 | `t t` |

#### 四種看法，逐項對照

上面那張表説的是「是什麽」，這張説的是「會做什麽」。每一格都是**量出來的**，不是從註釋
裏抄的——這份代碼裏已經有過三處註釋比代碼老。

| | **源碼 `t o`** | **表格操作 `t b`** | **畫成表格 `t f`** | **全窗表格 `t t`** |
| --- | --- | --- | --- | --- |
| 内部的層級 | `Off` | `Basic` | `Full` | `Basic` ＋ 佔住窗口 |

幾條容易誤會的：

- **`t t` 不是第四個層級**，它是「把窗口交給這張表」。層級還是 `Basic`——所以 `t q` 交回
  窗口之後，你回到的是剛纔那一種。
- **`t b` 的原則是只能多字、不能少字**：補白、欄號尺、頂欄都是**加**在頁面上的標註，所以
  它們在 `t b` 裏都有；折疊是**藏**字，所以要按 `t w` 開口。`t f` 還會**替換**（`|` 畫成
  `┆`），那是 `t f` 獨有的第三件事。
- **光標不會因爲站上去就展開一個折疊的格子**——`i` 纔會。全窗表格裏本來會（量那一格用
  的是窗口而不是上限），作者 2026-09-11 把它收回來了：「列宽容易跳……建议这个和 tf 保持
  一致」。每按一次 `l` 就給那一欄一個新寬度，於是一個只説「下一格」的鍵把整張表往旁邊
  推。在 Normal 裏讀一個折疊的格子有三條路，而且都不動版面：**右邊的面板**本來就整格
  攤開着，`i` 就地展開，`t w` 一次全開。
- **詳情面板開在「有東西是頁面上看不到的」地方**：`t f` 和 `t t` 會把長單元格折起來，
  那時面板是讀全内容的路；`t b` 什麽都不藏，面板等於把頁面已經在説的再説一遍，還要佔掉
  五分之一的寬度。`t i` 一旦表過態就永遠聽你的，換層級也不會悄悄改回去——和 `t w` 一樣
  的規矩。

- **四種標點没有分别**：markdown 的 `|`、csv 的 `,`、tsv 的 Tab、Excel 的 `;`，在 `t b`
  和 `t f` 下走的是同一條代碼，顯示效果一樣（#378）。

四種之間直接切，不用先退出去：在全窗表格裏按 `t b` 是回到表格操作，不是回正文。
**`t o` 是回正文的路**，四種裏哪一種都認。

**`t q` 只管全窗表格**：它把窗口交回去，並且回到剛纔那一種——`t f` `t t` `t q` 之後你
還在 `t f`。一份自己就是一張表的 `.csv`，它本來就没有「剛纔那一種」，那裏 `t q` 就是
`t o`。

**表格操作**是給「我想看見我打的是什麽，但想按格子走」的時候用的——改一份 Markdown
表格、對一份 CSV 的原文，逗號和 `|` 一個都不藏，而 `Tab`、`t r`、`t1s`、`t/` 全是格子
的意思。那幾行**不再折行**：一行就是一行，數得清第幾欄。

**畫成表格**與**全窗表格**的差别只有一條：欄寬是誰算的。畫在正文裏的那一種，欄寬是**整
張表**算出來的一份，所以滚動的時候格線不動；全窗那一種，欄寬是**看得見的那幾行**算出來
的，所以它捲到哪裏就照哪幾行收緊——一份十二萬行的拆分表因此只花一頁的力氣。

**`t b` 與 `t f` 裏，光標上下走得出表格**：在最後一行按 `j` 就走進表格下面那一段話，在
標題行按 `k` 就走進上面那一段。走出去 `hjkl` 就又是字母了，走回來又是格子。`J`／`K`
（翻頁）不走出去——一頁數的是**表格的**行，數完就停。

**全窗表格裏，標題行是畫出來的，不是站得上去的**：它凍在最上面一行，`t t` 從標題行按下
去落在**第一條數據**上，在第一條上按 `k` 就停住——不然光標明明在標題行，畫出來卻在第一條，
打一個字進的是欄名。`t b`／`t f` 裏標題行還在頁面上原處，改欄名就是改欄名。

**全窗表格是一扇窗，開在一張表上，走不出去。** `G`、`gg`、`g30g`、`:120`、搜索——這些
本來是整份文件的跳法，在窗裏一律**夾在表内**，並且説一句「全窗表格只走這張表」：`gg`
是這張表的第一條，`G` 是最後一條，滚輪滚到頭就停。出去的路只有三條：`t q` 把窗口交回
去（回到剛纔那一種），`t o`／`t b`／`t f` 換一種看法，`t ]`／`t [` 去下一張表。

從前它是漏的：`G` 一按光標就跳進底下那一章，窗裏没有表可畫，於是窗口自己悄悄交回給正
文——**全窗表格會在没有人要求的時候結束**。堵住這個口子，一整類邊角情况就没有了，也纔
換得到下面這一條。

**窗裏的行號是這張表自己的行號**（第 1 條、第 2 條…），不是文件的行號。狀態欄的「第 N
行」跟着它，`t1g`、`t20,20g` 數的也是它——**窗裏每一個數字都指同一件事**。走出窗子（`t
b`／`t f`／`t o`）行號就又是文件的了，那時 `t20g` 也就又是文件的第 20 行（夾在表内）。

**`t ]`／`t [` 走到别的表格，欄數不一樣也認得**：欄名、欄號、寬窄都照**那一張**表畫，
狀態欄報的也是那一張表的欄名。

**哪些行會跟着變**，看文件自己説了什麽：

- **整份文件就是一張表**——`.csv` `.tsv` `.md`，旁邊有一份 schema，**或者它從第一行
  到最後一行都對得齊**（擴展名是 `.txt` 也算，看的是内容不是名字）——那麽 `t b`／
  `t t` 是**整個文件**的狀態。在兩張表中間的段落上按也算數，文件裏每一張表一起變；
  光標走出表格，表格照樣是表格。
- **只有中間一段是表**——貼進稿子裏的一段跳格分欄、一段坐在 `## 第三章` 底下的碼表、
  `dict.yaml` 裏 `---` 之後那些條目——那麽它管的只有**光標底下這一段**，走出去就回
  正文，想再看要再按一次。

`|` 表格自己每一行都寫明了它是什麽，所以它走第一條，哪怕它坐在一份 `.txt` 裏。猜出來
的那一段纔走第二條——猜的東西不該在讀者走開之後還留在畫面上。

Markdown 裏**只有能被正確 parse 的表格**纔會變：缺了 `|---|` 那一行的、圍欄裏引用的，
都當正文。

**欄與欄之間怎麽分開**，是這張表的事，不是編輯器的事：二十八欄一個字寬的拆分表讀起來
是格子，要一條線才分得清；六欄很寬的表讀起來是頁面，欄欄之間都畫一條反而是字與字之間
的噪音。默認是**虚線**——畫得出邊界，又不會自己變成一欄：

```
:table-rules line dash      虚線 ┆（默認）
:table-rules line           一條實線 │
:table-rules line double    雙線 ║
:table-rules color          每欄一條淡底，紙從縫裏透出來
:table-rules off            什麽都不畫，靠對齊分
:table-rules                説現在是哪一種
[editor] table_rules = "off"
```

**放一份 schema 在數據旁邊，它就自動是表格。** `.yumete/tables/*.toml`，從**文件所在
目録**往上找（不是工作目録——schema 是數據的屬性，不是這次會話的）：

```toml
[table]
file = ["yuhao_division_golden_source.csv", "yuhao_division_pending.csv"]
key = "char"                  # 哪一欄是這一行的名字
delimiter = ","
quoting = "none"              # 目前只支持這一種，見下

[[table.column]]
name = "char"
label = "字"                   # 表頭顯示的名字，不寫就用 name

[[table.column]]
name = "d1"
hidden = true                 # 這一欄照樣讀、照樣寫，只是不畫、光標也不停

[[table.detail]]              # 只在詳情欄出現，不進格子、不寫回文件
name = "block"
compute = "block(char)"       # codepoint(欄) / block(欄) / range_label(欄, 區間表)

[table.link]                  # 「這一格指着本表的另一行」——正反兩個方向都靠它
from = ["ids_y", "ids_g"]     # 這些欄的内容是别的行的名字
to = "char"                   # 名字寫在這一欄

[ranges.cjk_blocks]           # 你自己的叫法，不是 Unicode 的
"CJK-D" = [0x2B740, 0x2B81F]
```

没有 schema 也能用：`-t` 會拿**文件自己的首行**當表頭，欄名有了就能對齊、能按格走。
分隔符也是猜的，規矩和 `:table-pipe` 那條一模一樣：跳格、逗號、分號裏哪一個每行都出
現同樣多次就是哪一個，猜不出來纔當逗號。所以 `:export tsv` 寫出去的文件，`-t` 讀得
回來——從前這裏寫死了逗號，跳格分欄的文件一律説「不是表格」。

**一份 `.txt`，每行都被同一個記號切成同樣多欄，打開就是表格。** 不用 `-t`，也不用
schema：跳格、逗號、分號、空格這四個裏，哪一個每行都出現同樣多次，它就是分隔符，再要求
它切得出兩欄以上。進的是「基本」，狀態欄説一句「本文件格式似乎是 Tab 分欄，故而以表格
模式打開，按 t o 回到源碼模式」。`.csv`／`.tsv` 不走這條路——名字已經説明了它是什麽；
寫了 schema 的、schema 有錯的，也一律不猜。

**`t o` 只用按一次。** 猜得不對（或者你就是要看原文），`t o` 回源碼，這個答案記在數據
目録的 `source-mode.txt` 裏，下次打開同一個文件就不再猜它。改主意按 `t b`／`t f`，那一
行就從名單上撤掉。名單只留最近 200 個文件，文件不在了自己掉出去。

**碼表没有表頭。** 「字⇥碼」一路到底，首行當表頭就少了一行、還把一欄叫成「一」。
`t H`（或 `:table-header off`）説明這件事：第一行變回普通的一行，欄名改用編號——就是
欄號那一行畫的那些數字（`t3/`、`t20,20g` 數的也是它）。再按一次換回來。**寫了 schema
的不受影響**：欄名是人取的，不會因爲一個鍵就没了，變的只是數據從第幾行開始。這一鍵
只對「整個文件是一張表」的那種有意義——`|` 表格的表頭是文件自己説的（底下那行
`---`），文中認出來的那一段（見下）本來就没有表頭。

**`t e` 把這張表的規格開在另一半。** 整份文件是一張表的時候，`t e`（或
`:table-schema`）就把説明它的那份 `.toml` 開在另一個工作區——鍵還在表格這一半，
`空格 w` 過去改。**没有 schema 的話，先寫一份出來**，放在數據旁邊的
`.yumete/tables/` 裏，名字跟着數據文件。

寫出來的那份説的**就是眼下看到的樣子**：分隔符是它猜到的那個，`t H` 説過的「第一行
是數據」也在裏面，欄名照首行。所以開了它、讀回去，一格都不會變——接下來你改的每一
項，改的都是眼前看得見的東西，而不是對着一張白紙猜格式。改完保存，`:table off` 再
`:table`（或 `t o` `t t`）就照新的讀。

已經有那個文件名的不會被蓋掉：那是别人的東西，把它打開看看它説什麽纔是對的做法。文中
認出來的那一段（見下）和 `|` 表格没有這一項——它們是**文件裏面**的表格，不是一份表格
文件。

#### 文中的一段也可以是表格

**整個文件不是表，裏面那幾行是。** 一張碼表貼進了章節，`dict.yaml` 的正文在 `---` 前
言底下，LaTeX 的 `tabular`——把光標放進那幾行裏，`:table`，它就是格子；`:table off`
出來，文件一個字節都没動過。

怎麽認的：

* **站在哪個分隔符上就是哪個。** 一行裏跳格和逗號都有，站在逗號上按 `:table`，就按逗
  號分。選中幾行也行，選區裏每行都一樣多的那個字符就是它。都没説的話，按跳格、逗號、
  分號、`&` 的順序試（`&` 是爲了 LaTeX 和 Typst）。
* **從光標那一行往上下走，走到不含那個分隔符的行爲止。** 空行是一個界，`## 第三章` 也
  是一個界——它裏面没有跳格。所以碼表緊貼在標題底下也認得出來。
* **進去之前先對一遍。** 兩三行的區塊要求每行欄數完全一樣；四行往上，三分之二的行一致
  就算數——`dict.yaml` 有些條目帶權重有些不帶，爲了那幾行拒絶整張表是不對的。對不齊就
  是分隔符猜錯了，寧可不進去，也不要在别人的稿子上畫一張歪的格子。
* **欄數按最寬的那一行算。** 那個權重欄還在，走得進去。
* **首行是數據，不是表頭。** 碼表没有表頭，欄名就是 1、2、3。

**它只讀不改寫。** 走格、`t g`、`t /` `t ?`、`t y` `t p` 照常用（`t p` 只寫到區塊的最
後一行爲止，不會順着往下寫進正文）；會重排整行的那些——`t1s` `t1S` `t r` `t R` `t d`
`t D` `t c` `t C`——一律不做。碼表是别人的數據，它周圍是别人的文章。真要整理它，先
`:table-pipe` 或者 `:table-csv` 把它**變成**表格，那樣文件自己每一行都寫明了它是什麽。

#### 鍵

| | |
|---|---|
| `h` `l` | 左右一格 |
| `j` `k` | 上下一行，停在同一欄 |
| `0` `$` | 這一行的第一格／最後一格——**要先按 `T` 換成按格**；按字（默認）下它們照正文的規矩答「行首是 `gh`」 |
| `c` | **換掉這一格**——整格清空，直接打新的。網格裏最常用的那個 |
| `d` | **清空這一格**（分隔符留着）；有選區的時候還是删選區 |
| `i` | 進格子，停在**第一個字之前**（`I` 一樣） |
| `a` | 進格子，停在**最後一個字之後**（`A` 一樣） |
| `t/` `t?` | **誰用了它**——一欄一欄地找。`/` 這邊找，`?` 另一個工作區看。`t1/` 只找第 1 欄，`t2-10?` 找第 2–10 欄 |
| `n` `N` | 走剛才找出來的那些行 |
| `T` | **換移動單位**：按字 ⇄ 按格（默認按字） |

| `o` `O` | 新開一**行**——連分隔符一起，不是一條空行 |
| `t r` `t R` `t d` | 加一行（下／上）／删這一行 |
| `t j` `t k` | 這一行下移／上移 |
| `t y` `t p` | 取整整一欄／把取到的那一欄貼在這一欄上 |
| `Tab`（格子裏） | 下一格；`S-Tab` 上一格。填一行不用碰分隔符 |
| `:table-jump 木` | 跳到表格裏叫「木」的那一行 |
| `t i` | 詳情欄開關 |
| `t H` | 第一行是欄名，還是跟别的行一樣是數據 |
| `t e` | 這張表的規格開在另一半，没有就先寫一份 |

#### `t` 是表格的命令組，`g` 是全文的

**表格的問題用 `t` 問，整份稿子的問題用 `g` 問。** 一個鍵不會因爲光標停在哪裏就換一
個意思——`gd` 在網格裏曾經是「哪一行叫這個」，於是寫進表格裏的一條腳注 `[^1]` 按 `gd`
去搜了網格，而那正是 `gd` 這個名字唯一該做的事。現在 `gd` `gD` `g/` `g?` 一律只認整份
稿子，表格自己的問題交給 `t/`、`t?` 和 `:table-jump`。

**跳到某一行**是 `:table-jump 木`：schema 的 `[table] key`（拆分表就是 `char`）那一欄
裏叫這個名字的那一行，`C-o` 回來。

**`t/` `t?`：誰用了它。** 站在 卵 上，你
想知道的是哪些字的拆分裏有卵，而那可能有四十處。這不是跳轉，是搜索——所以它就是搜索，
而且是**另一個方向的**搜索：

```
「卵」 第 2/17 行（n N 走）
```

`n` `N` 走這些處。它們就是「最後一次搜索」，所以 `n` 本來的意思没有變；打一個新的 `/`
就把 `n` 收回去。

#### 搜索有兩個方向

一頁紙是**一行一行**讀的，`/` 就這麽找。表格多了一個文檔没有的讀法：**一欄一欄**。問
「誰用了卵」，問的就是一欄一欄，答案也該按那個順序來。

```
:table-find row 卵         一行一行地找 —— 就是 `/`
:table-find column 卵      一欄一欄地找 —— 表格裏 t/ t? 就是它
:table-find 卵             不寫方向就是 row
```

**除了方向，兩者一模一樣**：模式是正則、命中的那一段就是選區、`n` `N` 走、到底了繞
回開頭。不搞特例——`林` 的拆分是 `⿰木木`，那裏面有**兩個**木，就是兩處，和 `/` 在一行
裏數出兩處是同一回事。

**搜哪幾欄**：schema 的 `[table.link] from` 列了哪幾欄就搜哪幾欄，按它列的順序——這正
是 schema 的用處，二十八欄的表只搜兩欄。没列就搜全表，並且説一句：

```
本表格文件未指定快速跳轉之範圍，從第一欄起搜索——第 1/17 處
```

**光標先落在第一欄的第一處**，不管你剛才站在第幾欄。同一個字每次 `t/` 得到的是同一
條路線——「把所有用到它的地方過一遍」就是這個意思。

按字的時候找的是光標下那**一個字**，按格的時候找的是**整格**。

#### `T`：按字走，還是按格走

默認按**字**走——一格裏的字纔是寫稿的人多半要動的東西。可是拆分表是一張網格，
整格取、整格換、一格一格走過去，這些要的單位是**格**：`T` 説了算。狀態欄右邊寫着現在
是哪一種，按下去那一刻也會説一句：

```
-- NORMAL --  拆分表.csv   第 50000 行 · ids_g · 格
```

`Tab` 不換單位，它**走格子**——右邊那一格，走到頭接下一行的第一格，`S-Tab` 倒着走。
每一個試算表都是這個意思，兩種單位下都一樣。

按字的時候，`hjkl`、操作符、選區全都恢復成平常的意思——這時它就是一個畫成網格的普通
文件。只有 `t` 那一族還認格子：**光標停在哪個部件上，`t/` 就找哪個**——按格的時候找
的是整格。

**格子裏怎麽移動光標**：進去之後（`i`／`a`／`c`）用**左右方向鍵**按字移動，`Home`／`End`
是這一格的兩頭。走到格子邊上再按一下，就邁進隔壁那一格——往右到頭接下一行的第一格，
往左到頭退回上一行的最後一格，落點在那一格的**另一頭**（從右邊走進去，光標就在它的
右端）。上下方向鍵按欄換行，和 Normal 下的 `j`／`k` 走一樣的步。

方向鍵只是走路，一個字都不改，所以不擋。**擋的是會改字的那兩個**：`Enter` 會把一行劈成
兩半，格首的 `Backspace` 會把兩格併成一格。另外，`Tab` 在最後一格會**開一行新的**（那是
在填表），方向鍵走到那裏就停住。

改一整格用 `c` 比 `i` 快得多：落在格子上、`c`、打新值、`Esc`。`u` 一次就全撤銷。

`HJKL` 還是翻頁，`gg`／`G`／搜索／操作符都不變——那些是關於行和文字的，格子没改變它們的意思。

##### `:table-check`——把整張表看一遍

四個問題，123,380 行時用眼睛答不了：

```
:table-check
```

- **哪一行的名字重了**（同一個字有兩行）
- **哪個部件查無此行**（拆分裏寫了它，表裏没有它）——⿰⿱⿲ 不算，那是結構符
- **哪一行欄數不對**
- 排好序的一個結果緩衝區，`gf` 跳到那一行，和 `:check-usage` 一模一樣的形狀

没查出問題就只説一句，不開緩衝區。

**在稿子裏查的是你站着的那一張表**，不是整份文件——一份 markdown 文件裏有幾張表就是
幾張，中間那些段落不是誰的行。分隔行（`|---|`）既不查也不算進行數。

#### 不會讓你出錯的幾件事

**逗號進不了格子——從任何一條路都進不去。** 這張表没有任何引號，一格就是兩個逗號之間
的東西，這條規則讓 8 MB 的手改表能逐字節原樣存回去。代價是**没有一格可以含有分隔符**。

這條守衛不在「打字」那裏，在**所有文字進出緩衝區的那兩個函數**上。第一版只守住了打字，
一次審查找出另外七條路都能繞過去——⌘V 粘貼、`空格 p`、輸入法上屏、`:s`、`r`、`R`、以及
在空格子上按 `d`（空格子的位置正好就是那個逗號，於是兩格併成一格；而這張表大多數欄在
大多數行上是空的，那是最容易誤傷的一條）。現在它們走同一道閘門，説同一句話。

不變式是：**表格模式下，一行的分隔符數量永遠不變。** `:s` 也照這條檢查——只改格子**裏面**
的替換照跑（`:%s/⿰木/⿰禾/g` 没問題），會改變格數或行數的直接拒絶並告訴你是第幾行。

**文件裏本來就有的引號讀得對。** 上面那條説的是「打不進去」，不是「讀不出來」：
`2500,"Smith, John",note` 是三格，中間那格連引號一起是你編輯的那幾個字符——引號在文件裏，
你看的就是文件。RFC 4180 的兩個連寫引號也認。`he said "hi"` 裏那個引號不在格子開頭，
所以它只是字：真要護住一個逗號，寫的人會把整格引起來。

**讀不了的只有一種：引號裏包着換行。** 那樣一條記録佔兩行，而這個網格從光標到存盤都是
「一行一條記録」，換個解析器也一樣。所以它被認出來、説出來，而不是半讀半猜：整份文件因此
不成格子時，開表格會直接告訴你是這個原因；文件大體上還是格子時，`:table-check` 會把那一行
單獨列出來説「引號没關上」，而不是含糊地報一句欄數不對。

**schema 有錯會説出來。** 打錯一個字的 schema 曾經是被默默丢掉的——二十八個標籤、兩個
算出來的欄位、整個跳轉全部消失，唯一的線索是狀態欄寫「照首行」而不是「照 division.toml」。
現在它直接告訴你哪個文件第幾行錯在哪。

**欄數不對的行標出來，但照樣能編輯。** 表格模式正是拿來修這種行的工具，一行壞掉就打不開
它，等於工具在最需要的時候缺席。多出來的欄位照畫——藏起來就是把問題藏起來。

**竪排和 CSV 網格互斥。** 格子是横着讀的，`:layout vertical` 會被拒絶（而不是畫出一個説不通的
東西），`-t` 也蓋過 `-v`。文檔裏的 `|` 表格不受這條管——它是頁面的一部分，頁面是什麽排版
它就是什麽排版。

#### Markdown 的 `|` 表格

同一套格子，指向文檔裏的**一段**而不是整個文件。光標放在任何一行 `|` 上，`:table`：

```
| 字 | 讀音 |
| -- | ---- |
| 木 | mu   |
```

**`t F` 會把表格排齊，排進文件裏。** Markdown 表格本來就該在自己的原文裏對齊（所以大家
都在手動敲空格），所以「對齊」就是編輯，而排好的結果在 GitHub、在别的編輯器、在任何地方
都是對的。

**排齊是你説了才排的。** 編一格出來不會順手把整張表排齊：一張自己敲的緊湊表格，改兩個字
只換兩個字，不會五千行一起補空格。已經排齊的表反過來也一樣——編完仍然是齊的，因爲那裏
重寫的本來就只有那兩個字。表格排没排齊，看的是每一行的形狀是不是一樣（剛編過的那一行不
算）。

**而頁面上的每一張表，不用你動手就是齊的。** 不只是光標所在的那一張，也不用進表格模式：
補出來的空格是畫上去的，文件裏一個字節都没多。這件事非在頁面上做不可——所見即所得把
`` ` `` 和 `**` 藏起來之後，每一行少掉的格數都不一樣，**同一份原文不可能在兩邊同時是齊
的**。所以原文歸 `t f`，頁面歸它自己，兩件事各做各的，互不礙着。

量的是兩根 `|` 之間**整格的寬度**，你自己敲的空格照舊算數；每一行都對欄寬有一票，
`|---|` 那一行也算——畫上去的只能加，不能減，所以文件裏已經排好的表，畫出來原樣不動。
`:render off` 之下不補（那時候頁面就是文件），直排之下也不補。

**齊了，鍵也就跟着是表格的鍵。** 補齊只是「基本」這一級的一半，另一半是鍵：光標一站到
表格行上，`hjkl` 走的就是格子，狀態欄報的是第幾行第幾欄，那幾行也不跟着正文折行——**都
不用按 `t b`**。`t o` 把兩半一起關掉。直排之下兩半都不來（直排不補齊），那裏要不要進表格
是你自己的決定，按 `t b`。


**按終端寬度量，不是按字符數。** 這是這個功能存在的理由：所有編輯器的表格格式化都是數
字符，於是一欄漢字排出來是歪的，漢字混拉丁排出來歪得更厲害。這裏一欄有多寬，量的是它
在終端上佔幾格。

没有 `|---|` 分隔行也能進——你正在寫的那個表格就没有——它會替你補一行。

##### 貼進來的東西作成表格，表格拆回去

從别處抄來的一段，逗號、分號或者跳格分欄的，**選中它，`:table-pipe`**：首行當表頭，
分隔行替你補上，欄寬按終端量齊，然後直接進表格模式。没有選區就取光標所在的**一段**
——空行是界，上下各走到空行爲止，所以稿子裏一段一段的東西不會被連累。

分隔符**看不出來就問你**，不猜。判斷的只有一件事：跳格、逗號、分號這三個裏，哪一個
**每行都出現同樣多次**。一份 CSV 每行的逗號一樣多；一段中文散文斷句用的是 `，、。`，
三個猜測一個都不沾，於是原樣不動，狀態欄叫你寫明：

```
:table-pipe          自己看：跳格、逗號、分號，哪個每行一樣多就是哪個
:table-pipe ,        寫明用逗號
:table-pipe tab      跳格（`Tab` 在命令行是補全，所以拼出來）
:table-pipe 、       任何一個字符都行——你比誰都清楚自己的數據
```

打不出來或者打出來看不見的，都有名字可寫：`tab`／`\t` 是跳格，`space`／`\s` 是空格，
另外 `comma`、`semicolon` 也認，引號裹一個空格（`" "`、`' '`）也認。

**一個空格它永遠不會自己猜**，多整齊也不算：一個空格是把句子連起來的那個字符，猜它，
一段散文就成了格子。**寫明 `:table-pipe space` 是可以的**——那是你説的，不是它猜的。

不過這條規矩問的是「每行齊不齊」，**不是「這是不是散文」**：兩行英文剛好各帶一個半角
逗號（`Yes, it works.` 配 `No, it doesn't.`），它照樣當成兩行兩欄。`u` 撤得回來。行數
越多越不會撞上，兩行是它敢下判斷的下限。

反過來，`:table-csv`（或者 `:table-csv tab`、`:table-csv ;`）把光標所在的 `|` 表格拆
回分隔文本，`\|` 還原成 `|`、`\\` 還原成 `\`，襯的空格去掉。落在**已經是** `|` 表格
的段落上的 `:table-pipe` 會拒絶：那一段本來就是表格，没有可作的。

**某一格裏本來就有那個分隔符，它會停下來告訴你是哪一格，不會替你加引號。** 這和表格模
式裏不讓你把分隔符打進格子是同一條規矩：一份「有的格加了引號、有的没加」的文件，在這個
程序裏讀着是對的，換一個程序讀，出問題那一格右邊的每一欄都錯位。換個分隔符，或者先改
那一格——你知道那份數據該怎麽辦。

**不想動稿子就用 `:export csv`**（`:export tsv` 同理）：光標所在的那張表另存一份，文件名
跟着稿子走，稿子本身一個字節不動。整個文件就是一張表的（`.csv` 開着表格模式）也認，於是
「讀 `.csv` 寫 `.tsv`」就是同一件事。

##### 鍵

走格、`c`、`i`／`a`、`y`／`Y`／`p` 都和 CSV 那邊一模一樣。多出來的是**結構**：`t`（表），
後面跟一個鍵，命令行會列出來。方向就是意思，`jk` 是行、`hl` 是欄，不用記哪個是哪個。

| | |
|---|---|
| `t r` `t R` | 加一行（下／上） |
| `t c` `t C` | 加一欄（右／左） |
| `t d` `t D` | 删掉這一行／這一欄 |
| `t j` `t k` | 這一行下移／上移（光標跟着走） |
| `t h` `t l` | 這一欄左移／右移 |
| `t1s` `t1S` | 照第一欄順排／倒排（`t0s` 是你站的這一欄，`t1a2d8as`、`t1,5,9s` 一次排幾欄） |
| `t y` `t p` | 取整整一欄／把取到的那一欄貼在這一欄上 |
| `t <` `t =` `t >` | 這一欄靠左／居中／靠右 |
| `t F` | 重新排齊，排進文件裏 |
| `t o` `t b` `t f` `t t` | 源碼／表格操作／畫成表格／全窗表格（見下） |
| `t w` | 太寬的格子摺起來／攤回去（源碼以外都算數） |
| `t a` | 太寬的格子折行——尾巴畫在它自己那一欄的下面幾行（只在全窗表格） |
| `t i` | 這一行攤成邊欄，一欄一行地讀 |
| `t q` | 全窗表格交回窗口，回到剛纔那一種 |
| `t ]` `t [` | 下一張表／上一張表 |

`o`／`O` 直接就是加一行，不用走 `t`。標題行删不掉——它是欄名。

`t p` 貼進來的格子**帶了分隔符就整批拒絶**，不會替你把它濾掉：`長, 久` 貼進一份 CSV
裏原本會靜靜變成 `長 久`。狀態欄報的是它本來要落在的那一行那一欄，一個字都還没動，
不用撤銷。貼進 `|` 表格則是照 Markdown 的規矩轉義（`|` 寫成 `\|`，反斜槓跟着加倍），
所以格子裏原本有什麽，讀回來還是什麽。

`t1s` 排序：**數字當數字比**（19、200、1900，不是 1900、19、2），其餘按碼位。漢字按
碼位不是任何人想要的排法，但那是這個編輯器目前能誠實給出的唯一一種——按拼音排要等
語言模型接進來。

**排幾欄**：`t1a2d8as`——第一欄順排、第二欄倒排、第八欄順排，最後那個 `s` 纔動手。
`a`／`d` 只記下一欄，不排；動作永遠是 `s`（或 `S`，最後一欄倒排），所以打到一半的
`t1a2d` 不會自己排起來，`Esc` 一按就全丢了。狀態欄按打過的樣子回顯：`t1a2d`。
**排序一定要説是哪一欄。** 光按 `t s` 什麽都不會發生——十二萬行的表排一次是真的要等，
而 `u` 退得回内容退不回時間，所以起手不是一個字母。站着的那一欄是 `t0s`／`t0S`：
`0` 不是欄號，正因爲如此它空着可以用來説「這一欄」。

**`-` 是範圍，`,` 是點名或成對。** `t2-10/` 是第二到第十欄（一種東西的一段），
`t1,5,9s` 是第一、第五、第九欄（同一種東西的好幾個），`t20,20g` 是第 20 行第 20 欄
（兩種東西）。一個鍵原本兩件事都做，寫下 `t20,20g` 那天就撞上了。

**行號是行號槽裏那個數。** 正文裏那是文件的行號，全窗表格裏那是這張表自己的行號（見
下）。兩邊都**夾在表内**：`t1g` 落在這張表的第一條，不是整份稿子的第一行——表格的鍵不
該把光標帶到三屏以外的段落裏去。

`|---|` 那一行是**畫出來的**，不是寫出來的：光標落在上面（`gg`、`G`、`:N`、搜索都會落
上去）時 `c`／`i`／`a` 會被擋掉，`t` 系列則當作是站在標題行上。要改對齊用 `t < = >`。

**注意 `t` 蓋掉了 vi 的 `t`（跳到下一個某字之前）**——不只在表格裏：`t` 整族是表格的
字頭，`t<字>` 那個 till 在 yumete 裏没有位子。要跳到某個字之前，`f` 之後 `h`。

一欄最寬排到 **32 格**。比這還長的格子照樣完整寫出來（什麽都不會被截斷），只是别的行
不再陪着它一起變寬——否則人物表裏一句備註就能把整張表撑到兩百格。

**`t w` 把超出的尾巴摺起來**，摺到哪裏就在那裏立一個 `>`。那個 `>` 是**金色加粗**的
——整頁的字都是灰的，這一個不是，所以它不會被讀成你自己打的那個大於號。（記號本身只能
是這個半角符號：Unicode 那幾個省略號在東亞環境下寬度不定，一格量成兩格，它後面每一欄
就都錯位了。）再按一次 `t w` 全部攤回去。文件一個字都没動：`t F` 排齊寫進文件的時候
讀的是原文，不是頁面。

**走過去不會攤開，要改字纔會。** 光標停在一個摺起來的格子上，它照舊摺着——**要讀全文
就開 `t i` 的詳情欄**（那裏一個字都不會少，而且會折行）。一按 `i`／`a`／`c` 進那一格，
它整格攤開，因爲光標不能停在頁面上没畫出來的字裏；`Esc` 一回 Normal 又摺回去。

這條規矩是拿卡頓換來的，換得很值：**攤開與否只跟「有没有在改字」有關，跟光標在哪裏無
關**，於是整張表的排版一份算好就一直用着，走一步不用重排。從前是「走進哪一格哪一格就
攤開」，那等於每按一次 `j` 都要把整張表重新量一遍——一張 286 行的表，在兩個字
寬的 `#` 欄裏上下走，每一步 15 毫秒。

**攤開的那一格不會把整欄撑寬**：它從自己那道牆往右頂出去，同一行後面的欄跟着右移，
**别的行一格都不動**。頂出去的地方牆還是畫的，兩邊也還留着空格，所以看得出邊界在哪裏。

**「基本」自己不摺，你叫它摺它就摺。** 那一級不准**自作主張**藏東西，所以出廠是全文；
按下 `t w` 就是你自己説了要摺，它照做，級别不動。真正没得摺的只有**源碼**——那一級照
原樣畫，没有一欄是排齊的，也就没有東西可以拿來量，`t w` 在那裏會直説要 `t b` 或 `t f`。
你按過的那一次算數：在「基本」裏攤開了，走到「畫成表格」還是攤開的。

**全窗表格裏 `t w` 也算數**，只是摺的辦法不一樣：正文裏摺的是**字**（尾巴下頁去），
全窗裏摺的是**欄寬**（那一欄畫到 32 格爲止）。斷口一樣立 `>`，光標所在的那一格一樣整
格畫出來——量它的時候拿的是窗口寬而不是上限，所以走進去就讀得到全文，`i` 進去改字也
走得到尾巴上。攤回去之後每一欄都畫到它自己那麽寬，最寬不過一個窗口——比窗口還寬的
那一欄再寬也没有用，格子是一欄一欄横向捲的，捲不進去的部分誰也走不到。

##### `t a`：折行——尾巴畫在下面，不是收起來

**全窗表格裏還有第三個答案**：`t a` 把每一個過寬的格子**折到它自己那一欄的下面幾行**，
一個字都不藏，也不用左右捲。一行有多高，看它最高的那一格要幾行；行號只畫在起頭那一
行，下面幾行是同一行的續行，所以數得清第幾條。

`t w` 和 `t a` 是同一件事的兩個開關，**永遠不會同時亮**。`t a` 走進折行：摺起的時候按
它就換成折行，攤平的時候按它就折起來，折着的時候按它攤平。`t w` 只認「摺不摺」：攤平
的時候按它就摺起，摺着的時候按它攤平，**折着的時候按它也是攤平**——一個字都不藏，要摺
起再按一次 `t w`。

**爲什麽只有全窗有。** 正文那一頁的行是編輯器共用的折行層算出來的（所有移動鍵、鼠標、
縱書、分屏都讀它），而它没有「懸垂縮進」——續行只能從最左邊開始，同一行剩下的欄會跟在
折出來的文字後面，那不是任何人講的折行。全窗那一張格子是表格自己畫的，所以它做得到。
在正文裏按 `t a`，它會説要先 `t t`，**設置照樣記下**，按 `t t` 進去就是折行的。

##### `Tab`：填表的時候

進了格子（`i`／`a`／`c`）之後 **`Tab` 跳下一格，`S-Tab` 跳上一格**，一路排齊。這是所有
表格工具的那個鍵，也是表格能填得快的原因：**你從頭到尾不用碰 `|`**。走到最後一行的最後
一格再按 `Tab`，它給你開新的一行——你顯然還没填完。

##### 這個模式只在表格上生效

進了之後不用關。走出表格、進到下面那段話裏，`hjkl` 就是字母、`|` 就是一個普通字符；走
回表格裏，格子又回來了。**一個只在它所關心的東西上生效的模式，不需要被關掉**——這也是
爲什麽它不會像 CSV 那樣把整頁翻成横排：`|` 表格是文檔的一部分，爲了改三行而把整頁翻過來，
是把周圍的東西全扔了。

排版隨時是對的，因爲每次編輯之後它都重排一遍；重排是冪等的，所以排一百次和排一次一樣。
`u` 一次撤銷「編輯 + 重排」——你加了一欄再後悔，要回到的是**加之前那張表**。

**從表格軟件直接貼進來。** Excel、Numbers、LibreOffice、瀏覽器裏的表格——它們往剪貼板
上放的都是**製表符分隔**的行。在格子上按 `p`（或者 `空格 p` 從系統剪貼板，或者直接
⌘V／Ctrl+V 讓終端把它送進來），它從**光標所在的那一格**開始往右往下填，不够的行和欄自己
長出來：

```
木→mu          在「字」那一欄上按 p
目→mu          三行兩欄就進去了
禾→he
```

裏面本來有 `|` 的格子會寫成 `\|`，不會把一行切成兩行。CSV 那邊欄是 schema 定的，貼不下
就直説，不會偷偷把每一行往右擠。逗號分隔的也認，但**要求每一行的逗號一樣多**——一段
帶兩個逗號的話是一段話，不是表格。

没有製表符也没有換行的，還是照舊當一格的文字貼。

**光秃秃的 `|` 打不進格子**（和 CSV 的逗號同一道閘門），格子裏真要寫它，寫成 `\|`——
那是 Markdown 表格唯一的轉義，這裏認它：`a\|b` 是一格。

代碼塊裏的 `|` 表格**不是**表格，是引文：`:table` 會拒絶，不會去重排别人貼進來的例子
（這份手册裏就有好幾個）。只有一欄的行也不算表格。

#### 詳情欄

右側——**在 markdown 稿子裏也是右側**。一行表格有二十八個欄位，那是個高東西，寫在
哪裏都是高東西。**註**（腳注、`%%批註%%`）不切欄：它浮在角落上，見〈註在句子旁邊〉。

**部件列在最上面**——那是這個面板真正被用來看的東西；底下才是欄位。**每一欄都列，空
的也列**，前面帶欄號：空本身就是拆分表裏的一個發現，而「這一格是不是空的」正是你開這
個面板要問的。欄多了它會捲到光標所在的那一欄，`t20,20g` 也認那個號碼。算出來的欄位名
字後面帶 `*`，提醒你文件裏没有這一欄。

部件後面跟着行號；没有自己那一行的部件標成紅色的 `—`，對拆分表來説那個「没有」本身就
是發現。

**`t i` 開關**（從前是 `空格 d`）。它是表格的鍵，就該住在表格那一組裏；`空格 d` 現在
是字典。空格或 Tab 隔開的表格（碼表那一類）也列得出來——那種表没有表頭，欄名就是欄號。

**放不下的欄位會折行，不會被切掉**。這個面板正是摺起來的那一格該去讀的地方，所以它自
己再切一次就等於什麽都没答；折行走的是頁面那一套折行規矩（禁則照樣管），欄位名對齊在
左邊，續行縮在同一格起。面板窄了就多幾行：`:table-detail 40` 給它更寬一點。

### 没有名字的緩衝區也有崩潰副本

`yumete` 不帶參數啟動、寫一個小時——這是開一場戲的正常方式，而它以前是**唯一没有安全網
的緩衝區**：恢復副本放在文件旁邊，而它没有文件。

現在它在數據目録裏有一份（`drafts/scratch-<進程>-<第幾個>.yumete`），和有文件的緩衝區
走同一套自動保存。**只有真的打了字之後才給名字**——從没打過字的空緩衝區不該留下任何東西。

崩了之後下一次啟動會説：

```
有 1 份没存的草稿——`:recover` 打開
```

`:recover` 把它們各開成一個緩衝區（叫「草稿 scratch-…」），同時**把文件拿走**，免得下次
再問你一遍。`:recover!` 直接丢掉。這是唯一會去找它們的命令——那份工作没有文件名，别的東西
永遠不會提起它。

### `u` 不會撤銷「什麽都没發生」

撤銷點以前是在命令**宣稱**要編輯的時候記下的，不是在它真的動了字的時候。所以三個什麽都
没删掉的 `d`，就留下三個什麽都撤銷不了的 `u`；`i` 按完馬上 `Esc` 也是一個。`u` 於是變成
「有時候管用」——那是最快讓人不再信任一個編輯器的方式。

現在撤銷點是**掙來的**：宣稱的時候先記着（ropey 的複製共享結構，記着一個没發生的編輯只
花一個指針），字**真的動了**才進撤銷棧。被守衛擋下的編輯同理——它没動字，就不是一個值得
回去的地方。

### 剛才剪掉的那段去哪了

每一次 yank、每一次删除都蓋掉同一個暫存器，所以「三次編輯之前剪掉的那一段」以前是没有
答案的。現在它們留在一個**最近十六個**的環裏，`空格 "` 列出來：

```
系統剪貼板
0   那年冬天，山下起了大雪。 …（4 行）
1   阿寧從門後探出頭來。
2   「你來得正好。」
"a  第三卷的開頭
```

第一行是**系統剪貼板**——它不在這個列表裏（只有前端讀得到它），所以那一行是「去問一下」
而不是「已經拿着」。下面是不帶名字的暫存器的歷史（新的在上），再下面是 `"a`–`"z` 這些
帶名字的。

選一條就粘貼。`yy` 兩次不會在列表裏留兩條——那是你**取了一次**的東西。

### 没改過就别寫：`:x` 與 `:update`

`:w` 是**無條件**寫：動没動過都往硬盤上寫一遍。内容當然一樣，可是文件的**修改時間**
被推成了現在——而靠時間戳辦事的東西不少：`make` 和各種構建腳本看的就是「這個文件比上次
新嗎」，同步和備份工具（Dropbox、rsync）也一樣。翻開幾十個文件查點東西，順手 `:wq` 出來，
它們就以爲你把整本書都改了。

所以另有一對「改過纔存」的：

| | |
| --- | --- |
| `:x` `:xit`（`:exit`） | 改過纔存，然後退出 |
| `:up`（`:update`） | 改過纔存，不退出 |

没改過的時候它們什麽都不寫，狀態欄説「没有改動，未寫盤」。這是 vi 和 helix 分 `:x` 與
`:wq` 的原因，yumete 從前把 `:x` 當成 `:wq` 的别名，就把這個分别丢了。

⚠️ **給了路徑就一定寫**：`:x 第二章.md` 是在説「存成這個名字」，那是一句指令，不是
一次順手的保存。

### 文件在外面被改了

一個文件在 yumete 裏開着，同時被外面改掉——git 切分支、同步文件夾、`:!sed -i`、或者
你在另一個編輯器裏也開了同一個文件。以前 `:w` 會**一聲不響地蓋過去**，另一個版本就没了。

現在讀進來和寫出去的時候都記下這個文件的**大小和修改時間**；對不上就停下來：

```
這個文件在外面被改過了——`:reload!` 讀它的，`:w!` 用你的
```

- `:reload` 重讀文件。這裏乾淨就直接讀；有没存的改動會被攔下來
- `:reload!` 重讀，**丢掉**這裏的改動
- `:w!` 用這裏的蓋掉外面的

**`:reload-auto on` 讓它自己讀。** 打開之後，每兩秒問一次磁盤（便宜的那一問是一個
`stat`）：文件在外面變了、而你這裏**乾淨**，就直接讀進來，狀態欄説一聲。你這裏**有改
動**的時候它不動手，只提醒一次——合併不是編輯器該替你做的決定。

`:reload-auto` 不帶詞就是問現在是開是關。

**被碰過不算被改過。** 大小和時間只是一個便宜的問句——「這可能變了嗎」——而它説「可能」
的次數，遠多於真的變了：同步文件夾把一模一樣的字節重寫一遍、`touch` 一下、git 切回原來
那個版本。爲這些攔下來，比不檢查還糟：撞上三次假警報，`:w!` 就成了反射動作，然後**真的
那一次也照打**。

所以時間對不上的時候，它會**把文件讀出來對一下雜湊**：字節一樣就當没事，安靜地存。八兆
的表大約兩毫秒半，而且只在便宜的那一問答不出來的時候才付。

**文件被删掉算「改過了」**——把它寫回去等於復活一個别人删掉的東西。

### 這一存把文件撑大了很多

一個鍵可以把一份稿子變成三份那麽大。`t F` 對齊一張表，最寬那一格是一整段，於是每一行都
補到那麽寬——這個項目自己的 `development.md` 就一鍵從 425,694 字節變成過 2,945,642。那一
次修在對齊上（太寬的欄現在整張表不動），可這一類事没有修完的一天，而稿子和磁盤之間最後
一道門是保存。

所以 `:w` 遇到**又翻倍、又多出 256 KB 以上**的時候，會在屏幕中央停下來問：

```
╭安全核驗────────────────────────────────────────────────╮
│ 這一存會把《第一章.md》從 25 KB 變成 1.1 MB，44.1 倍。 │
│                                                        │
│ y  繼續保存                                            │
│ d  查看區别                                            │
│ n  取消保存                                            │
╰────────────────────────────────────────────────────────╯
```

- `y` 照存
- `d` 看改了什麽——就是 `:diff`。**這一存不做**，看完你自己再決定
- `n` 不存。`Esc` 也是這一個

它説的是**數字**，不是「幅度較大」：形容詞正好是你没法覆核的那一半，而你要決定的就是這
個數字對不對。

**兩個界限缺一不可。** 只看「翻倍」，一份 3 KB 的草稿寫成 7 KB 就會被攔——那是一個早上
的活；只看「多 256 KB」，一本長篇加一章就會被攔。兩個一起纔説得出這件事的形狀：文件
**成倍**地大，而多出來的量**不是人打得出來的**。

**新文件第一次存永遠不問。** 磁盤上還没有那一份，没有「從多少變成多少」可言。

**問題開着的時候，鍵盤全歸它。** 不是那三個答案的鍵，一個都不會漏到底下的稿子上去。

⚠️ **今天只有 `:write` 裝了這道門。** `:w!` 自己就寫着「蓋過去」；`:wq` 和 `:wa` 各差一
行，留到這個問法用順手了再説。

### 和外面交換文字

**`Cmd+C` / `Cmd+V` 永遠到不了 yumete**——macOS 的終端自己截走它們。這不是可以繞過的
事，是終端定的。所以：

| | |
| --- | --- |
| `空格 y` | 把選區送到系統剪貼板（也同時進内部寄存器） |
| `空格 p` / `空格 P` | 從系統剪貼板粘貼 |
| `Cmd+V` | 照樣可以用——終端把文字送進來，yumete 當**文字**收 |
| 鼠標拖選 | 在 yumete 裏選，然後 `空格 y` |

**任何帶 ⌘ 的按鍵都不進編輯器。** 開了 Kitty 鍵盤協議之後 ⌘C 其實**真的會送進來**，
而讀成一個光秃秃的 `c` 就是 Normal 模式的 **change**——於是「我想複製」變成「删掉選
區」。所以 ⌘／⌥⌘／Hyper 一律丢棄，交還給終端。複製用 `空格 y`。

**寫**剪貼板走終端自己的 OSC 52，不靠任何庫，而且是唯一能穿過 ssh 和 tmux 的路（有些
終端默認拒絶，狀態欄説的是「已請求」而不是「已複製」）。**讀**不能走同一條路——幾乎所
有終端都拒絶 OSC 52 讀取，而且拒絶得對：那等於讓管道另一端的任何程序把你的剪貼板倒進
一個文件。所以讀走的是本機的 `pbpaste`（Linux 上是 `wl-paste`／`xclip`），没有就明説。

`Cmd+V` 能用是因爲開了**括號粘貼**。這順帶修掉一個真的 bug：没有它的時候，粘貼是一串
按鍵，在 Normal 模式下粘進來那一段的**每一個字符都會當命令執行**——那不算粘貼出錯，那
是編輯器在跑一個没人寫過的宏。

鼠標現在可以在 yumete 裏**拖選**（點擊定位、拖動選取）。終端自己的選區仍然在——按住
Option 拖（Ghostty／iTerm2）就是它，用來複製狀態欄之類不在緩衝區裏的東西。

### 一本長篇

一本小説是一百多個文件。找東西、查東西的結果，yumete 大半**變成文本**——文本這個編輯器
已經有好工具了。⚠️ **搜索是例外**，它有自己的一扇面板（見下），因爲搜索要一邊改條件一邊
看結果，而那是文本做不到的。

⚠️ **`:grep` 没有了**，取代它的是**高級搜索面板**：`:search-gd` 就是從前的 `:grep`。
**`:replace` 還在，但意思換了**——從前它是「把剛才 `:grep` 找到的都換掉」，現在它開的是
同一扇面板、多一行「換成什麽」。

#### 找一個字

**`空格 /`（或 `:search`）開一扇面板**，在邊欄裏。它跟 `/` 的分别是：`/` 一次給你一
處，面板把**全部**列出來。

```
 尋找                     3 處
 ────────────────────────────
  霜▏
 [ ] 正則         [ ] 完整匹配
 大小寫  智能
 ────────────────────────────
     1  霜降於石階，她没有回頭
     3  那一年的霜來得早。
     5  霜花在窗上結成了葉子的
```

**開出來鍵就在框裏，打字就是搜**，每打一個字重找一次。框裏預先填着**上次搜的那個詞、
整個選中**——所以直接打字是換一個新詞，直接 `Enter` 是接着上次那個找。手上劃了一段
（不止一個字）就用那一段，你劃它的時候意思已經在屏幕上了。

⚠️ **命令不收要找的字。** `:search 卵` 是「一個叫卵的文件夾」，不是「搜卵」——這是有意
的，一個命令只説**在哪裏找**，找什麽永遠在框裏打。

| 在哪裏找 | |
| --- | --- |
| `:search`（`空格 /`） | 這個文件 |
| `:search-cd` | 這個文件所在的文件夾，含子目録 |
| `:search-wd` | yumete 打開的那個文件夾 |
| `:search-gd` | 最近的 git 項目——**最有用的一個**，你不必自己數往上幾層 |
| `:search ../稿` | 指名那一個 |

⚠️ **只有「這個文件」是邊打邊搜的。** 其餘要按 **`Enter`** 纔去找：一百章讀一遍，不能每
打一個字母做一次。在等的時候右上角寫着「Enter 開找」，找完了纔換成數目。面板標題一直
寫着此刻在哪裏找。`R` 是再找一遍（文件在外面改過了）。

**跨文件的結果是一棵樹**：一個文件一行，底下是它的命中。`h` 把一個文件摺起來、`l` 打開，
`Enter` 在文件那一行上也是摺與開、在命中那一行上是**打開那個文件並跳過去**。
没存的字也算——開着的文件搜的是它的緩衝區，不是磁盤上那一份。

説了一個不存在的文件夾它會**明説**，不會悄悄退回「只搜這個文件」給你一張看着像真的短清單。

| 在框裏 | |
| --- | --- |
| `Enter` | 下一處，**鍵留在框裏**——改詞是搜索裏最常做的事，交出去就每改一個字都要回來 |
| `Tab` `S-Tab` | 下一格／上一格 |
| `Esc` | 出框，回到面板的 Normal |

「上一處」框裏**没有鍵**：`Esc` 出來按 `N`。往回找是少見的動作，而框裏 `n` 是字母 n，
`Shift+Enter` 終端多半送不出來。

| 出了框（面板的 Normal） | |
| --- | --- |
| `hjkl` | 走格子；在結果那一格 `j`／`k` 走命中 |
| `Enter` `空格` | 翻開關；在結果上是「去那一處」 |
| `i` | 回框裏改詞 |
| `Tab` | 下一格 |
| `C-w` `q` | 去下一區／關掉這一格 |

**三個開關**。正則**默認關**——稿子裏找 `(注)`、`[^1]`、`A.B` 的時候多，關着省事。
大小寫**三檔**：智能（默認，和 `/` 同一條規矩——打了大寫纔算數）、敏感、不敏感。
⚠️ **完整匹配對漢字是空的**：兩個漢字之間没有「詞的邊界」，它只對稿子裏的西文起作用。
三個開關**記到 yumete 關掉爲止**，重開回到出廠。

**面板搜的就是 `/` 搜的那一次**：`n`／`N` 走的是同一批命中，關掉面板它們還在。⚠️ 但
`n` **不會**把面板拉回來——邊欄是吃列的，彈回來整頁要重排，寫字的時候不該爲按一下 `n`
付這個錢。要面板回來就再 `空格 /`。

**列表裏走，正文不動**（和大綱一樣），`Enter` 纔跳過去。那一條的**前後文寫在最下面
那一行**——面板只有三十來欄，而那一行有整個窗口那麽寬。

框空着的時候右上角**什麽都不寫**：「還没搜」和「一處都没有」是兩件事，後者寫「没有」。
正則寫不通就在同一格用**朱**寫「正則寫不通」，而**列表留着上一次能通的那批、畫成灰的**
——打正則必然路過 `[`、`(` 這些寫不通的中間態，每一下清空再填會閃。

#### 找了換

**`:replace` 開的是同一扇面板**，只是多一行「換成什麽」。`-cd`／`-wd`／`-gd`／
`:replace ../稿` 跟找的那幾個一樣，説在哪裏換。

`Tab` 從「找什麽」落到「換成什麽」時**鍵留在打字裏**——兩個框上下挨着、一前一後填。

| 在結果上 | |
| --- | --- |
| `r` 在一條命中上 | 換**這一處** |
| `r` 在文件那一行上 | 換**這個文件**的全部 |
| `R` | 換**全部**——⚠️ 只有這一個會先問一句 |

前兩個是你眼睛正看着的改動，一本書的每個文件不是。

⚠️ **一個字節都不先寫盤。** 每個有命中的文件被**開成緩衝區**、在裏面改，所以每一個都能
各自 `u` 撤回、`gn` 逐個看過去，`:write-all` 纔是你説「好」的那一下。這是這件事的安全
所在——**没有一條可以閉着眼睛打的全局替換**：模式是你剛剛用過的、命中也已經在眼前列
出來了。

換完面板會**重找一遍**（偏移全都不作數了），數目跟着降。要是某一行後來被别的東西改過、
已經找不到那一處了，它會説「那一處已經不在那裏了」，不去改此刻恰好在那個位置的東西。

`:search` 之後那一行收起來，`r`／`R` 跟着失效——「只是看看」的時候不該留着兩個會改字的鍵。

**忽略規則讀的是 `.gitignore`**（走目録這一段用的就是 ripgrep 的那個庫），書裏有没有
`.git` 都算數；上層目録的 `.gitignore` 也算。邊欄的樹狀圖問的是同一個問題，所以看得見
的和搜得到的是同一批文件。

**哪裏算「這本書」**：從當前這個文件往上找，先找帶 `.yumete` 的那一層（書的配置、
`words.txt`、`tables/` 本來就放在那裏），其次是帶 `.git` 的那一層，都没有就是這個文件
自己所在的目録。在哪個目録裏敲的 `yumete` 不影響它——從别處打開一章，搜的仍是這一章
所屬的那本書。`空格 f` 的文件選擇器、邊欄和 `:word-discover` 認的是同一個地方。

**早上接着昨天。** `yumete` 不帶文件名啓動時，它把上次開着的那些文件重新打開，每一個都
停在你離開時的那一行，然後在狀態欄説一句「接着上次：開了 5 個文件」。**只有不帶文件名時**
——説了要開哪個文件的人，得到的就是那個文件。

不想要就 `[editor] session = false`，那樣不帶文件名就還是從空白緩衝區開始。

記在數據目録裏（按工作目録分開，所以一本小説和一個代碼倉庫不會共用一份），不在你的項目
裏留東西。中途被移走或删掉的文件就不開了：這是個方便，方便没有資格每天早上往屏幕上放一
條錯誤。最多記 **24 個**，你正在的那個排第一——一次跨文件的改動會把每個文件都打開，
不設上限的話明早就是一百二十個。

**記號。** `M` 加一個字母把這裏記下來，`'` 加同一個字母回去——**跨文件**，那個文件會
自己打開。`C-o` 再回到你按 `'` 的地方。用 `M`／`'` 而不是 vi 的 `m`／`'`，因爲 `m` 在
這裏是配對模式。

**這本書自己的詞。** 阿寧——每一頁都有的那個名字——是任何詞典都不會有的那個詞。以前它
被切成 `[阿][寧]`：`w` 要按兩次才走過去，分詞著色把它畫成兩個詞。

在 `.yumete/words.txt` 裏一行一個寫下來（`#` 開頭是註釋）：

```
# 人物
阿寧
沈鶴年
# 地名
落霞鎮
```

從**正在編輯的那個文件**往上找（和表格 schema 一樣：這份詞表是稿子的屬性，不是這次會話
的）。啓動時讀一次，**中途加了名字，`:w` 存下就生效**——存這個文件就是重讀它，狀態欄會説現
在有幾個詞在用。（在别處改了它，`:word-list reload` 手動重讀。）

它是**疊在**現有分詞之上的，不是換掉：宇浩的語言模型（或者 `segmentation.txt`、或者
自帶的那份小詞表）照樣決定其餘的邊界，只有拼得出你的詞的那幾段會被併起來。長的優先，
所以「阿寧」贏過「阿」。

⚠️ **這個文件是你的，yumete 只讀不寫。** 下面那個自動認詞會另寫一份名單給你看，但**不會
動這一份**——你在這裏寫下的、删掉的，没有任何東西會改回去。

**它自己就在認。** 打開一個文件的時候，yumete 順手讀一遍，把「像詞而字典裏没有」的那些
串找出來，當場拿去分詞——**你什麽都不用做，也看不見它做**。計算在另一條線程上，稿子一個
字都不會卡；算完之前按 `w` 走的是語言模型的邊界，算完之後就跨得過「落霞鎮」了。`:w` 存稿
的時候也會再問一次——**同一個文件隔五分鐘纔真的重算**，換了文件立刻重算。

它讀**兩趟**：先讀這一篇，再讀這一篇所在的**文件夾**（含子目録）。

⚠️ **兩趟，而不是把它們拼成一段讀。** 看起來一樣，其實差很遠。拿宇浩自己那份文檔量過：
「宇夢」在講它的那一篇裏是 60 個候選中的**第 8 名**，在那個文件夾的 181 個裏是第 46 名，
到了整個倉的 969 個裏**整個消失**——而那張榜的頭幾名是 `习习`、`火火`、`宀八`，幾百張拆
分表的字根。它的次數自始至終都是 24，**一次都没少**。丢掉它的是**名額**（只留前幾百個）
和**剪枝**（別處常見的長串會把它吸收掉）。

所以這一篇**單獨讀一趟，並且佔住一半名額**：文件夾裏的任何東西都吸收不了它的詞，也擠不
掉它。要讀得更寬，用下面那三條命令明説。

它數三件事：

    内聚度   這幾個字擠在一起的次數，遠多於各自獨立時該有的次數嗎
    左熵右熵  它前後跟得住各種各樣的字嗎，還是永遠只跟那一個

第一件把「阿寧」和「的時」分開；第二件把「阿寧」和「阿寧説」分開——真正的詞前後什麽都
接得住，碎片只有一個習慣的鄰居。兩件缺一不可。**最後纔問分詞器**：它已經會併的一概不
報，所以「説道」「突然」不會出現在名單上，門檻也因此可以放得寬。一次最多用 200 個（一
部長篇找得出六千個候選，後面那些是「出現過兩次」而已）。

**這份名單只在内存裏。** 没有文件、没有緩衝區、没有一句話要你答應——關掉 yumete 它就没
了，下次開文件再算一遍。所以也没有「拒絕」這回事：你不用去删它，它本來就不存在。

**想看它認了什麽：`:word-discover`。** 這條命令當場重算一遍，把名單寫成
`.yumete/discovered_words.txt` 並打開給你看，按出現次數排。範圍用的是**和搜索一樣的四個
字**——學一次，兩處都認：

| 命令 | 讀哪些 |
| --- | --- |
| `:word-discover` | 這一篇 |
| `:word-discover-cd` | 這個文件所在的文件夾（含子目錄） |
| `:word-discover-gd` | 整個倉（帶 `.git` 的那一層） |
| `:word-discover-wd` | yumete 打開的那個目錄 |


```
# 本書自己的詞：掃了 118 個文件自動找出來的。每次 :word-discover 整份覆蓋。
# yumete 不讀這個檔——在這裏刪一行什麼也不會發生。要永久留下某個詞，抄進 .yumete/words.txt。
阿寧	# 213 次
王語嫣	# 176 次
落霞鎮	# 84 次
```

⚠️ **這個檔是單向的：yumete 只寫它，從不讀它。** 每跑一次就整份覆蓋，所以在裏面改什麽都
不算數。看見一個你想**永久**留下的詞（比如它偶爾没被認出來），把它抄進
`.yumete/words.txt`——那一份反過來，**只有你寫，yumete 只讀**。

**改一個名字，改遍全書。** 一個角色改名，一百二十章都要改。

```
:replace-gd     開面板，找什麽／換成什麽各打一行，Enter 找
                結果一條一條看得見
R  y            全部換掉（只有這一個會問）
:write-all      確定了再存
```

安全在**順序**上：**没有一條可以閉着眼睛打的全局替換**。要換的那些先在眼前列出來，
而且一個字節都不先寫磁盤——每個文件開成緩衝區、在裏面改，各自 `u` 撤得回，`gn` 逐個看得
過去，`:write-all` 纔是你説「好」的那一下。

`:toc` 開大綱欄，`:toc 3` 直接跳到第三條。標題是 Markdown 的 `#` 和 Typst 的 `=`——
没有 parser，標題就是行首的那幾個井號。

**没有標記的小説也有章節**：一個 `#` 都不用的 `.txt`，「第一章」「第四百一十二卷」
「楔子」「後記」這樣自成一行的短行就是它的標題。只在整份稿子找不到一個 markup 標題
時才這樣找——用 `#` 的稿子已經説清楚它怎麽標章節了，正文裏偶爾出現的一行「第三章」
不是第二種意見。

**目録不算章節。** 一本書開頭那一串「第一回」「第二回」……是清單，不是一百二十個章
節。清單的樣子是**成串**：中間只隔空行，一條接一條；正文的章回標題是孤零零一條，下面
跟着正文。三條以上連在一起就整串當目録丢掉——連最後那一條也丢，哪怕它下面正好跟着
「校閲參考」那樣的幾行字（紅樓夢就是這麽把目録的末條排到「第一回」前面去的）。兩條連
在一起不算串：資治通鑑每卷收尾一行、下一卷開頭一行，正是背靠背的兩條。

網上抄下來的書還帶着網頁的箭頭：「◀上一回 第二回　張翼德怒鞭督郵 下一回▶」。**那對
箭頭是框，不是標題**，摘掉再認，所以三國演義的一百二十回是一百二十條，標題也不帶箭頭。

**還有只數數的書**：金庸的天龍八部五十章，每一章只寫「一 青衫磊落險峰行」，一個「章」
字都没有。這種一行單看什麽都不是——年份、清單、腳注長得一模一樣——所以認的不是那一
行而是**那本書**：數字要從一起、一路往下數，每一條下面要有正文，還要够多條纔算一本
書。中間插進來的數字不算數，也打斷不了這個數。書裏但凡寫了一個「章」或一個「卷」，
這條路就不走——它已經説過它怎麽標章節了。

`:buffer` 看開了哪些，`:buffer-close`（短寫 `:bc`）關掉一個。同一個文件不會被打開兩次——第二次
`:open` 是切過去，因爲兩個緩衝區共用一個文件意味着兩份撤銷歷史、兩個修改標記、兩個搶救
稿在搶同一個位置，那是丢稿的方式而不是打開文件的方式。

**`:q` 關掉的是這一個文件，不是編輯器。** 開着三章按 `:q`，你回到第二章；只剩最後一個
時它纔真的退出。這是 Vim 與 helix 的規矩，也是寫作時想要的那個：關掉手上這一份，不等於
收工。真要走人是 **`:qa`**（`:qa!` 連没存的一起丢）。

没有 `:Q`。它跟 `:q` 只差一個 Shift 而意思不同，那正是手會滑的地方；短寫要用 `:bc`。

### 今天寫了多少：`:count-progress`

寫長篇的人跟自己約的那件事——一天兩千字——没有人替他數。數了也記不住昨天是多少，更
記不住上一次斷在哪一天。

```
:count-target 2000        每天兩千字，記下來
:count-progress           今天寫了多少，這本書寫到哪了，連了幾天
```

`:count-progress` 開出來的是一份清單：一天一行，最近的在最上面，後面那條長條是那一天的份量。

```
2026-09-06　1830 字　███████████
2026-09-05　2440 字　████████████＋
2026-09-04　260 字　█
今天 1830／2000 字（91%），本書 62480 字，連續 3 天
```

`＋` 是超過目標的那一天。`－` 是**删多過寫**的那一天——删掉一千字的下午也是幹活，只是
那個數字是負的，畫不成條。没有設目標時條照樣畫，比的是這些天裏最好的那一天。

**它數的是字，不是字符。** 和 `:count` 同一個算法：漢字算一個，`ABC` 三個字母不是三個
字。所以「今天 1830 字」是責任編輯認的那個 1830。

**記在 `.yumete/progress.tsv`，一行一天一個文件：**

```
# yumete 寫作進度：日期 ⇥ 文件名 ⇥ 起 ⇥ 現
目標	2000
2026-09-05	第一章.md	0	1830
2026-09-06	第一章.md	1830	2440
```

⇥ 是一個 tab。**這是一份可以自己改的文本**——手抖了改回去、把哪一天删掉、換臺機器合
併兩份，都是編輯這個文件的事。看不懂的行原樣跳過，不會整份作廢。

「起」是這一天第一次打開它時的字數，「現」是最後一次存盤時的字數，兩個相減就是那一天
的份量。所以它記的是**存盤之間的變化**——没存過的改動不算數，這一點和 `:count` 不同。

**「本書」是每一個文件最後一次存盤時的字數加起來**，一百二十章各記各的。

**連續幾天**是往回數的：昨天有寫、前天有寫，就一直數下去；今天還没開始不算斷（早上八
點打開編輯器不該看見「連續 0 天」）。

**它不會自己在你的目録裏留東西。** `:count-target` 或第一次 `:count-progress` 纔建那個文件；建好之
後，這本書底下每一次 `:w` 都往裏記一筆。不想要了就 `:count-target off`，或者把那個文件删掉。

### 一本書裏兩個寫法：`:check-usage`

寫了一年的稿子，前面是「裏」，後面是「裏」。兩個都對——都是規範的漢字，没有任何一個
拼寫檢查器會説話：Word 查的是病句，Grammarly 是英文的，而所有的拼寫檢查器都按空格切
詞，一整章在它眼裏是一個詞。於是這件事只能自己看，而自己看不見。

`:check-usage` 不問字典，問**這份稿子**。同一組的兩個寫法**都在這裏出現過**才算一
條：「裏」四百次、「裏」三次，那三次就是稿子還没定下來的地方，而多的那個就是它想要的
那個。只寫「裏」而從不寫「裏」的稿子，一個字都不會被報出來——那是風格，不是不一致。

結果和 `:table-check` 是同一個形狀：一個 `文件名:行號: 這裏是「裏」3 次，全文
多用「裏」400 次` 的緩衝區。三百條不是一句狀態欄裝得下的，**`gf`** 跳到那一行去改。

自帶的那張表有六十來組——<!-- verbatim -->裏/裡、為/爲、臺/台、著/着、才/纔、群/羣、甚麼/什麼<!-- verbatim -->、身分/
身份……收的是真會兩邊寫的那些。面/麵、谷/穀、困/睏 這種**兩個字義不同**的没有收：那
不是寫法之爭，報出來只會吵。

**這本書自己的那些**——阿嬌和阿姣、落霞鎮和落霞鄉——任何異體字表都不會有，而恰恰是一
年下來最容易走樣的。寫在配置裏，一行一組，想留的那個寫在前面（並列時它贏）：

```toml
[editor]
usage_groups = ["阿嬌 阿姣", "沈鶴年 沉鶴年", "落霞鎮 落霞鄉"]
```

長的寫法贏過它裏面的短的：有「甚麽 什麽」這一組時，「什麽」不會再被當成「麽」算一次。

### 這一章你説了幾次「然後」：`:word-habit`

把稿子裏的詞數一遍再按次數排，第一名永遠是「的」，第二名是「了」——中文就是這樣的，這
件事任何一本書的答案都一樣，所以它什麽也没告訴你。有用的是另一個問題：**這一章比尋常
的文章多説了哪些詞**。

`:word-habit` 問的是這個。它拿分詞器的詞頻表當底：一個詞在你這裏出現 `c` 次、全篇 `n` 個
詞（**只數詞頻表認得的那些**——`P` 就是在那本詞表裏的比例，兩邊要在同一個宇宙裏數，
不然一本人名滿篇的小説每個「倍」都被攤薄），而尋常文章裏它的比例是 `P`，那麽

    多 ＝ (c / n) ÷ P          倍
    分 ＝ c × ln(多)

排的是**分**不是**倍**。差别就在這裏：一個説了三次、比别人多三倍的詞不值一提，而
「然後」多四倍卻説了四十七次，那纔是你自己看不見的那個口頭禪。「的」在哪本書裏都多，
所以它的「倍」是一，一個字都不會被報出來。

    ch03.txt:12: 「然後」47 次——比尋常文章多 4.2 倍

結果和 `:check-usage` 一樣是可以 `gf` 跳過去的清單，行號是那個詞**第一次**出現的地
方。

**它有意不説三件事。** 詞頻表裏没有的詞跳過——「阿甯」不是口頭禪，是個人名，一本書自
己的詞是另一件事。單個字跳過——分詞器把不認得的漢字一個個拆開，那些是它的碎屑不是你
的選擇。説了一兩次的跳過——三次纔算習慣。

**它需要一張詞頻表。** 裝了宇浩字料層就是那 125 萬條；没裝時走内置的那份七萬五千條，
報得出來的少一些。一張詞頻都没有的詞表（比如關掉了分詞）會直接説出來，而不是給你
一份空清單讓你以爲自己寫得很乾淨。

### 没有收尾的那個「：`:check-punct`

`:check-punct` 看三樣東西，前兩樣是體面，第三樣纔是它存在的理由。

**半角。** 中文裏的 `,` 不是逗號，是一個擠在字身左下角的東西——輸入法晚切了一下就會
有一個，而排版社退稿最常見的理由就是它。`,` `.` `;` `:` `!` `?` `(` `)` 都查。

**`...`。** 中文的省略號是六點，`……`。三個點是英文的。

**開了口没收尾的「」『』（）《》〈〉【】。** 這一條纔是重點：少一個 `」`，**它那一行
看不出任何問題**，而從那裏往後，這一章每一個引號的意思都反了過來。校對的人盯着出事
那一頁看，什麽也看不出來——因爲那一頁是對的。

**只在中文旁邊纔算數。** `3.14`、`1,000`、`README.md`、一整句英文，裏面全是半角標
點，而且全都對。決定一個標點對不對的是**它旁邊的那個漢字**，所以只有貼着中文的纔報；
`` `代碼` `` 和 ``` 圍起來的整塊一概不看。小數點和千分位另外還擋了一道。

**跨段的引文不會被冤枉。** 一段引文分好幾段時，中文的排法是每一段開頭都重開一個
「，只有最後一段收 `」`。所以一行末尾還開着的 `「`，只有在**下一段不是也用「開頭**
的時候纔算漏。括號没有這個説法，開了就得在同一段裏收。

結果和 `:check-usage` 一樣是個可以 `gf` 跳過去的清單。

### 排版社没有的那個字：`:check-charset`

`:check-charset` 找出**不在任何字集裏**的字——通用規範、臺灣、香港、古籍，四個都没
有的那些。

這件事的可怕在於它**不在你這邊出錯**。你屏幕上的字體有那個字，它看起來一切正常；排版
社的没有，於是三個星期以後它變成一個豆腐塊，或者變成另一副字體裏一個大小不對的字，
而且每一次印刷都這樣。没有一個寫作工具問這個問題，而答案早就在編輯器裏了——`:yume-scheme` 載進來的那份拆分表就帶着每個字的字集。

**一個字一行，不是一處一行。** 一個帶生僻字的人名會出現四百次，而它是**一個**決定：
留着，或者整本換掉。四百行只會把另外那三個字埋掉。所以每一行給的是這個字**第一次**出
現的地方、全文多少處，以及它在哪個 Unicode 區塊——區塊纔是「字體會不會有它」的答案。

```
書.txt:37: 「𠮷」不在任何字集裏（CJK擴展B），全文 412 處
```

没載方案的時候它只説一句「没有字集數據」，不會假裝查過。

「只在古籍裏」的字**不報**——那是 `:ruby-auto rare` 的事（它給生僻字注音），古籍是一
個字集，字體多半有。這裏報的是四個都没有的。

### 簡繁：`:convert`

`:convert s t` 把整份稿子從簡體轉成繁體，`:convert t s` 反過來。

**這件事 yumete 自己不做。** 发 在 头发 裏是 髮、在 发现 裏是 發；干 是 乾、幹 還是
干；里 是 里還是裏，要看它是路上的里還是裏面的裏。一張字表答不了這些，要一本詞典加
上分詞，而那本詞典
[OpenCC](https://github.com/BYVoid/OpenCC) 已經認認真真做了十五年。所以 `:convert`
就是去跑 `opencc`——自己再寫一個，只會寫出一個更差的 OpenCC，而稿子要信它。

没裝 opencc 的時候它説一句怎麽裝，一個字都不動。`:convert-opencc install` 在 macOS
上會替你跑 `brew install opencc`；别的系統上它只把命令印出來，因爲那需要 sudo，而全
屏的編輯器不是該問你密碼的地方。裝好之後 opencc 要在 `PATH` 上，`:convert` 纔找得到
它。

七個代號，前五個就是 opencc 自己的配置名：

| | |
| --- | --- |
| `s` | 簡體 |
| `t` | OpenCC 的繁體——爲 説 裏 着 |
| `tw` | <!-- verbatim -->臺灣正體——為 裡 著<!-- verbatim --> |
| `hk` | 香港繁體 |
| `jp` | 日本新字体 |
| `c` | **大陸通規繁體**——爲 裏 着 説 内 吴 |
| `g` | **古籍通規繁體** |

`:convert` 不帶參數，列出這七個以及每一個能去哪裏。opencc 不是每兩個之間都有路
（`jp` 只回得了繁體），列出來的就是能走的。

**`c` 和 `g` 是這裏自己加的。** OpenCC 的繁體是港臺字形，而大陸出版社排一本繁體書用
的是通規字形，宇浩自己那份字料也是照通規寫的。兩者差的是**字形，不是用詞**：<!-- verbatim -->説 對
說、内 對 內、吴 對 吳<!-- verbatim -->，幾十個字，一個換一個。這麽小的事情就該是數據，所以它是一張
表——`:convert s c` 先讓 opencc 跑 `s2t`，再拿那張表把字形掃一遍。表抄自
[GujiCC](https://github.com/forFudan/GujiCC)。

從 `c` 出發也走得通：先把那張表**倒着**走一遍，回到 opencc 認得的字形，再交給它。所
以 `:convert c tw` 是「通規 → 繁體 → 臺灣正體」。有幾個字倒不回去——<!-- verbatim -->通規把 蝨 併進
虱、把 嶽 併進 岳<!-- verbatim -->，一個 虱 没有唯一的來路——那幾個原樣留着，不猜。

**`force` 是換詞，不是換字。** opencc 有幾個帶 `p` 的配置（`s2twp`、`tw2sp`）連詞彙
一起換：内存 變 記憶體，鼠標 變 滑鼠。那和上面所有事情都不是一回事——它會改字數，而
且回不去——所以要明説：`:convert s tw force`。没有 `p` 配置的那幾對，`force` 直接回
絶。

**反悔按 `u`。** 一次轉換是一步撤銷，整份稿子一起回來。**别拿反方向當撤銷**：`s t`
之後再 `t s` 得到的不是你原來那份稿子，是它繞了一圈的樣子。

### 導出

排版信息——竪排、標點旁置、注音——本來只活在屏幕上。`:export html` 把它們寫進一個
可以直接打開的文件：竪排用 `writing-mode: vertical-rl`（瀏覽器是終端以外唯一一個一
行 CSS 就能排縱書的地方），旁置用 `hanging-punctuation`，注音用 `<ruby>`。不給路徑
就用文稿自己的名字換個後綴：`chapter.md` → `chapter.html`。

**那個文件也能直接印。** 同一份 HTML 帶着一段 `@media print`：紙張大小、天頭地腳、
每一章從新的一頁起、標題不落在頁腳。字號是**算出來的**，不是挑的——竪排的行往下走，
版心就是「字數 × 字身」：你已經説了一縱幾個字，紙又説了那一縱要走多遠，字有多大就
没有剩下的選擇了。小紙上要長縱，字自然就小，跟真排一本書一樣。

紙張在配置裏（`[export] page`，默認 A5），因爲開本是一本書定一次的事。一縱幾個字則
是 `[editor] zong_length`——**没寫的話那是窗口此刻給多長**，所以要印之前先把它定下來。

⚠️ **頁碼與書眉没有**，導出的文件裏寫明了爲什麽：那要用 `@page` 的邊欄框
（margin boxes），瀏覽器一個都没實現。打印對話框自己的頁眉頁腳是眼下唯一的頁碼。

`:export typst` 出的是**横排**，而且在文件開頭寫明爲什麽：Typst 目前没有竪排。與其出一
個看起來像竪排、實際不是的文件，不如説清楚。注音會改寫成 `#ruby(base, reading)`，並
且在文件開頭附一個可以自己改的定義。

兩種導出都只認**標題、段落、注音**——一份稿子就是由這三樣構成的，猜其餘的只會做出一
個「看起來對，直到它不對」的文件。

**標記會被排出來，不是照抄。** `**很好**` 導出的是 `<strong>很好</strong>`（Typst 是
`*很好*`），不是四個星號——照抄標記的那個不叫導出，叫複製。

**批注不進書。** `%%這裏要改%%` 是你對自己説的話，手册一直是這麽説的，可它以前會原樣
寫進交給出版社的那個文件。現在它和標記符號本身一樣，導出時什麽都不留。

### 搶救稿

改了還没存的時候，yumete 每隔幾秒在文件旁邊寫一份副本：`chapter.md` 的副本叫
`.chapter.md.yumete`。保存和正常退出都會把它删掉，所以順利的時候你根本看不見它。

「每隔幾秒」是**最多五秒**，而且**停筆也算數**——寫完一段停下來想情節，那幾秒鐘的字
照樣會被寫進副本。（2026-09-11 之前不是這樣：副本只在你按下一個鍵的時候才寫，所以一
停筆就再也不寫了，斷電丢掉的正好是你正看着的那一句。）

要是這中間終端崩了、電斷了，下次打開同一個文件，狀態欄會説有一份更新的搶救稿，並且
文件名後面一直掛着 `[draft]` 直到你處置它。它**不會**自動載入——悄悄給你看一份和硬
盤上不一樣的文字，是讓人分不清自己在讀哪一版的開始。`:recover` 載入（載入以後 `u`
可以退回硬盤上那版，`:w` 才算採納），`:recover!` 直接丢掉。

**没被認領的搶救稿不會被動。** 打字不會蓋掉它，`:q` 和 `:q!` 也不會删掉它——只有
`:recover!` 會。這條規矩也順帶擋住了同一個文件開兩個 yumete 時互相踩的大半情形：第
二個進程看見的是一份「别人的稿子」，於是既不寫也不删。真正的鎖（像 vim 那樣）還没
有，所以同開兩個窗口寫同一章仍然不是好主意。

没有名字的臨時緩衝區没地方放副本，所以没有。副本寫不下去（目録只讀之類）會在狀態欄
説一次。`[editor] autosave = false` 可以整個關掉。

`:q` 和 `:wq` 查的是**所有**打開的文件，不只是眼前這個。`gn` `gp` 能走到每一個，
所以在乾淨的文件上退出而丢掉另一個没存的，是編輯器該攔下來的事；攔下來時會直接跳到
那個没存的文件，`!` 才是對一個有名字的文件做的決定。

文件一律當 UTF-8 讀。開頭的 BOM 會去掉（不然它就是第一段看不見的第一個字）；Big5 或
GB18030 的舊稿會被擋下並告訴你用 `iconv` 轉，而不是丢一句 Rust 的内部錯誤。

**字數**用 `:count`（或 `:wc`）。注音標記不算寫作——`<ruby>永和<rt>えいわ</rt></ruby>`
是兩個字兩個字符，不是磁盤上那二十幾個字符。它同時報三個數，因爲「寫了多少」在中文裏有三個答
案：出版社數的是**字**（漢字本身），文字處理軟件數的是**字符**（連標點一起），對話
多的段落兩者能差一成以上。有選區時統計選區——量一場戲，而不是量一本書。

**改了什麽**用 `:diff`。所有你按得到的比較工具都是**按行**比的，而中文的一段就是一行：
把五百字裏的一個「的」挪個位置，`git diff` 就把整段抹掉再畫回來——説的没錯，但你想知道
的那件事（**哪個詞**）埋在五百個字裏。`:diff` 按**詞**比，用的是這個編輯器自己的分詞，
就是 `w` 走的那一套：

    ch01.txt:2: 那年冬天，雪下得[-很早-]{+極早+}。

`[-…-]` 是去掉的，`{+…+}` 是加上的，`⏎` 是換行加了或者少了。結果是一份可以 `gf` 跳過
去的清單，跟 `:check-usage` 一樣。

不帶參數就是跟**磁盤上那一份**比——「這一坐下來我改了什麽」，這個問題保質期最短。帶一
個路徑就是跟那一份比：昨天的那一章，重寫之前留的那份底稿。路徑是相對**當前這個文件**
所在的目録算的。

兩份差得太遠（一千二百處以上）就不逐詞列了，會直接説差得太遠——那已經不是同一篇稿子的
兩稿，逐詞比不出東西來。

**分詞**——`w`／`b`／`e` 和詞語著色靠的東西——來自同一個引擎的詞頻表（125 萬條帶權）
和詞彙表，以引用共享，不會佔第二份内存。没裝輸入法數據時，退回數據目録裏的
`segmentation.txt`，再退回内置詞表——那一份七萬五千條，從同一個引擎的語言模型裏按詞頻
取出來，**分五軌**各取各的（繁簡一致 25000／簡體 15000／繁體 15000／台灣繁體 10000／
通規繁體 10000）。不分軌不行：簡體語料會把「抬頭」這種詞整批壓下去，一刀切下來只剩
「抬头」，繁體稿子處處掉回單字。

**兩邊本來就分得開的詞不著色。** 一個詞如果左右都是空格、換行或者標點，頁面上已經把它
斷開了，再上一層底色是把同一件事説兩遍——西文句子大半如此，中文句子也有不少：
「今天天氣很好。」裏 `今天` 要標，`好。` 不必。剩下的正是眼睛得自己切的那幾串漢字。
整個著色不想要就 `:word-show off`，或者配置裏 `show_segmentation = false`。

**兩種畫法。** 出廠是**字色**（`:word-show ink`）：**紙不動**，隔一個詞的字本身換一支
稍淡的墨（第 15 檔），記號落在字上，一頁讀下來還是一頁散文。

`:word-show 底色`（`:word-show tint`）換成另一種——隔一個詞在紙上鋪一層極淡的色。它把
邊界說得更死，代價是「模糊卻嘈雜」：底色是個**方塊**，標的是詞佔的那塊地方而不是詞本
身，滿頁方塊，眼睛要越過它們纔讀得到字。頁面上本來就有底色的時候（`==標記==`、`::: 提
示` 那一類）尤其吃虧，底色一多就分不清哪層是哪層。

配置裏是 `word_mark = "ink"` ／ `"tint"`。兩種都是嚴格隔一個詞，所以没被標的那個詞永遠
夾在兩個標了的中間，説的話一樣多。

## 八、命令

打 `:` 就在命令行上方列出命令，邊打邊篩。**即將補全的部分**用淺色顯示在光標後，
**Tab** 採納它，再按 Tab 換下一個匹配，**Shift-Tab** 往回。

一個**打完了的**命令會連它下面那一族一起列出來：打到 `:yume` 就看見 `:yume-scheme`、
`:yume-chaifen`……所以「這個命令下面還有什麽」是看得見的，不必先知道才找得到。Tab 選
中子命令時整句一起寫上去。

**有前提的命令會先説前提。** 標點旁置要竪排、而且密排關着才有地方掛；密排和段組只管
竪排；`:table-jump`、`:table-check`、`:table-rules` 要先在表格模式裏；`:yume-chaifen` 要先有
碼表。這些條件**寫在命令旁邊**，於是三處都説得出來：

- 菜單裏那一條就標着 ⟨需要 竪排、密排關，句末加 force⟩；
- 真按下去也不會默默設一個没人讀的旗標，而是説「還不行，需要：竪排、密排關」；
- **句末加 `force`** 就一併打開：`:view-hanging on force` 等於 `:layout vertical` +
  `:view-dense off` + `:view-hanging on`。

没有 `force` 的時候**什麽都不動**——一條小命令不該把整個版面翻成竪排；缺什麽你看得見，
換不換由你。

搜索行也會猜：它給出**上一次搜索詞**的剩餘部分，所以再搜一次同樣的東西就是 `/` 加
一個 Tab。

**每種文件自己説要跑什麽**（`[language.…]`）。`tinymist` 以前是寫死在程序裏的，
其實那是你這台機器的事，不是編輯器的事：

```toml
[language.typst]
preview = { run = "tinymist preview --no-open {file}", kind = "server" }
format  = { run = "typstfmt {file}" }

[language.markdown]
format = { run = "rumdl check --fix {file}" }
zhuyin = { run = "pandoc {file} -o {dir}/{name}.docx" }   # :run zhuyin
```

`kind` 有三種：`once` 跑完就完（跑完重讀文件），`server` 一直跑着（`:view-preview` 用它，
`:view-preview off` 停），`filter` 把稿子從 stdin 送進去、把回來的東西換上（不碰文件，
`u` 可以撤銷）。佔位符：`{file}` `{dir}` `{name}`。

**動詞不分語言**：`:view-preview`、`:format` 在每種文件裏都是同一個鍵，配置説這種文件怎麽做；
自己起名的用 `:run <名字>`。

**項目自己的 `.yumete/config.toml` 也可以定**，因爲安全不靠「誰能寫」，靠**怎麽跑**：
不經過 shell（所以 `;` `&&` `$( )` 只是普通字符，不是語法），佔位符**整個當成一個參數**
（文件名叫 `我的 稿;rm -rf ~.md` 也還是一個參數），而且載入時就檢查——引號不配對、
不認識的佔位符、出現 shell 元字符，都會在狀態行指出是哪個文件的哪一條。

右邊可以是**一串**鍵，不只一個。這樣默認值可以照我們認爲對的來定（`J`／`K`／`H`／`L`
是翻頁，因爲這是一本書），而不同意的人花一行配置，不是離開。左邊必須是**一個**鍵——
那是你按下去的東西，没有「按一串」這回事。

編號字符**必須是全角**（兩格寬），否則列會錯開。帶圈中文數字 ㊀㊁㊂ 是全角；帶圈阿
拉伯數字 ①②③ 屬於東亞「模糊寬度」，不同終端可能畫成一格也可能兩格，不要用。列表用
完之後的候選退回普通數字。

### 主題：墨香

默認主題叫**墨香**（`moxiang`，兩個名字都認）。它是**四種墨**：

- **黑墨**——紙面，也就是正文的底。
- **白金墨**——正文。白裏帶一點金，不是骨白：整屏都用骨白的話，色階上每一格都變暖，
  於是正文、標題、傢俱一個顔色，頁面就没有層次了。
- **金墨**——**不是正文**的那些字：標題、表頭、面板裏的欄名。整屏是灰的，它才找得到。
- **紅墨**（朱）——**不對**的那些：欄數不齊的行、没有字根的部件、腳注的號。不做強調。

黑墨和白金墨之間的深淺全部插值算出來——一條色階，0（純墨）到 1000（純紙）。換主題是
改幾個數，不是填一張表；改了之後各處的關係仍然對，因爲關係本來就是算出來的。

色階分**一百零一檔**：第 0 檔是墨（最反主題色），第 100 檔最主題色，**紙在第 90 檔**。
底下的刻度是 0–10000，**一檔一百步**，所以檔號就是刻度除以一百——不必記第二套號。
⚠️ **檔與檔不等距**——有名字的那十幾檔是量出來的位置，不是格子除出來的；檔號是給人說話
用的，刻度是給眼睛用的。要給某一檔起名字，隨時加一條就是。

| 檔 | 刻度 | 用在哪 |
| --- | --- | --- |
| 0 | 0 | 正文，以及一切**就是**正文的東西 |
| 15 | 1500 | 分詞的第二支墨（`:word-show ink` 隔一個詞換的那一支） |
| 20 | 2000 | 表格的欄尺 |
| 25 | 2500 | **旁註**：注音、拆分、候選的編號——讀得到，但不是正文 |
| 35 | 3500 | 傢俱：行號、没選中的分頁、鍵名、批注 |
| 40 | 4000 | 標記本身（`**`、`#`、表格的豎線） |
| 50 | 5000 | 線：邊框、想寫多長那條線、稿紙刻度 |
| 63 | 6300 | 選區的底色（**只有**底色，字保留自己的顔色） |
| 73 | 7300 | 要看得見的一條：竪排的段落號帶、表格光標所在那一行 |
| 81 | 8100 | 傢俱：邊欄、分頁條 |
| 84 | 8400 | 安靜的底：一塊（引用、圍欄） |
| 86 | 8600 | 分詞的底色（`:word-show tint`），以及表格隔行的那一檔 |
| **90** | 9000 | **紙**——正文的底 |
| **100** | 10000 | **狀態欄**——比紙更沉的那一級 |

⚠️ **第 73 和第 63 是被釘住的。** 表格裏三層底色疊在一起——選區、光標行、欄底——三者
必須彼此看得出來（1.24:1）。往紙的方向再挪兩檔，莫蘭迪的淺色模式下就掉到 1.20，站在哪
一行就看不出來了。莫蘭迪是對比度最少的那套主題，這兩個數是它定的。

第 35 檔以上是**讀得動的墨**，第 73 檔以下是**寫得上的底**，中間那一段除了線以外不放東
西——放進去的東西太淡讀不動，又太濃當不了底。

**表格只有兩種底色，其中一種就是紙。** 正文行隔一行鋪第 86 檔，中間那些行原樣留給紙。
**表頭與它底下那條 `---` 是一整塊**，兩行都用紙色——表頭靠的是**金字**，再給它一塊底反而
把它和分割線切成了兩半。三種底色是比表格要說的話多了一種。

**底色的對比可以比字低得多，因爲面積大。** 表格隔行只差 1.13:1，一條線或一個刻度差這麽
點根本看不見，而鋪滿一整行的兩塊底，眼睛一掃就分得開。

**紙不在盡頭，這是有意的。** 梯子從墨走到紙，也就是從**反主題色**走到**主題色**；紙停
在第 90 檔，後面還留十檔，是為了讓「比正文再沉一級」有地方可站。狀態欄就站在那裏——深
色主題下它比正文更黑，淺色主題下更白，同一個說法，不必分兩種。`[theme] status_bar =
"raised"` 可以讓它改回從前那樣，往墨的方向抬一階。

傢俱那一格從前離紙面只差一點（970），理由是**主題色是墨黑**：邊欄和表頭跟正文分開，靠
的是那條線和金墨，不是把底色調成灰的。⚠️ **命令行下移之後那個理由不成立了**（#302）：
狀態欄挪到最底下，正文最後一行就貼着它，而 970 對紙面是 1.03:1——本該一眼找得到的那一
條讀成了頁面的一部分。所以現在是 900：一塊既没有線、也没有自己位置的底，總得看得見。

**金墨**和**紅墨**不在這條色階上，因爲它們不是墨的多少。金墨給標題、表頭、面板的欄名
和邊欄的目録名；紅墨給腳注、參差的行號、光標所在那一段的號碼。`==標記==` 用的是紅墨
**沖淡到快要變成紙**——那是讀者自己的筆，不是「這裏不對」。分詞的底色是同一支紅墨再沖
淡一層，所以它跟着深淺走，不必另外配。

### 官服品色

除了金和朱，還有三支顏色，給頁面上**不是散文**的那幾樣東西。取的是官服的品色——它本來
就**有次序**，正好拿來說「這段字有多大權柄」：

| 品 | 色 | 給誰 | 爲什麼 |
| --- | --- | --- | --- |
| 龍袍 | 金 | 標題 | 作者自己的聲音 |
| 皇室 | 黃 | `::: warning` | 比金深一階，不是金 |
| 一至三品 | 紫 | 行内代碼、代碼塊 | 一個字都不能錯的那種字面 |
| 四至五品 | 朱 | 腳注、`::: caution`、衝突 | 朱批 |
| 六至七品 | 綠 | 引用 | 別人的話 |
| 八至九品 | 藍 | 鏈接、`[[章節]]` | 只是個地址 |

**粗體、斜體、標題不上色相**——它們本來就是正文，加顏色只是噪音。但代碼不是散文，是從
另一種語言裏引來的一段字面；只靠「比正文暗一階」標它，說的是「這段不重要」，而它往往是
一行裏最精確的東西，並且**頁面一變深它第一個消失**（墨從 13.7:1 調到 10:1 那一次，行内
代碼對紙就從 7.3:1 掉到 5.5:1）。

三支色都**比正文暗**（8.2–9.2:1 對正文的 11.1:1），所以正文仍然是頁面上最亮的東西。

**出廠不上底色**：`` ` `` 和 `>` 本來就畫在那裏，邊界已經在頁面上了，再鋪一層底是把答
過的問題再答一遍。想要代碼坐在框裏就 **`:theme-fill on`**（`off` 收回，不帶參數是反過
來）。

**五個提示框各佔一色**，從輕到重——**GitHub 的五個警示與 VitePress 的五個容器是同一套**，
這裏合成一套：

| 框 | 色 | GitHub | VitePress |
| --- | --- | --- | --- |
| `::: note` | 藍（八九品） | `[!NOTE]` | `info`、`details` |
| `::: tip` | 綠（六七品） | `[!TIP]` | `tip` |
| `::: important` | 紫（一三品） | `[!IMPORTANT]` | — |
| `::: warning` | 黃（皇室） | `[!WARNING]` | `warning` |
| `::: caution` | 朱 | `[!CAUTION]` | `danger` |

`info`／`details`／`danger`／`error` 都認，寫哪一個都到同一格。**黃不是金**：金是龍袍，只
給標題；黃是皇室，比金深一階（色相只差六度，明度低二十四）。

它們的底是那支顏色**洗到離紙 1.5:1**——一眼看得出是一塊，而框裏那段話仍在 7.4:1 上讀得
動。⚠️ 這四塊從前共用一塊灰底，理由是「四個灰底彼此只差 1.4–2.4 ΔE，分不出來」。那句話
沒錯，但它說的是**灰**：現在分它們的是色相，離紙多遠由同一條規矩定——**距離說「這是一
塊」，色相說「哪一塊」**，兩件事各歸各位就都成立了。

⚠️ **朱留在最重的那一格**，雖然品階裏紫壓着朱。朱是這個編輯器裏唯一一支有硬含義的顏色
——合併衝突的標記、腳注號、欄數不齊的行都用它——兩個顏色都說「這裏不對」就等於都不說。
紅是最危險，這一條也是唯一不用學的約定。

`mode = "auto"` 會**問終端**它的底色是什麽（OSC 11），據此決定深淺——問的是終端而不
是桌面，因爲淺色桌面上開一個深色終端的人，已經回答過這個問題了。終端不答就照配置裏的
`dark`／`light`；寫死 `mode = "dark"` 則根本不問。

`ground = "terminal"` 把底色還給你的終端：yumete 不畫紙，只按色階決定各處退多遠。適合
配色是自己調過的人。

### 【黑白】

第二套主題，`[theme] name = "黑白"`（`bw`、`heibai` 也認），或者 `:theme bw` 當場換。
**只有黑、白和灰**：没有金墨也没有紅墨的顔色，它們説的話改由**位置**説——金墨比正文
還亮（整頁只有它比正文亮），紅墨再亮一階，是唯一走到色階盡頭的東西。深淺兩個模式都有，
`mode` 照舊。

它不是墨香關掉顔色的版本，而是「把顔色全拿走以後，這套設計還立不立得住」的那個問題本
身——順帶也是色弱、色盲和單色終端上看到的東西。

臨時要換用 **`:theme`** 和 **`:theme-mode`**——**主題是主題，深淺是深淺**，兩個問題兩
條命令：`:theme bw` 換一套墨，`:theme-mode light` 只換深淺（`system` 是回到終端開機時答
的那個）。兩條都不帶參數就是問現在是什麽。它們**不改配置文件**——這是爲了下午房間亮起
來的那一次，寫進 `[theme] mode` 的才是你每天想要的。

⚠️ 從前 `:theme light` 也能換深淺，`:theme ink dark` 還能一句問兩件事。那讓「主題」一個
詞說了兩件事，所以拆開了：現在 `:theme` 只認主題的名字。

## 十、還没有的

明説出來，免得你去找：

- **多光標。** Helix 的 `C`、`s`、`S` 需要内核持有**一組**選區而不是一對錨點／光
  標。那是改造編輯器而不是給它加東西，所以寧可不做也不半做。`gt`／`gc`／`gb`（跳到
  屏幕頂／中／底）缺席是同一個原因的小號版本：滚動位置在渲染層，不在編輯器裏。
- **圈點**（着重號）——能畫，用注音那一列；標記語法還没定。
- **拉丁串真旋轉。** 終端轉不了字形，所以長的拉丁串只能逐字母往下堆。縦中横 能處理
  兩個字符，整個詞没辦法。
- **代碼的語法高亮、LSP、分屏。** 見 [development.md](development.md) 裏的功能表。
  （Markdown 和 Typst 的著色是有的，見「Markdown 著色」；大綱邊欄也是有的，`空格 o`。）
